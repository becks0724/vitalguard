# idea.md — 안전조달(SafeProcure)

> 1단계 아이디어 구상 결과. 클로드(산업안전 제품 아키텍트) ↔ 코덱스(조달데이터·심사 비판가) 2라운드 토론으로 수렴.
> 작성 2026-06-15. 대상 공모전: **2026 공공조달데이터·AI 활용 창업경진대회(조달청)** / 부문: **제품·서비스 개발**.

---

## 0. 한 줄 정의

**나라장터 조달 데이터와 AI로, 착공 전에 "안전관리비 과소계상 의심"과 "고위험 작업"을 선별하는 발주 단계 안전 게이트.**
기존 산업안전 모니터링 플랫폼 `safetymonitor`에 **코드 변형 없이 끼우는 플러그인 모듈**(방향 A)로 구현한다.

---

## 1. 배경 — 왜 이 아이디어인가

- 공모전 필수요건: **조달청 공공데이터(필수) + 타기관 공공데이터 + AI** 동시 활용.
- 우리 자산: `safetymonitor`(IndusView) — 작업자 웨어러블 생체신호 기반 산업안전 모니터링 플랫폼.
  이미 **KOSHA(산업재해)·기상청(KMA)** 공공데이터를 **플러그인 패턴**(env키+캐시+목업fallback / API프록시 / 대시보드 컴포넌트)으로 연동한 실적이 있다.
- 따라서 **조달청 나라장터 데이터 모듈을 같은 패턴으로 추가**하면 기존 제품을 건드리지 않고 공모전 특화 기능을 "뺐다 넣었다" 할 수 있다(방향 A 채택, 방향 B 불요).

## 2. 핵심 통찰 (토론에서 얻은 것)

토론 초기 안은 "조달데이터로 현장을 식별 → 웨어러블 모니터링"이었으나, 코덱스가 두 가지 치명적 약점을 지적했다:

1. **조달데이터가 보조키로 전락** → 공공데이터활용·독창성 점수 약화.
2. **공고→실제 현장 엔티티 매칭**이 4일 내 신뢰성 확보 불가(좌표·착공일·공정률은 조달데이터 밖).

→ **재포지셔닝**: 조달데이터를 **주인공**으로 끌어올린다. 현장 매칭이 필요한 "사후 모니터링"이 아니라, **발주(조달) 단계 그 자체**를 분석 대상으로 삼는다. 웨어러블은 "이미 동작하는 제품"의 증거로만 붙인다.

2라운드에서 코덱스가 추가 교정: **"안전관리비 위반 확정 탐지"로 과장하면 심사에서 반박당한다**(OpenAPI만으로는 원가계산서 세부·대상액이 없음). → **"과소계상 의심 공고 조기 선별 / 예비검증 + 근거 제시"** 로 표현 수위를 낮추되, 근거 문장·산정식을 투명하게 보여 신뢰를 확보한다.

## 3. 제품 컨셉 (확정안)

플러그인 모듈 **안전조달(SafeProcure)**. 두 레이어.

### 레이어 1 — 발주 단계 (핵심, 조달데이터가 주인공)
나라장터 **공사 입찰공고/계약** 데이터를 받아 AI·규칙으로 다음을 산출한다.
- **(a) 위험작업 태그 추출** — 공고 과업/공고명 텍스트에서 고소작업·굴착·전기·밀폐공간·중장비·해체 등 위험작업을 **원문 근거문장과 함께** 태깅. (AI: LLM 분류, 룰 키워드 폴백)
- **(b) 안전관리비 예비검증** — 공사종류·추정가격·공사기간으로 **산업안전보건관리비 법정 계상요율**(고용노동부 고시 별표·조달청 제비율 기준)을 적용해 기준액을 계산하고, 공고/계약상 값과 비교해 **과소계상 의심 / 검토 필요 / 정상** 으로 분류(확정 아님, 근거·산정식 표시).
- **(c) 위험 프록시** — 저가낙찰률·공기단축 등 데이터로 위험 가중. (설명가능 가중 스코어)
- → **현장 사전 안전 리스크 프로파일**(위험도·주요 위험요인·권고 3개)을 발주기관/관제자에게 제공.

### 레이어 2 — 현장 단계 (보조, 기존 제품 연결)
사전 프로파일을 `safetymonitor`의 웨어러블 실시간 모니터링 + KOSHA 재해이력과 연결해 **"발주 위험 → 착공 후 실시간 감시"** 루프를 완성. (이번 MVP는 연결 지점만 제시, 고도화는 비범위)

## 5. AI 활용 정당성 (심사 독창성 대비)

- 단순 LLM 요약 래핑이 아니라, **비정형 조달 공고문을 "안전 리스크 피처"로 변환**하는 것이 AI의 역할.
- 안전관리비 예비검증은 **결정적 규칙엔진**(법정요율)으로 두어 신뢰성을 확보하고, AI는 텍스트 이해·위험도 종합에 한정 → "신뢰할 수 있는 AI" 포지셔닝.

## 6. 심사 5지표 매핑 (제품·서비스 개발 / 각 20점)

| 지표 | 우리의 대응 |
|---|---|
| 기술성·완성도 | 이미 동작하는 모노레포 제품 + 새 모듈 실동작(목업fallback로 키 없이도 데모) |
| **공공데이터활용(조달청 필수)** | 조달청 OpenAPI 3종을 핵심 입력으로, 타기관 3종 결합 |
| 발전 가능성 | 발주기관 SaaS·나라장터 연계·전국 확장 로드맵 |
| 독창성 | "발주 단계에서 사고를 사전 차단" + 조달 텍스트→안전 피처 변환 |
| 효과성 | 공공공사 산재 예방·안전관리비 적정 집행이라는 사회적 가치 |

## 7. 슬로건 후보 (소개서 1페이지)

1. "조달공고 속 비용·공기·위험작업을 AI로 읽어, **착공 전** 안전 리스크를 선별합니다."
2. "나라장터 데이터와 AI로 **안전관리비 누락 의심**과 **고위험 작업**을 착공 전에 찾아냅니다."

## 8. 미해결 / 대안 (토론 기록)

- **표현 수위**: "탐지"가 아니라 "의심 선별/예비검증". 데모 신뢰도를 위해 실제 공고 20~30건을 수작업 라벨링 권장(코덱스 제안). → MVP는 3~5건 핵심 + 가능 시 확대.
- 방향 B(공모전 특화 v2 분리)는 방향 A 실현가능성이 확인되어 **불채택**.
- 실 API 키 미발급 시: 전 기능 **목업 fallback**으로 데모 동작(기존 KOSHA 패턴과 동일), 키 연결 시 실데이터 자동 전환.
