# PRD — 안전조달(SafeProcure) 모듈

> 제품 요구사항 정의서. `safetymonitor`에 끼우는 조달 안전 플러그인 모듈.
> 대상: 2026 공공조달데이터·AI 활용 창업경진대회(조달청) / 제품·서비스 개발 부문.
> 마감: 2026-06-19(서류). 작성 2026-06-15.

---

## 1. 문제 정의

공공공사는 산업재해 다발 영역이다. 그러나 위험은 대부분 **착공 후**에야 모니터링되고, **발주(조달) 단계**에서 위험 신호(과소 안전관리비, 위험작업 누락, 무리한 공기)는 사람이 일일이 검토하지 못한 채 통과된다. 발주기관은 공고당 검토 인력이 부족하다.

## 2. 목표 / 비목표

### 목표 (이번 MVP)
- G1. 나라장터 공사 공고/계약 데이터를 표준화해 보여준다.
- G2. 공사종류·추정가격·공사기간 기반 **안전관리비 예비검증**(과소계상 의심/검토 필요/정상)을 **산정식·근거와 함께** 제시한다.
- G3. 공고문에서 **위험작업 태그**를 원문 근거문장과 함께 추출한다.
- G4. 위 셋을 종합한 **현장 사전 안전 리스크 카드** 1화면을 제공한다.
- G5. API 키 없이도 **목업 fallback**으로 전 기능 데모가 동작한다(심사 시연 안전성).
- G6. 기존 `safetymonitor` 코드를 **변형하지 않고** drop-in으로 추가된다.

### 비목표 (이번에 하지 않음 — 코덱스 합의)
- N1. 안전관리비 **"법정 위반 확정 판정"** (→ "의심 선별/예비검증"으로 한정).
- N2. 전국 공고의 **실제 현장 좌표 자동 매핑**(엔티티 매칭).
- N3. 웨어러블 실시간 모니터링 **고도화**(연결 지점만 제시).
- N4. 산재 예측 **ML 모델 학습 완료 주장**(설명가능 휴리스틱 스코어로 한정).
- N5. KOSHA·기상청 대시보드 **과확장**(조달 핵심성 유지).
- N6. LLM **자동 종합판정 문장 남발**(근거·산정식 우선).

## 3. 사용자 / 시나리오

- **주 사용자**: 공공 발주기관 안전·계약 담당자, 안전관리 컨설턴트.
- **시나리오**: 담당자가 안전조달 대시보드를 연다 → 공사 공고 목록에서 위험도 높은 공고가 정렬 상단에 뜬다 → 카드 클릭 → 안전관리비 예비검증(기준액 vs 추정, 산정식), 위험작업 태그(원문 근거), 권고 3개 확인 → "검토 필요" 공고를 우선 검토.

## 4. 기능 요구사항 (MVP, 우선순위 = 코덱스 top3 확정)

### F1 (필수·1순위) 조달 데이터 수집·표준화
- 나라장터 입찰공고/계약 OpenAPI에서 공사 건을 가져와 `추정가격, 공사기간(시작·종료), 공종/면허, 지역, 수요기관, (계약 시)계약금액·낙찰률`로 표준화.
- env키(`G2B_SERVICE_KEY`) 게이트 + 30분 캐시 + **목업 fallback**(샘플 공고 3~5건 내장). KOSHA 모듈 패턴 동일.
- 산출: `/api/g2b/notices` (목록), `/api/g2b/notice/:id` (상세).

### F2 (필수·2순위) 안전관리비 예비검증 룰엔진
- 입력: 공사종류, 대상액(추정가격 근사), 공사기간.
- 처리: 법정 계상요율표(공사종류×금액구간×기간 보정) 적용 → **기준 안전관리비** 계산.
- 출력: `기준액`, `산정식(근거)`, `입력 충분도`, 분류 `정상 / 과소계상 의심 / 검토 필요(데이터부족)`.
- **결정적 규칙엔진**(AI 아님) — 신뢰성 확보. 입력 부족 시 단정하지 않고 "검토 필요".

### F3 (필수·3순위) 공고문 위험작업 AI 태그
- 입력: 공고명·과업 텍스트.
- 처리: LLM(env `ANTHROPIC_API_KEY`)로 위험작업 분류(고소/굴착/전기/밀폐공간/중장비/해체 등) + 원문 근거문장 추출. **룰 키워드 폴백** + **목업 precomputed**로 키 없이도 동작.
- 출력: `[{tag, severity, evidence(원문)}]`.

### F4 (필수) 사전 안전 리스크 카드 + 목록
- 카드: 위험도(0~100, 설명가능 가중), 주요 위험요인, 안전관리비 예비검증 결과, 위험작업 태그, **권고 3개**.
- 목록: 공고들을 위험도 정렬, "검토 필요" 배지. `safetymonitor` 다크/라이트 테마·캐러셀 패턴 재사용.

### F5 (필수) 데모 안전성
- 모든 외부 의존(조달 API, LLM)은 키 없을 때 목업 fallback. "샘플/실데이터" 배지로 출처 명시(기존 KOSHA 패턴).

## 5. 위험도 스코어 (설명가능)
`risk = w1·위험작업심각도 + w2·안전관리비_의심 + w3·저가낙찰/공기단축 프록시 + w4·공종 재해통계(KOSHA)`.
가중치·기여도를 카드에 분해 표시(블랙박스 금지). 학습모델 아님 — 근거 기반 휴리스틱.

## 6. 아키텍처 (기존 패턴 준수, drop-in)

```
apps/dashboard-web/
  app/lib/g2b.ts              # 조달청 OpenAPI 클라이언트 (env키+캐시+목업fallback)
  app/lib/safety-cost.ts      # 안전관리비 예비검증 룰엔진 (법정요율 정적테이블)
  app/lib/risk-tagging.ts     # 공고문 위험작업 태그 (LLM+룰폴백+목업)
  app/lib/procure-risk.ts     # 위험도 종합 스코어
  app/api/g2b/notices/route.ts
  app/api/g2b/notice/[id]/route.ts
  app/components/ProcureRiskBoard.tsx   # 목록(위험도 정렬)
  app/components/ProcureRiskCard.tsx    # 사전 안전 리스크 카드
packages/schemas/src/procurement.ts    # Zod 스키마(공고/검증/태그/리스크)  ← 선택
```
- **납품 형태**: 위 파일들을 `<OUT>/safeprocure-module/`에 동일 경로 구조로 제공 + 통합 가이드(`INTEGRATION.md`). 사용자가 자기 레포에 복사 → 기존 코드 무변형. (검증은 클로드가 /tmp 클론에 적용해 빌드·테스트)

## 7. 데이터 소스 / 외부 의존
- 조달청 OpenAPI: 입찰공고(15129394)·계약(15129427)·낙찰(15129397) — `apis.data.go.kr`, `G2B_SERVICE_KEY`(Decoding) env. 미발급 시 목업.
- 고용노동부 산업안전보건관리비 계상기준(고시 별표·조달청 제비율 기준) — 정적 요율 테이블로 코드 내장.
- KOSHA/KMA — 기존 연동 재사용.
- LLM — Anthropic Claude API(`ANTHROPIC_API_KEY`) env, 미발급 시 룰/목업.

## 8. 비기능 요구사항
- 보안: API 키는 `.env.local`(gitignore), 서버 라우트에서만 사용(클라 노출 금지). 입력 검증(Zod). 외부 응답 tolerant 파싱.
- 성능: 30분 캐시, 목록 1초 내 렌더(목업).
- 호환: Next.js15/React19/TS strict, `tsc --noEmit` 0, 기존 `pnpm test` 깨지지 않음.
- 컴플라이언스: 개인정보 미수집(공고/계약 공개데이터만). "예비검증·의심"임을 UI에 명시(과장 금지).

## 9. 검증 기준 (5단계 QA)
- V1. `pnpm --filter @safetymonitor/dashboard-web typecheck` EXIT 0.
- V2. `/api/g2b/notices` 목업 200 + 표준화 필드 반환.
- V3. 안전관리비 룰엔진 단위테스트(요율 케이스 3종) 통과.
- V4. 리스크 카드 dev 렌더 + 위험도 분해 표시, 콘솔 에러 0.
