## 왜 이 슬라이스부터인가 (순서를 바꾼 근거)

`research/live-server-analysis.md` §2-1 에 **앱 토큰으로 지금 당장 되는 API 12개**가 있다.
그 안에 **요구사항 13(캘린더 OCR 사진에 펜으로 메모)의 재료가 전부 들어 있다.**

| API | 쓰임 |
|---|---|
| `GET /api/calendar/media` | 현장 사진 목록 + 댓글 |
| `POST/PATCH/DELETE /api/calendar/media/comment` | 댓글 |
| `GET /api/calendar/events` · `/labels` | 일정·라벨 |
| `POST /api/app-media` | 사진 업로드 (D-2 A안의 저장 경로) |
| `GET /api/admin/site-info` | 현장 정보 |
| `GET /api/inspection-schedule` | AED 점검 마커 |

반면 `S` 현장의 `GET /api/monitor/vital` 은 **앱 JWT 를 401 로 거부**한다(§2-2).
→ **`R` 은 서버 확장(D-4) 없이 실제 API 로 붙고, `S` 는 D-4 를 기다려야 한다.**
그래서 `R` 을 먼저 만든다. **이게 이 앱의 존재 이유이기도 하다** —
관제웹을 옮기는 게 아니라 **펜으로 하는 것**이 태블릿을 쓰는 이유다.

### ★ 전제가 바뀌었다 — 반드시 읽어라

종전 문서의 **"작업자 앱(카메라·OCR)" 은 틀렸다.** 태곤 님 정정:

> **OCR 이 들어간 휴대폰 앱은 `현장 담당관 앱`이다. 작업자용 앱은 없다.**
> 작업자용은 팀원이 만든 **워치 앱**뿐이고, 그건 생체·수집 경로라 캘린더 사진과 무관하다.

따라서 **캘린더 사진은 담당관 본인이 올린 것**이고,
"한 현장 = 담당관 1명 = 태블릿 1대" 이므로 **원본 업로더와 주석본 업로더가 같은 사람**이다.
→ **D-2 A안(합성본 재업로드)은 유효하다.** 귀속이 바뀌지 않는다.
→ **설계를 되돌릴 필요 없다. 그대로 만들어라.**

### 네가 확인할 것 — 1건

**`calendar_media` 테이블에서 `title`(그리고 `description`)의 길이·타입 제한**을 찾아라.
`varchar(n)` 인지 `text` 인지. 제한을 넘겨 **잘리면 원본 연결이 끊긴다** —
보완 2 에서 `title` 이 원본 식별자를 담는 **유일한 연결 고리**이기 때문이다.
스키마 정의 파일(`ensureSchema` 계열이 정본이다. DDL 파일은 정본이 아니다)을 읽고
**파일·행과 함께** 답해라. 못 찾으면 "확인 못 함" 이라고 써라.

여유가 되면 같이:
- `media_url` 프리사인 **만료 시간** — 오프라인 캐시 정책에 직결된다
- `GET /api/calendar/media` 의 **페이징·필터**(현장·기간) 파라미터
- 댓글 `POST` 본문 스키마와 길이 제한

## 2단계 — 구조 먼저 (화면보다 계약이 먼저다)

```
lib/

  app.dart         # 라우팅
```

### ★ 지켜야 할 계약 규칙 5가지

1. **화면은 `contracts/` 만 본다.** `live/` 나 `mock/` 을 직접 import 하지 마라.
   나중에 D-4 가 정해지면 **구현만 갈아끼우고 화면은 안 고친다.**
2. **모델은 실제 서버 응답 모양을 따른다.** `live-server-analysis.md` §3-2 의 `CalendarMedia`
   필드(`date_key`·`captured_at`·`media_url`·`ocr_text`·`road_address`·`latitude`·`longitude`·
   `worker_id`·`uploader`·`description`·`comments[]`·`coordGapM`)를 그대로 쓴다.
   **편한 대로 이름을 바꾸지 마라.** 지금 바꾸면 붙일 때 전부 고쳐야 한다.
3. ★ **서버가 주지 않는 필드를 모델에 만들지 마라.** 모의 구현에서도 마찬가지다.
   실측에서 이미 겪었다 — 시안의 "남은 시도 2회" 는 API 에 없는 값이었다.
4. ★ **모의 데이터는 화면이 모의라고 말한다.** `S` 현장처럼 모의로 채운 화면에는
   **"모의 데이터" 표지**를 띄운다. 나중에 진짜와 헷갈리면 잘못된 판단을 한다.
5. **`captured_at` 은 KST 로컬 ISO 로 보낸다.** `Z` 로 보내면 **9시간 어긋난다**(§3-2).

### 인증

- v2 로그인 → 토큰 보관. **비밀번호를 기기에 저장하지 않는다**(토큰만).
- `twoFactorRequired` 면 **비밀번호를 그대로 쥔 채 6자리만 더해 재전송**(중간 토큰을 만들지 않는
  관제웹과 같은 구조). 잠기면 `429` + `retryAfterSec` 만 표시한다.
  **남은 시도 횟수를 화면에 만들지 마라 — 서버가 주지 않는다.**
- 허용 목록: `role IN ('platform_admin','site_manager')`.
  시공사 법인 계정은 `site_manager` + `is_company_account=true` 라 **같은 검사로 통과**한다.
- `A-07`~`A-12` 실패·경계 화면은 `app_uIuX_plan.md` §2.1 의 **[확정] 표를 그대로** 따른다
  (access 만료는 single-flight refresh 먼저 · 계정 B 로그인 시 계정 A 큐 내용 노출 금지 등).

### `R-06` STT — P4 실측 반영

- **후보를 보여주고 고르게 한다**(`I-4`). 1순위를 그대로 확정하지 마라.
  실제 반환 후보는 **3~5개**다.
- **확인 없이 저장하지 않는다**(`I-5`). `안전대 미착용`→`안전띠 적용` 처럼
  **부정이 사라져 의미가 뒤집히는 실패**가 실측으로 나왔다.
- 입력 칩 4개(`이상 없음`/`재점검 필요`/`작업 중지`/`즉시 조치 요망`)는
  **등급 색 띠 없이**, **기본 선택 없이**, `관리자 기록` 출처 라벨과 함께.
- `lib/stt_screen.dart` 의 플랫폼 채널을 재사용해라. **새 패키지를 깔지 마라.**
