## 무엇이 남나

**네가 직전 작업에서 보고한 것이다.**

> 현재 `deleteCalendarMedia` 는 원본·잉크본 행과 파일만 삭제한다. 댓글에는 연쇄 삭제 외래키나
> 명시적 삭제 처리가 없어 **댓글 행과 음성 파일이 남고, 목록에서는 보이지 않게 된다.**

즉 사진을 지우면 이렇게 된다.

| | 지금 | 되어야 할 것 |
|---|---|---|
| 원본 행 | 삭제 ✅ | 삭제 |
| 잉크본 행·파일 | 삭제 ✅ | 삭제 |
| **댓글 행** | **남는다** ❌ | **삭제** |
| **음성 파일(스토리지)** | **남는다** ❌ | **삭제** |

원래 글 댓글도 같은 상태였지만, 음성이 붙으면서 **스토리지 파일까지** 고아가 된다.
누구도 못 보는데 용량만 먹는다.

## 고칠 것 — `deleteCalendarMedia` (`lib/db.ts:4790`)

이미 **한 트랜잭션**으로 원본+잉크본을 지우고 저장 키들을 돌려준다(`status: "deleted", files: [...]`).
**그 트랜잭션 안에 댓글을 더한다.**

1. 원본을 지울 때 **그 원본에 달린 댓글을 전부 삭제**해라(`media_id = 원본 id`).
   - ⚠ 잉크본에는 댓글이 달릴 수 없다 — 서버가 `commentOf` 에 잉크본 지정을 **400** 으로 막는다.
     그래도 **확인하고**, 만약 달릴 수 있는 경로가 있으면 그것도 같이 지워라. **확인 결과를 보고해라.**
2. 삭제된 댓글 중 **`audio_storage_key` 가 있는 것들의 키**를 `files` 에 실어라.
   호출부가 이미 `files` 를 순회하며 스토리지를 지운다.
   - ⚠ 댓글에는 `storage_provider` 컬럼이 **없다.** 사진은 `storage_provider='naver'` 를 보고 지운다.
     음성은 `putObject` 로 같은 스토리지에 올라간다. **호출부가 음성 키도 실제로 지우도록**
     `storageProvider` 를 무엇으로 채울지 정하고 **그 근거를 보고해라.**
3. **`DELETE ... RETURNING` 으로 얻어라.** 먼저 SELECT 해서 모으면 그 사이 행이 바뀔 수 있다
   (기존 주석이 TOCTOU 를 이유로 그렇게 하고 있다 — 같은 원칙을 지켜라).
4. 잉크본 **단독** 삭제(`annotation_of` 가 NULL 이 아닌 행)에는 이 처리를 **적용하지 마라.**
   잉크본에는 댓글이 없고, 유예도 적용하지 않는 경로다.

### 유예 규칙은 그대로다

원본 삭제는 **10분 유예** 안에서만 된다(`MEDIA_DELETE_WINDOW_MIN`). **바꾸지 마라.**
유예를 넘겨 거부되면 **아무것도 지워지면 안 된다** — 댓글도 남아야 한다(트랜잭션이 롤백된다).

## 하지 않는 것

- 이미 고아가 된 데이터 정리 — 라이브에는 아직 음성 댓글이 **없다**(배포 전이다)
