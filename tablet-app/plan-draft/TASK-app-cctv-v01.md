## 왜 지금까지 안 됐나 (읽고 시작해라)

1. **티켓은 1회용이다.** `_consume_jti` 가 SQLite 기본키로 사용 이력을 남긴다
   (`cctv-ai/edge/cctv_gate.py:131-132`). **갱신마다 새 티켓을 받아야 한다.**
2. **관제웹 티켓 API 는 앱이 못 쓴다.** 관제웹 세션(`session-jwt.ts`)과
   앱 세션(`app-jwt.ts`)의 **서명키가 다르다.**
   → 그래서 앱 전용 라우트가 이미 만들어져 있다: `app/api/app/admin/cctv-ticket/route.ts`
3. **그 라우트에 딱 하나가 빠졌다 — 게이트 주소.** 앱이 티켓을 받아도 **어디로 보낼지 모른다.**

## 1. 서버 — 티켓 응답에 게이트 주소를 담는다

**파일**: `조달청_rlaxorhs77eng-alerts/…/app/api/app/admin/cctv-ticket/route.ts`
**고칠 곳**: `:81-84` 의 성공 응답 **하나뿐이다.** 그 밖은 손대지 마라.

```ts
// 게이트 주소 — 앱은 빌드타임 NEXT_PUBLIC_* 을 볼 수 없으므로 서버가 알려준다.
// 런타임 env 를 먼저 본다: 게이트 주소가 바뀌어도 대시보드 재빌드 없이 고칠 수 있다.
const gateApi = (process.env.CAM03_GATE_API ?? process.env.NEXT_PUBLIC_CAM03_GATE_API ?? "").trim();
```

응답에 `gateApi` 를 추가한다. **빈 문자열이면 빈 채로 내려보내라** — 앱이 그걸 보고
"게이트가 설정되지 않았다"고 말해야 한다(V-03). 라우트에서 500 을 내지 마라.

⚠ `.env` 는 읽기 차단이다. **값을 확인하려 하지 마라.** 코드만 쓴다.

## 2. 앱 — 티켓 받기

**파일**: `lib/data/live/live_gateway.dart` (+ 같은 계약의 추상 클래스가 있으면 거기도)

기존 `me(accessToken)` 과 **같은 모양으로** 하나 추가한다.

```dart
Future<CctvTicket> cctvTicket(String accessToken, String cameraId);
```

- `POST /api/app/admin/cctv-ticket`, 본문 `{"cameraId": cameraId}`
- 기존 Bearer 전송 방식을 그대로 쓴다(`:103-126` 참고). **새 인증 경로를 만들지 마라.**
- 응답: `{ok, ticket, expiresAt, ttlSec, gateApi}`
- `CctvTicket` 모델은 기존 모델들이 있는 곳에 같은 스타일로 둔다.

**오류를 삼키지 마라.** 401·403·404·429·503 을 **구분 가능한 형태로** 올려라 — V-03 이 그걸 쓴다.

## 3. 앱 — V-01 화면 (본체)

**새 파일**: `lib/ui/cctv/cctv_screen.dart` (폴더 구조는 기존 `lib/ui/` 관례를 따라라)

### 동작 — 한 주기

```
① 티켓 발급(cctvTicket)  →  ② {gateApi}/cctv/stream3 GET, Authorization: Bearer <티켓>
→  ③ multipart 첫 파트(JPEG 한 장)만 읽고 즉시 끊는다  →  ④ 화면에 그린다  →  주기 대기
```

**③ 은 이미 구현돼 있다.** `cctv_probe_screen.dart` 의 multipart 파서를 **그대로 가져와라**
(첫 파트만 읽고 `detachSocket()`/구독취소로 끊는 부분). 다시 짜지 마라.

- 기본 주기 **5초**. 3·5·10초 중 고를 수 있게 한다.
- **직전 요청이 안 끝났으면 건너뛴다.** 겹쳐 쏘지 마라.
- 티켓 발급 rate limit 이 **60회/분**이다(`route.ts:10`). 3초 주기 = 20회/분 → 안전하다.

### 카메라

지금 게이트가 있는 카메라는 **`CAM-03` 하나뿐**이다. 상수 하나로 두고 화면에 표시해라.
**V-02(다분할)·V-06(샘플 카메라)은 이번에 만들지 마라.**

### 표시 — ★ 사양이 까다롭다. 그대로 지켜라

| ID | 요구 | 구현 |
|---|---|---|
| **V-01** | 기준 시각 · 경과 · 갱신 간격을 **함께** 표기 | `14:32:05 기준 · 3초 전 · 5초 간격` |
| **V-04** | ⚠ **오래된 스냅샷을 현재처럼 보여주지 마라** | 경과가 **주기의 3배**를 넘으면 화면에 **`갱신 멈춤 · N초 전 영상`** 을 겹쳐 띄우고 이미지를 흐리게 한다 |
| **V-03** | **왜 안 되는지 말한다** | 아래 표대로 **사유별로 다른 문장**을 띄운다 |
| **V-05** | 백그라운드 전환 시 폴링 중단 · 복귀 시 재개 | `WidgetsBindingObserver` 의 `AppLifecycleState` |

**V-03 문구 — 이게 이 화면의 핵심이다.** 관제웹은 "연결 중"만 떠서 원인을 알 수 없었다.

| 상황 | 띄울 말 |
|---|---|
| `gateApi` 가 빈 값 | 현장 CCTV 주소가 설정되지 않았습니다 |
| 티켓 401/403 | 이 현장 CCTV 를 볼 권한이 없습니다 |
| 티켓 404 | 등록되지 않은 카메라입니다 |
| 티켓 429 | 요청이 많습니다. 잠시 후 다시 시도합니다 |
| 티켓 503 | 서버에 CCTV 설정이 없습니다 |
| 게이트 연결 실패·타임아웃 | 현장 장비에 연결되지 않습니다 (Wi-Fi·장비 전원 확인) |
| 게이트 503 `disabled` | 현장에서 카메라를 꺼 두었습니다 |
| 게이트 503 `too many viewers` | 동시 접속이 많습니다 |

**"연결 중" 하나로 뭉뚱그리지 마라.** 그게 지금 관제웹의 결함이고 V-03 이 그걸 고치려는 것이다.

⚠ 오류가 나도 **폴링을 멈추지 마라**(현장 네트워크는 끊겼다 붙는다). 다만 연속 실패 시
간격을 늘려라(2배씩, 최대 60초). 성공하면 원래 주기로 되돌린다.
