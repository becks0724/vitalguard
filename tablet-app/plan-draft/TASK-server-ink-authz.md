## 무엇이 뚫려 있나

`app/api/app-media/route.ts:157` 은 `annotationOf` 가 **있는지만** 본다.

```ts
if (!annotationOf) { ... 400 }
```

그래서 지금 이 세 가지가 **전부 통과한다.**

| 뚫린 것 | 결과 |
|---|---|
| 남의 원본 ID 를 적어 보냄 | **담당관 A 가 담당관 B 의 사진에 잉크본을 붙인다** |
| 없는 ID 를 적어 보냄 | **고아 잉크본**이 생긴다 |
| 잉크본 ID 를 원본으로 적어 보냄 | 잉크본에 잉크본이 달린다 — 목록·삭제 로직이 가정하지 않은 모양 |

태곤 님 결정은 **"작성한 담당관만 고친다"** 다. 위변조 방지가 이 기능의 존재 이유인데,
**남이 남의 기록에 표시를 붙일 수 있으면 그 자체가 위변조다.**

## 고칠 것 — `app/api/app-media/route.ts` 잉크 분기 한 곳

`annotationOf` 가 있을 때, **INSERT 전에** 원본을 조회해 아래 순서로 막아라.

| 검사 | 실패 시 |
|---|---|
| ① 원본이 **존재하는가** | **404** |
| ② 원본이 **잉크본이 아닌가** (`annotation_of IS NULL`) | **400** |
| ③ 요청자가 **그 원본을 올린 사람인가** | **403** |

- 조회는 **`getCalendarMediaById`(`lib/db.ts:4634`)를 써라.** 이미 있고, 이번에 그대로 두기로 한 함수다.
- ③의 신원은 이 라우트가 **이미 쓰고 있는 것**을 그대로 써라(`verifyAppJwt` 로 얻는 값).
  **새 인증 경로를 만들지 마라.**
- ⚠ **owner 예외를 둘지는 네가 정하지 마라.** 이 레포의 기존 미디어 소유권 규칙
  (`mediaScopeClause` · `MediaScope`)을 **먼저 읽고**, 그 관례와 일관되게 맞춘 뒤
  **무엇을 골랐고 왜인지 보고해라.** 확실한 것은 하나다 — **다른 담당관은 절대 안 된다.**

### 오류 문구

앱이 사용자에게 그대로 보여줄 수 있게 **사람이 읽는 한국어**로 써라.
기존 이 파일의 오류 문구 스타일(`"잉크본에는 annotationOf(원본 ID)가 필요합니다"`)을 따라라.

### 사진·영상·녹음은 그대로다

이 검사는 **잉크본에만** 적용한다. `annotationOf` 가 없는 일반 업로드는
**지금과 동작이 완전히 같아야 한다.** 회귀가 가장 큰 위험이다.
