**태블릿을 들고 현장을 걸어다니며** 쓴다. 사무실 책상이 아니다.

**P4 터치 근거·한계:** [설계 제약 §3](artifacts/design-constraints.md)의 실측표를 따른다.
맨손 표본 **20**, 천 표본 **18**이며 크기당 **3~4개**다. 천은 **면 95% 의류 원단을 손에 감싼 조건**으로,
원본 기록에는 **겹수·두께가 없다.** 실제 면 목장갑·PU 코팅장갑을 대표하지 않는다.
**4/4는 네 번 중 실패가 없었다는 뜻**이며 실패율 0%를 보장하지 않는다.
**72dp 맨손 오차 69.1**은 원본 기록의 측정 사고 이상치다.
맨손 평균 오차 벡터는 **(3.3, 12.7)dp · 크기 13.2**, 천은 **(2.7, 7.7)dp · 크기 8.1**로,
아래쪽 편향은 천 조건에서만 나타난 현상이 아니다. 손가락 압력은 **1.000 고정**, 접촉반경은 **0.1~0.2**로
이 값으로 **장갑 착용을 자동 감지하지 않는다**. 펜 필압은 **0.041~0.917**로 변한다.

## 0.3 캔버스 **[관측]** — 앱을 실기기에 띄워 잰 값 (2026-09-12)

```
             세로                        가로
전체        865.9 × 1385.4 dp         1385.4 ×  865.9 dp
안전 영역    865.9 × 1331.3 dp         1385.4 ×  811.8 dp   (상 39.1 + 하 15.1 제외)
IME 뜰 때    865.9 ×  978.3 dp         1385.4 ×  458.8 dp
IME 소실률        26.5%                      43.5%   ← 가로가 1.6배
좌우 제스처 띠    29.6 dp 각각               29.6 dp 각각  (회전해도 같다)
```

**이 표에서 곧장 나오는 규칙 3가지**

1. **`SafeArea` 만으로는 부족하다.** `padding.left/right` 는 **0.0** 인데
   좌우 제스처 띠 **29.6 dp** 는 `systemGestureInsets` 에만 있다.
   → 드래그·스와이프·캔버스 끝 획은 `MediaQuery.systemGestureInsets` 를 **직접 읽어** 피한다.
2. **상태바·네비바는 회전해도 위/아래**다. 가로에서 측면으로 옮겨 간다고 가정하지 않는다.
3. **가로에서 키보드는 화면 절반 가까이를 먹는다**(43.5%). `IME 368.0 dp` 는 방향과 무관하게
   같은데 안전 높이만 줄기 때문이다. → **가로일수록 키보드를 더 피한다.**

> ⚠ **런타임 인셋을 읽는다.** 위 수치는 "이 창·이 방향·이 IME(Gboard 한글 기본)"의 관측값이고
> **하드코딩하지 않는다.** 다른 입력기·이모지 패널·분할창에서 달라진다.

# 1. 정보 구조

## 1.1 [확정] 4목적지

```
┌ 공통 상단 ─────────────────────────────────┐
│ 현장명            ◷ 마지막 수신 12:10      │
│ [!!] 새 경보 2건 · …          [ 경보 보기 ] │ ← 비차단 · 슬롯 항상 예약
├ 본문 ──────────────────────────────────────┤
│                                            │
│                          [ 주 실행 ]  ← 한 벌·좌/우 선택
├ 목적지 ────────────────────────────────────┤
│  현장    경보②    기록    전송함            │
└────────────────────────────────────────────┘
      └ 현장·경보 상세에서 → 영상 보기
```

## 1.2 왜 이 구조인가

| 결정 | 이유 |
|---|---|
| **2층 탭 해체** | 관제웹은 상위 6 + 하위 4 2층이지만, 사무 4개를 뺀 뒤에는 유지할 이유가 없다 |
| **경보를 목적지 + 전역 스트립 둘 다** | 이력·분류는 업무함이고, **새 경보는 어느 화면에서든 알려야** 한다 |
| **자동 모달 금지** | 펜으로 쓰는 도중 확인 버튼이 손끝 아래 삽입되면 **오조작**한다 |
| **스트립 슬롯 항상 예약** | 경보가 왔을 때 **캔버스 높이가 변하면** 스트로크 좌표·터치 대상이 움직인다 |
| **영상은 상세 진입** | 독립 빈도 미확인 · 대역폭·배터리 부담 |
| **전송함이 목적지** | 지연 전송을 하는 이상 **"무엇이 올라갔나"** 를 볼 곳이 필요하다 |
| **현장 전환 버튼은 2개일 때만** | 배정이 1개면 **선택지가 하나뿐인 UI** 를 두지 않는다 |

## 1.3 화면 계층

```

V 영상      단일 채널 (상세에서 진입)

```

# 2. 화면별 설계

각 화면의 **목적 / 구성 / 규칙 / 실패 상태**를 적는다. 시각 시안은 `artifacts/ui-mock/index.html`.

## 2.1 A 인증

### A-01 로그인
- **목적** — 관제웹과 같은 계정으로 들어간다. **가입 화면은 없다**(계정은 관리자가 만든다).
- **구성** — 로고 · 아이디 · 비밀번호 · `이 기기에서 로그인 유지` · `로그인` · 아이디/비밀번호 찾기
- **규칙** — 입력칸 **72dp**, 버튼 **64dp**(장갑). **비밀번호를 기기에 저장하지 않는다**(토큰만).
- **실패** — `A-03` 잘못된 자격 · `A-04` 미승인(403) · `A-05` 서버 미설정(503) · **`A-11` 사용 불가 역할**

### A-02 2단계 인증
- **구성** — 6자리 입력 · `확인` · `다른 방법으로 로그인`
- **규칙** — 비밀번호를 그대로 쥔 채 `totpCode` 만 더해 재전송(중간 토큰 없음).
- ⚠ **서버가 주지 않는 수치를 화면에 만들지 않는다.** 현재 API 는 **남은 시도 횟수를 주지 않는다** —
  잠겼을 때 `429` + `retryAfterSec` 만 준다. **잠긴 뒤에 남은 시간을** 보여준다.

### A-06 현장 선택
- **1개면 이 화면을 건너뛴다.** 2개일 때만 뜬다.
- 각 현장에 **상태 아이콘 · 미대응 경보 수 · 마지막 수신 · 미전송 기록 수**를 함께 보여준다.
- 고지 — *"현장을 바꾸면 조회는 새 현장으로 바뀌지만, **아직 보내지 못한 기록은 작성한 현장에 그대로** 남아 그 현장으로 전송됩니다."*
- **[확정 2026-09-12]** 현재 서버는 `site_info_daily`의 전역 최신 1행만 주므로 단일 현장이다.
  기존 **배정 1개면 건너뛴다** 규칙대로 앱에서 통과한다. 다중 현장이 생길 때를 위해 화면 정의는 보존한다.

### A-12 첫 로그인 비밀번호 변경 — 앱에서 제외
- **[확정 2026-09-12]** 앱에서 제외하고 관제웹이 담당한다. `/login`·`/me`가 변경 필요 여부를 주지 않으므로
  앱은 이 상태를 판정하거나 차단하지 않는다.
- ⚠ **[미검증 · 잔여 리스크] 첫 비밀번호를 바꾸지 않은 계정도 앱에 로그인된다.**
  관제웹에서 강제 변경을 거치지 않은 계정이 앱으로 먼저 들어올 수 있다.

### A-07~A-11 (실패·경계)
`A-07` 세션 만료/회수(`refresh` 와 `reauth` 구분) · `A-08` **재로그인 전 초안 보존 안내** ·
`A-09` **재로그인 계정이 다름**(이전 큐 미발송) · `A-10` 배정 현장 0개 ·
`A-11` **이 앱을 사용할 수 없는 계정**

**[확정] 허용 목록** — `role IN ('platform_admin','site_manager')`.
시공사 법인 계정은 `site_manager` + `is_company_account=true` 표지라 **같은 검사로 통과**한다.

> **A-11 은 A-04 와 다르다.** 승인이 안 된 게 아니라 **역할이 다른 것**이라 문구가 달라야 한다.
> ⚠ **서버가 토큰 자체를 발급하지 않는다.** 앱이 화면만 가리면 API 는 열려 있다.

**[확정] 실패·경계 화면 규칙** (코덱스 지적 반영)

| 상황 | 하지 말 것 | 할 것 |
|---|---|---|
| `access` 만료 | 곧바로 로그인 화면으로 보내기 | **single-flight refresh 먼저.** 복구되면 사용자를 건드리지 않는다 |
| `refresh` 실패·회수 | "닫으면 보호된 화면으로 돌아감" 식의 시트 | **재인증 요구.** 화면 전환 **전에** 초안을 기존 사용자·현장에 묶어 영속화 |
| 네트워크 장애 | 큐·`refresh` 토큰 삭제 | **회수로 오인하지 않는다.** 상태만 `전송 대기` 로 |
| 계정 B 로그인 | A 큐의 **썸네일·내용·이름·현장명·건수** 노출 | B 전송함엔 B 기록만. 안내는 *"다른 계정으로 작성한 기록은 해당 계정으로 로그인한 뒤 확인할 수 있습니다"* + `[계정 전환]` |
| 배정 현장 0개 | "배정이 없습니다"를 조회 실패에도 쓰기 | **조회가 성공해 0개일 때만.** 실패는 *"현장 목록을 불러오지 못했습니다"*, 비활성·회수는 별도 문구 |

- **A-08 문구 정정** — *"작성 현장으로 그대로 전송됩니다"* 는 **권한이 유지된다는 조건이 빠졌다.**
  → *"미전송 기록은 작성한 현장에 보관됩니다. 전송할 때 해당 현장 권한을 다시 확인합니다."*
  배정이 회수된 뒤에도 무조건 전송된다고 약속하면 안 된다.
- **A-10 동작** — `[배정 다시 확인]` `[다른 계정으로 로그인]`.
  `[관리자 문의]` 는 **연락 경로가 실제로 마련돼 있을 때만** 둔다.
  이전 현장의 미전송 자료는 **보존하되**, 배정 0개 상태에서 조회·발송 권한을 만들어 주지 않는다.
- ⚠ **[미결]** 오프라인 캐시 **열람**을 재인증 전에도 허용할지는 **D-7 정책**으로 따로 정한다.
- B 가 A 의 기록을 **자기 이름으로 발송**하거나 **일괄 삭제**하는 버튼은 두지 않는다.

## 2.2 S 현장

### S-01 현장 요약 — **첫 화면**
- **목적** — 이 화면만 보고 **"지금 현장이 어떤가"** 가 끝나야 한다.
- **구성**
  ```
  [작업 중 1/4명]  [미대응 경보 2건]  [미전송 기록 2건]      ← 3지표
  현장 상태
   [✓] 현장 기상   특보 없음 · 광주               12:08  ›
   [✓] 작업자      정상1 · 대기3 — 대기자는 미수신  12:10  ›
   [!!] 가스 감지   CO 52ppm · 탱크 야드           12:10  ›   ← 행 배경 연빨강
   [!] AED         배터리 교환 임박 · B1 외 1건    09:00  ›   ← 행 배경 연주황
  영상   [CAM-03] [CAM-01] [CAM-02]                            ← 눌러야 켜짐
                                     [ ✎ 현장 기록 남기기 ]
  ```
- **규칙** — 행 높이 **72dp**(V-5) · 상태는 **아이콘 + 행 배경**(글자 중복 없음) ·
  **각 행에 수신 시각**을 함께 둔다 · 영상은 **자동 재생하지 않는다**(데이터·배터리).
- **실패** — `S-07` 최초 캐시 없음 · `S-08` 수신 오래됨 · `S-09` 부분 실패 · `S-10` 권한 거부

> ⚠ **`조회 0행`을 `정상 0건`으로 표시하지 않는다.** 데이터가 없는 것과 이상이 없는 것은 다르다.
> ⚠ **대기 작업자는 생체 미수신이라 판정 대상이 아니다** — 화면이 이 구분을 말한다.

### S-02 작업자 (카드형)
관제웹 12컬럼 표는 866dp 에 안 들어간다. **카드 1장 = 작업자 1명**으로 재설계하고,
카드에는 **이름·직급·상태 아이콘·핵심 수치 2~3개·수신 시각**만 둔다. 나머지는 펼침.

### S-03 작업자 지도
VWorld 항공사진 + 마커. **나침반이 없어 방위를 표시하지 않는다.**
`GPS 수신 n / 전체 m` 을 함께 보여준다.

### S-04 가스 · S-05 AED · S-06 기상
- **가스** — **실연동/데모 구분을 유지**한다. ⚠ 실연동은 `raw`, 데모는 `ppm` 으로 **단위가 섞여 있다.**
  위험·주의 행을 **상단 고정**하는 것을 검토한다.
- **AED** — 교환주기·점검 예정일.
- **기상** — **현장 고정 좌표 기준**(작업자 위치를 쓰지 않는다).

## 2.3 L 경보

### L-01 목록

- ⚠ **행을 탭해도 확인 처리되지 않는다.** 상세로 들어갈 뿐이다.
- ⚠ **`미대응 모두 확인`은 첫 시안에서 제외**한다(오조작 영향이 크다).

### L-02 상세 + 대응 확인

- ⚠ **결과 불명이면 재전송이 아니라 서버 상태 재조회**가 먼저다.
- **연락** — `연락처 복사` · `보호자 정보 보기`.
  ⚠ 화면이 말한다 — *"이 태블릿은 통화 기능이 없습니다(셀룰러 미탑재). 전화는 단말기로 거세요."*

### L-03 오프라인 — 대응 확인 불가
- 버튼을 **비활성**하고 이유를 말한다: *"대응 확인은 연결된 뒤에 가능합니다."*
- **예약·완료 상태를 만들지 않는다.** 연결돼도 **자동 처리하지 않고 직접 다시 눌러야** 한다 —
  누가 언제 확인했는지가 안전 기록이기 때문이다.
- 캐시된 경보 내용은 계속 보여주되 **"11:41에 받아둔 것"** 임을 밝힌다.

### L-05~L-07

## 2.4 R 기록 — **요구사항 13의 핵심**

### R-01 캘린더 · R-02 날짜별 목록
관제웹 3단(사이드+격자+패널)은 태블릿 세로에 안 들어간다.
세로는 **날짜 선택 → 목록 → 상세** 1단을 유지하고, 가로는 **왼쪽 캘린더 / 오른쪽 그날 목록** 2단으로 둔다.
회전 중에도 선택 날짜를 유지하고 오른쪽 목록을 즉시 갱신한다. 기준 실측은 세로 **865.9×1385.4dp**,
가로 **1385.4×865.9dp**다. 방향을 고정하지 않는다. 미확인 사진 배지를 유지한다.

### R-03 사진 상세
- **구성** — 사진 · 촬영시각 · 도로명 · GPS · **좌표 대조** · 촬영자 · `원문 OCR 보기` · 댓글
- **타인이 올린 사진이 기본 가정**이다. **원본 수정권과 "내 주석을 덧붙일 권한"은 다르다.**
- **주 실행** = `[✎ 펜으로 표시하기]`
- 가로에서는 사진과 상세·실행을 2단으로 두어 주 실행을 첫 화면에 온전히 보인다. 세로는 1단을 유지한다.

### R-04 펜 주석 캔버스
- **구성** — 가로 전체를 쓰는 캔버스 + **도구 한 벌**(펜·형광펜·도형·지우개·되돌리기) +
  확인을 거치는 `전체 지우기` + `원본만 보기` + `저장`
- **규칙**
  - **경보 스트립 슬롯이 상단에 예약되어 있어 새 경보가 와도 캔버스 높이가 변하지 않는다.**
  - **펜 = 그리기 / 손가락 = 이동·확대**(T-3). 도구판은 **갑자기 위치를 바꾸지 않는다.**
  - **자동 임시저장**하고 그 사실을 표시한다.
  - 필압·기울기를 반영한다 — **[관측] 둘 다 실제로 변한다**(필압 `0.041~0.917` · 기울기 `59.7°`).
  - **지우개는 화면 안 도구로 만든다(P-6)** — 펜에 **지우개 꼬리가 없다**(`invertedStylus` 표본 0).
  - 가로 기본 보기는 사진을 폭에 맞춰 크게 잡고, `전체 보기`는 원본 전체가 들어오도록 맞춘다.
    캔버스를 2단으로 쪼개지 않는다.
  - 색 선택 원은 **40dp로 보이게** 하고 탭 영역은 **56dp**로 유지한다.
  - `전체 지우기`는 되돌릴 수 없으므로 확인 대화상자를 거친다. `주석 저장`·`되돌리기` 바로 옆에 두지 않는다.
  - **펜 측면 버튼에 기능을 걸지 않는다** — OS 펜 메뉴가 선점해 앱까지 오지 않는다 **[관측]**.
  - ★ **[관측] 팜 리젝션은 "차단" 이 아니라 "사후 취소" 다.** 손바닥이 일단 `touch` 포인터로
    **들어온 뒤**(동시 접촉 2) 시스템이 `PointerCancel` 로 거둬간다. 취소되는 건 `touch` 이고
    **`stylus` 획은 살아남는다.** 따라서:
    - **잉크는 `stylus` 만 그린다(P-4).** `touch` 로도 그리면 **취소가 오기 전 몇 프레임이
      손바닥 점으로 화면에 남는다.** 이건 §T-3("펜=그리기 / 손가락=이동·확대")을
      **편의가 아니라 정확성 때문에** 반드시 지켜야 한다는 뜻이다.
    - **`onPointerCancel` 로 취소된 포인터의 획을 되돌린다(P-5).** 다른 포인터의 정상 펜 획은 보존한다.
      `onPointerUp` 만 처리하면 흔적이 영구히 남는다.
    - **동시 접촉 2를 전제**로 짠다. 포인터 하나를 가정한 코드는 여기서 깨진다.
- **실패** — `R-10` 원본 접근 불가 · `R-11` 저장공간 부족 · 수정 충돌

### R-05 저장 결과 — **[확정] A안 + 보완 2**
**근거** — 한 현장 = 담당관 1명 = 태블릿 1대(태곤 님 2026-09-12). "다른 기기에서 열기"가
구조적으로 발생하지 않아 B안의 이점이 무의미하다.

| 보완 | 화면에서 |
|---|---|
| **`dateKey` = 원본 날짜** | 주석본이 **원본과 같은 날짜 칸**에 놓인다 |
| **`title` 에 원본 식별자** | `현장 이미지 (주석) — 원본 08-28 14:38` 로 관계가 보인다 |

- **전송은 1건**이다(D안은 2건이라 *사진만 성공하고 댓글 실패*가 가능).
- **로컬 벡터는 보관**하므로 본인 기기에서는 **주석만 지우거나 이어서 고칠 수 있다.**

- 가로는 결과 이미지와 상태·실행을 2단으로 두어 `주석 이어서 편집`을 첫 화면에 보인다.
- 모의 게이트웨이가 성공을 돌려줘도 **`모의 전송 완료 — 실제 서버로 보내지 않았습니다`**라고 표시한다(N-1의 짝 원칙).

> ⚠ **실제 앱에는 A/B/D 기술 선택을 노출하지 않는다.** 평가용 UI 다.

### R-06 입력 3경로 — **요구사항 14**
```
① 내가 남기는 현장 평가   ← 센서 판정과 별개. 관리자가 적는 기록
   [이상 없음] [재점검 필요] [작업 중지] [즉시 조치 요망]   ← 색 띠 없음
   ⚠ 기본 선택 없음 — 확인 없이 안전 기록을 만들지 않는다. STT의 I-5와 같은 원칙
② 펜으로 쓰기            [글씨 그대로 저장]  ← 자유 기록의 1순위
   자동 필기 텍스트 변환은 이번 채택 범위에 넣지 않는다
③ 말로 하기              [🎤 누르고 말하기]  ← 푸시투토크. 상시 청취 아님
   반환 후보 최대 5개 표시 → 사용자 선택·필요 시 수정 → 문장 확인 → 저장
   기본 선택 없음 · 후보를 고르는 것만으로 저장하지 않음 (I-4·I-5)
```
- **[확정] 요구사항 14의 채택 결론:** **펜 잉크 그대로 저장이 자유 기록의 1순위**, 순정 온디바이스 STT는
  **후보 선택·확인 필수인 보조 수단**이다. 정형 응답은 기존 입력 칩을 먼저 사용한다.
  Lenovo OS 손글씨 기각은 유지하고 **ML Kit·sherpa-onnx는 채택 불요**다. ML Kit은 사용 불가로 결론낸 것이 아니다.
- **I-4 후보 선택 화면:** 1순위 한 줄을 자동으로 입력하지 않는다. **후보 5개를 상한으로 요청하고 실제 받은 후보를
  원래 순서대로 모두 표시**한다. 원시 로그에는 **3~5개**가 돌아왔으므로 없는 후보를 만들지 않는다.
  후보 영역은 스크롤할 수 있게 하고 선택한 문장을 별도 확인 영역에 보여준다. 정답이 없으면
  **다시 말하기·수정·펜 기록**을 제공한다. 선택은 저장이 아니다.
- **I-5 확인 후 저장:** 실측에서 **`작업자 두 명 안전대 미착용` → `작업자 두 명 안전띠 적용`**으로
  부정이 사라져 뜻이 뒤집혔다. 후보 선택 후 문장 전체를 보여주고 **명시적인 확인·저장**을 거친다.
  수정하면 수정된 문장을 다시 확인한다. 미확인 후보·부분 결과는 업무 기록·전송 큐에 저장하지 않는다.
  위 **‘이상 없음’ 기본 선택 금지**와 서로 같은 원칙으로 적용한다. 진단용 원시 로그 보존은 별개다.
- **[관측] 근거:** `createOnDeviceSpeechRecognizer`·`ko-KR`가 비행기모드 ON·Wi-Fi OFF·활성 네트워크 OFF에서 인식됐다.
  오프라인 최종 **5건 중 1건**은 1순위 원문 일치, **5건 중 3건**은 후보에 원문이 포함됐다.
  조건당 5문장 최종 결과 1회씩이므로 정확도·향상 배수로 일반화하지 않는다.
  같은 ‘미착용’ 문장이 오프라인에서는 맞았으므로 온라인 연결 때문에 부정이 사라졌다고 쓰지 않는다.
  [원시 로그 251 이벤트](research/raw/p4-stt-2026-09-12.jsonl) · [전체 결과 표](research/device-facts.md).
- **[확정]** 칩은 **한 축(조치 수준) 4단계**다. 종전 6개는 *사안 유형*과 *조치 수준*이 섞여 있었다.
- **구체적 내용(무엇이·어디가)은 펜·음성이 맡는다** — 칩으로 사안을 열거하면 목록이 감당 못 하게 커진다.
- **[확정] 서버 판정과 섞지 않는다** (코덱스 지적 반영). 종전 미결이던 항목의 결론:
  - 4문구를 서버 `severity`(정상/주의/위험)로 **자동 변환하지 않는다.** 이건 4단계 등급이 아니라
    **4개 기록 선택지**다. `작업 중지`와 `즉시 조치 요망` 사이에 **순위가 정의된 적이 없다.**
  - **칩의 등급 색 띠를 없앴다.** ok/warn/danger 3색으로 칠하면 ⓐ 3단계로 접히는 것처럼 보이고
    ⓑ 뒤 두 개가 같은 등급으로 읽히며 ⓒ 그 빨강이 **위쪽 센서 판정 점과 같은 색**이었다.
    색 대신 **`관리자 기록` 출처 라벨**로 구분한다(§3.2 "같은 말을 두 번 하지 않는다"와도 맞는다).
  - **`관리자 기록: 이상 없음` 과 `센서 판정: 위험` 은 동시에 존재할 수 있다.** 전자가 후자를
    해제·덮어쓰지 않는다. 각각 **출처와 시각**을 따로 표시한다.
  - `작업 중지`를 골랐다고 해서 **작업중지 지시가 전달됐다/완료됐다고 표시하지 않는다.** 실제 명령·
    조치 완료는 별도 제품 결정과 감사 계약이 필요하다. 칩 선택은 **초안 값 변경**일 뿐이다.
  - **저장 후보 필드** — 선택 코드/원문 · 작성자 · 작성 현장 · 관찰 시각(사용자 입력) ·
    서버 접수 시각 · 관련 사진/주석 ID. 기존 `alert.severity` 나
    `calendar_event.hazard_type` 에 밀어 넣지 않는다.
  - ⚠ **[미검증]** 현 API 에 이 구조를 받을 필드가 없다. **원문 메모로 보존하는 임시 방식**과
    **전용 계약 추가** 중 어느 쪽인지는 서버 팀과 따로 정해야 한다.
- **키보드는 최후 수단**이다 — 뜨면 안전 높이의 **세로 26.5% · 가로 43.5%** 가 사라진다 **[관측]**.

# 3. 시각 언어

## 3.1 색 — 관제웹 토큰을 그대로 쓰되 **쓰는 방식이 다르다**

| 용도 | 값 | 쓰는 법 |
|---|---|---|
| 브랜드 | `#0D74CE` | **흰 글자만** 올린다(4.77:1). 잉크는 실패(3.76:1) |
| 본문 | `#171717` / `#60646C` | 흰 배경 17.93 / 5.94 |
| 정상 | `#10B981` | **배경면 전용.** 위에 잉크(7.07:1) |
| 주의 | `#F59E0B` | **배경면 전용.** 위에 잉크(8.35:1) |
| 위험 | `#EF4444` | **배경면 전용.** 위에 잉크(**4.76:1** — 7~8.4 아님) |

> ⚠ **`주의`·`정상`·`muted` 는 흰 배경 위 본문 텍스트로 쓸 수 없다**(2.15 / 2.54 / 2.85:1).
> 이것은 **실내·야외 공통**이다.

## 3.2 상태 표시 — 같은 말을 두 번 하지 않는다

```
정상  ✓   둥근 사각        주의  !   둥근 사각        위험  !!  원형
```
- **모양이 곧 라벨**이다. `[✓정상]` 처럼 글자를 붙이면 옆 문장과 의미가 겹쳐 번잡해진다.
- 색을 못 보는 사람을 위해 **글자 수(✓/!/!!)와 테두리 모양을 모두 다르게** 한다.
- 접근성은 `title`·`aria-label` 로 보장한다(화면에는 안 보인다).
- ⚠ 녹색·주황 면 자체가 흰 바탕 대비 3:1 미달이므로 **테두리로 비텍스트 대비를 보강**한다.

# 4. 반응형

## 4.1 [문서] 방향을 고정할 수 없다

Android 16 은 **targetSdk 36 + sw600dp 이상**에서 방향·크기 제한을 기본적으로 무시한다.
**판단 기준은 방향이 아니라 창 크기 클래스**다.

| 창 | 레이아웃 |
|---|---|
| 좁음(분할창 포함) | **1단** — 목록 → 상세 |
| 보통(세로 전체화면) | 1단 + 필요 시 2단 |
| 넓음(가로 전체화면) | **2단** — 좌 목록 / 우 상세 |

> ⚠ "세로=1단 / 가로=2단"으로 단정하지 않는다. **좁은 가로 분할창은 1단**이고,
> 2단 가능 여부는 **최소 패널 폭·글자 확대·필기 면적**이 정한다.

## 4.2 전환 시 지켜야 할 것

**작성 중인 스트로크(원본 좌표계) · 댓글 초안 · 선택한 사진 · 대기 큐를 잃지 않는다.**

## 4.3 edge-to-edge

시스템 바 아래까지 그리되 내용은 `SafeArea` 로 보호한다.
⚠ **`ime` 인셋에는 하단 네비바가 이미 포함**된다 — **중복 차감하지 않는다.**
