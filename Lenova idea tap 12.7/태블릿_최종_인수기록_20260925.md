## 2. 구현된 사용자 흐름

- **현장 / 경보 / 기록 / 전송 상태 / 설정** 5개 목적지. CCTV는 현장 상세에서 진입한다.
- 사진을 찍어 **기기에 보류**하고, 펜 주석·텍스트 메모·음성을 붙인 뒤 명시적으로 한 번에 전송한다(R-7).
- 원본 사진과 잉크 벡터를 분리하며, 서버의 부모 영수증 ID로 딸린 기록을 연결한다.
- 전송 완료 원본과 추가 열람·편집은 관제웹에서 처리한다. 완료 시 기기 원본·미리보기 정리, 완료 메타데이터는 7일 보관 규칙을 적용한다.
- 오프라인 기록을 보존하고 자동 재전송하지 않는다. 결과 불명은 서버 등록 여부 확인 후 재시도한다.
- 경보 대응 확인은 명시적 사용자 동작이며 오프라인 예약을 하지 않는다.
- 펜만 잉크를 그리고, 손가락 이동·핀치 확대와 구분한다. 지우개는 닿은 획을 통째로 지운다.
- 현장 정보 수동 갱신, 403 뒤 재조회, 로그인 거부 시 서버 세션 폐기 후속 수정이 반영돼 있다.

권한 범위: 현재 앱은 응답 역할 `platform_admin`·`owner`·`site_manager`·`admin`을 허용한다. 신 DB의 공용 응답에서는 `site_manager`와 `owner_officer`가 둘 다 `admin`이므로, 최종 역할 제한은 서버 Q2가 담당한다. 공용 로그인·미디어·댓글까지 관리자 API와 같은 차단 범위라고 간주하지 않는다.

확인 한계: release 앱의 기기 내부 파일이 실제로 0개 남는지는 직접 전수 조회하지 못했다. R-7 정리는 단위 테스트와 UI의 목록 비움·재진입 차단으로 검증했다.

## 5. 현재 설치본과 신 DB 준비본 구분

| 구분 | 현재 태블릿 | 신 DB 준비본 |
|---|---|---|
| 코드 | main `4ac6f170` 포함 `8b9a071c` | `feat/newdb-cutover` Q9 `9fb95dd5` |
| 경보 ID | 양의 정수만 | **UUID 문자열 + 기존 양의 정수** 함께 지원 |
| 앱 검사 | 617/617 · 분석 문제 없음 | 담당 보고: 625/625, 관련 35/35 · 분석 문제 없음 |
| APK | 현재 설치·복원 확인 완료 | 담당 보고: 기존 릴리스 키 빌드 86.3MB, **실제 기기 미설치** |
| 반영 범위 | main push 완료 | 16:42 KST 인계 기준 main 반영·push 없음 |

Q9 커밋의 UUID/정수 분기 코드는 직접 대조했다. 테스트·빌드 숫자는 신 DB 담당의 검증 보고다.
담당은 전환 준비 환경의 로그인·역할·현장 격리·UUID ack 7/7 통과를 보고했으며 서버 전환 검증을 계속하고 있다. 이를 라이브 태블릿 통과로 기록하지 않는다.

전환 시 담당자가 확인할 것:

1. 전환할 main에 `4ac6f170`과 Q9 준비본이 포함됐는지 확인한다.
2. 설치될 APK의 커밋·해시·서명을 고정하고 실제 기기에 덮어설치한다.
3. 신 DB에서 site_manager·platform_admin의 관리 API 허용, owner_officer·worker 거부, 현장 배정 범위를 확인한다.
4. 실제 UUID 경보 한 건을 명시적으로 확인 처리하고 서버 결과·처리자·중복 처리 여부를 대조한다.
5. 사진 묶음의 참조·멱등키·결과 불명 복구를 신 DB에서 확인한다.

이 전환 작업의 담당·실행 순서는 [DB 전환 런북](../../DB재구축/15_라이브_전환_런북_초안_20260916.md)을 따른다.

## 7. 실행·복원과 자료 위치

현재 폴더에서 다음과 같이 같은 서명의 APK를 덮어설치한다. 앱 삭제는 하지 않는다.

```sh
adb -s HA2HG0SD install -r artifacts/releases/20260925/vitalguard-field-4ac6f170.apk
adb -s HA2HG0SD shell am start -W -n com.vitalguard.field/com.vitalguard.vitalguard_field.MainActivity
```

이 APK는 현재 구 DB 계약의 설치본이다. 신 DB 전환 뒤에는 정수 전용 구 앱만 단독 복원하면 UUID 경보 처리가 맞지 않으므로 서버 계약과 함께 판단한다.
서명키와 비밀번호는 기존 보관 체계를 유지하며 이 문서·APK 자료 묶음에 포함하지 않았다.
