## 요청과 화면

- 대시보드 ‘영상 보기’는 바로 CAM-03으로 들어가지 않고 카메라 선택 팝오버를 연다. 사용자 제공 화면 미러링 메뉴처럼 둥근 반투명 회색 패널, 가운데 겹친 화면 아이콘/제목, 구분선과 카메라 행을 사용한다. CAM-01 또는 CAM-03을 누르면 해당 영상으로 들어간다.
- 기존 앱은 CAM-03과 `/cctv/stream3`만 고정했다. 카메라 선택과 `/stream1`·`/stream3` 대응을 추가했다. 실제 권한은 카메라별 티켓 API가 판단한다.
- 현재 앱용 카메라 목록 API는 없다. 확인된 CAM-01·CAM-03을 선택지로 제공하며 목록에 보이는 것을 연결 성공/권한 보유로 간주하지 않는다. 신 DB 관제 세션용 카메라 목록 API를 앱 JWT로 호출하지 않는다.
- CCTV 화면 상단은 이전·제목·카메라 탭·설정과 짧은 수신 상태로 압축했다. ‘다시 받기’는 제거했다. 아래 영상이 남은 높이를 모두 쓰고 CCTV의 빈 경보 슬롯도 회수한다. 실제 경보는 계속 표시한다.
- 영상 터치는 더 큰 오버레이를 연다. 두 손가락 확대(1~5배), 확대한 영상 이동, ‘원래 크기’(1배·중앙), 이전/시스템 뒤로가기로 닫기를 제공한다. 영상은 원래 종횡비를 유지하고 새 프레임이 와도 확대율을 유지한다. 카메라 전환·뷰포트 변경 시 초기화한다.
- 설정의 2/5/10초 버튼을 **실시간·0.5초·1초·1.5초·2초 슬라이더**로 바꿨다. 기본2초. 계정별 `settings:cctv-period-ms`에 저장하고 기존 seconds 키와 구분한다. 이전2/5/10초 설정은 새 범위 기본2초로 해석하며 계정 선택을 섞지 않는다.

## 수신 계약

- `POST /api/app/admin/cctv-ticket`에 앱 Bearer와 선택한 `cameraId`를 보내 read 티켓을 받는다. 영상 게이트에는 전용 티켓만 보낸다. 세션 토큰/비밀번호는 보내지 않는다.
- 실시간은 **MJPEG 연결 하나에서 연속 프레임을 받는 방식**이다. 나머지 값은 같은 스트림에서 화면에 반영하는 간격이다. 0.5~2초 선택이 네트워크 사용량을 줄인다고 주장하지 않는다.
- 티켓은 연결마다1회 소비된다. 만료 시 새 티켓으로 다시 연결하며 기존 티켓을 재사용하지 않는다. 매 프레임 티켓을 새로 발급하지 않으므로 서버 분당60회 제한을 짧은 폴링으로 소진하지 않는다.
- 선택한 카메라 하나만 수신한다. 카메라 변경은 이전 이미지를 즉시 비우고 이전 연결의 늦은 프레임을 버린다. 화면 이탈·백그라운드·로그아웃 시 수신을 멈춘다.
- 길이가 있는/없는 MJPEG 파트 모두 처리하고 다음 경계를 보존한다. 프레임16MB·이미지1600만 픽셀 제한, HTTPS/리다이렉트 금지, 무응답15초 제한을 유지한다. 재연결 실패는 최대60초 backoff이며 실시간에서도0초 재시도 루프를 만들지 않는다.
- 실제 FPS/지연은 원본 카메라와 네트워크에 따른다. 앱이 카메라 촬영 프레임률을 올리거나 소리를 재생하는 것은 아니다. 서버·Jetson 설정/배포 변경은 없다.
