### 0.3 그대로 확정하면 안 되는 조사 문구

1. **v2 수용 ≠ 관제 인가 ≠ 2FA 완료 ≠ 즉시 회수.** `verifyAppJwt`는 서명·만료를 확인하므로 유효 v2도 통과한다. `verifyMobileAccessJwt`는 aud/tokenUse/v/sessionId를 추가 검사하지만 DB 세션 상태를 조회하지 않는다. 로그인은 조건부 TOTP이며 `twoFactorPending` 계정도 발급 가능하다. 기존 앱 API 재사용과 관제 API 확장을 따로 검증한다.
2. **주석 A/D의 ‘서버 변경 없음’은 합성 이미지 게시 형식 한정.** 기존 업로드 재사용 후보이지만 영속 원본 연결·다중 단말 재편집·중복 방지는 별도 계약이다. A/D라도 로컬 원본+벡터를 보존하면 작성 단말에서 다시 편집할 수 있다.
3. **IME 언어 목록·서비스 등록은 문장 입력 성공 증거가 아니다.** Lenovo 한국어 팩 설치 후 실펜 시험에서 오인식이 확인되어 현재 주력 후보에서 기각했다(§0.4). ML Kit·Gboard·실제 Flutter 필드·비행기모드·수정 동작은 별도 시험이다. 순정 STT 등록도 오프라인 한국어 보장이 아니다. [Android SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer)
4. **펜 축 보고는 실제 변화·팜 거부·지연 실증이 아니다.** 144 Hz는 화면 모드다. 500 nit도 시스템 보고값이지 광도계 실측이 아니다. `pressureMin` 하나로 펜 여부를 결정하지 않는다. [Flutter PointerEvent](https://api.flutter.dev/flutter/gestures/PointerEvent-class.html)
5. **1385×866 dp는 전체 화면 환산 참고치.** 실제 창·시스템 바·IME·분할창에 맞춰 적응한다. API 36 큰 화면의 방향/크기 제약 변경을 검토한다. [Android 16 동작 변경](https://developer.android.com/about/versions/16/behavior-changes-16)
6. **프리사인 URL과 이미지 바이트 캐시는 별개.** 만료 URL을 영속 ID로 삼지 않는다. 권한과 보존 정책을 정한 파일 캐시는 별도 설계할 수 있다.
7. **새 패키지·유지보수 평가는 채택 전 재확인한다.** ‘조사 권고’를 ‘팀 확정’으로 옮기지 않는다. 이벤트 소싱·Drift·FCM·FSI·네이티브 잉킹 모두 필요 범위와 시험을 거친 후보다.
8. 기존 폰 앱의 평면 `lib/`·Swift 수집·Riverpod 미사용은 그 앱의 관례다. 새 담당관 앱에 자동 복제하지 않는다. 판정과 의미 색의 일관성은 유지한다.
9. **KST 날짜와 촬영 시각을 분리한다.** 현 업로드는 dateKey 누락 시 capturedAt 앞 날짜를 사용한다. ‘Z는 항상 9시간 오류’로 일반화하지 않고 자정·명시 dateKey·지연 업로드 계약을 시험한다.

화면 설계의 사실 기준은 live-server-analysis §6이다. 상위 6탭+관제 하위 4탭, 안전 신호등 4행, 대응 확인 모달, 넓은 작업자 표, 3영역 캘린더, 빠른 질문 칩이 있는 현장 어시스턴트를 전체 화면 목록에 반영한다. 가스 실연동 raw와 데모 ppm, 지도 공급자 표기 차이는 그대로 보존·확인한다. ‘첫 화면은 반드시 이것’, ‘카드만 가능’ 같은 조사 제안은 사용자 선택 전 확정하지 않는다.

### 0.4 Lenovo OS 필기 실사용 결과 — 현재 주력 후보 기각

2026-09-12 Claude 전달: 한국어 팩 다운로드, 인식 언어 한국어 선택, 손글씨 ON, 실제 Tab Pen Plus 연결 후 태곤 님이 Chrome 주소창에 **`네이버 구글`**을 썼다. 입력 결과는 **`네ㅇ뻐7ㄱㅜ그리`**였다. 이 시험에서 자모 분리·다른 문자 혼입·오인식을 보였으므로 **플랜 A 중 Lenovo OS 위임은 현재 주력 입력 후보에서 기각**한다. 앱 코드나 Flutter 필드의 시험 결과는 아니다.

설정에는 선택 언어와 영어·숫자·구두점을 함께 인식한다는 안내가 있다. 이것이 오인식의 원인이라는 설명은 가설이다. 단일 문구로 엔진 전체의 한글 조합 능력이나 모든 OS 입력기를 일반화하지 않는다. Gboard는 별도 미검증 경로다.

- 권고 입력 순서: **정형 터치 선택/템플릿 → 변환 없는 사진 펜 주석 → 자유 문장이 필요할 때 STT/ML Kit 실측 후보.** 타이핑을 줄이는 방향이며 요구사항 14의 문장 변환 검증을 면제하지 않는다.
- 언어팩 다운로드 중 Wi-Fi가 없어 설정 화면으로 이동한 사실을 반영해 모델/네트워크 필요 상태를 사전에 알려준다. 인식 준비를 현장에서 조용히 실패시키지 않는다.
- 시험 과정에서 Lenovo HandwritingIme가 기본 입력기가 되었고 **Claude가 Gboard로 원복 완료했다고 보고했다**. 앱은 사용자 기본 IME를 존중하고 강제 변경하지 않으며 필요한 설정만 안내한다.
- OS의 왼쪽 아래 Easy Jot, 오른쪽 아래 빠른 노트, 화면 꺼짐 메모 제스처를 앱의 모서리 스와이프와 충돌하지 않게 검토한다.
- 연결된 펜 장치가 확인된 것과 필압·tilt·버튼 이벤트의 실제 앱 동작/지연이 검증된 것은 다르다.

## 2. 신규 ERD 기능 수용성 분석

### 2.1 적용 상태를 읽는 방법

ERD 앞부분은 001~060, 후반은 061 설계 확정 및 070·071·072 재현본 적용 결과가 섞여 있다. ‘전체 그림’의 생체 표 부재 설명도 과거 상태이며 ERD §17 이후 설계와 구분해야 한다. **문서상 설계 / 재현본 적용 / 캠퍼스 적용 / 라이브 연결** 네 상태를 따로 기록한다. 이번 분석은 DB 카탈로그 직접 검증이 아니다. 오래된 `danger_zone` 표·kind 설명은 기존 프로젝트의 2026-09-08 제거 결정과 충돌하므로 복원 근거로 사용하지 않는다.

### 2.2 증빙·일지: 펜을 담을 자리가 있는가

**수용하는 기능:** `media`는 현장에 귀속된 외부 스토리지 객체와 메타, `media_comment`는 작성자가 있는 텍스트 소통, `calendar_event`는 현장의 날짜·시각·라벨·메모를 표현한다. 070은 media의 `date_key/title/description`, 댓글 `updated_at`, 일정 `end_date_key/note/hazard_type`, 라벨 순서를 보강한다.

**확인되지 않은 계약:** 스트로크/레이어, 원본과 주석본의 관계, 좌표 기준·회전·해상도, 주석 버전·동시 편집·삭제 이력. `body`, `description`, `note`가 text라는 이유로 JSON을 밀어 넣으면 검증·권한·검색·표시 의미가 혼합된다. 펜 전용 구조가 이미 완성됐다고 볼 수 없다.

**설계 제안(미확정, DDL 아님):** 사진 주석은 `media`에 종속된 별도 주석과 리비전 자원으로 다룬다. 원본은 유지하고 서버가 현장·행위자·권한을 확인한다. 벡터/투명 레이어의 본체는 크기·조회 패턴에 따라 검증된 JSONB 또는 외부 객체로 선택하고, 미리보기 합성본은 별도 표현으로 둘 수 있다. 원본 ID·버전/해시·좌표계·주석 리비전이 필요하다. 현장·부모 media가 일치하도록 서버/DB 제약을 설계한다.

일정에 붙는 필기나 날짜 칸 자체 필기가 필수이면 별도 대상 관계를 설계한다. FK 없는 `target_type/target_id`만 두는 일반 첨부 구조를 자동 채택하지 않는다. 사진 주석 요구를 일정 필기로 임의 확대하거나 축소하지 않는다.

| 안 | 신규 도메인이 수용하는 부분 | 추가 계약·트레이드오프 |
|---|---|---|
| A 합성 이미지 | 이미지 자체는 media의 역할에 부합 | ‘어느 원본에 누가 주석했나’ 관계는 없음. 별도 media만 올리면 편집 의미가 소실 |
| B 벡터 | 증빙 원본과 편집 가능한 주석을 분리한다는 의도에 적합한 확장 후보 | 주석/리비전 구조·권한·좌표·감사 필요. 웹은 합성 미리보기부터 제공 가능 |
| C 투명 PNG | 외부 객체 저장 구조를 활용 가능 | 원본 연결·크기·회전·레이어 순서 규격 필요. 개별 선 편집 불가 |
| D 합성본+댓글 | media와 텍스트 소통 기능을 재사용 가능 | 댓글 링크는 참조 무결성·원자적 게시·버전 계약을 보장하지 않음 |

**현재 라이브에서의 가능성은 별도다.** A/D는 현 업로드·댓글 API 재사용 후보이며 B/C는 현재 서버에도 새 계약이 필요하다. 이것이 신규 스키마를 구 DB에 맞추자는 의미는 아니다.

070의 설명 수정은 본인/platform_admin, 댓글 수정은 본인, 댓글 삭제는 본인/platform_admin이라는 정책을 갖는다. 061의 미디어 삭제는 업로드 후 10분 창, 이후 제한이고 070 후속에 재확인되어 있다. 따라서 ‘편집=기존 미디어 삭제 후 재업로드’는 장기 설계로 적합하지 않다. 타인이 올린 사진 위에 자신의 주석을 새로 추가할 권한은 원본 수정권과 별도로 결정한다.

### 2.3 담당관·현장 scope: 누가 무엇을 볼 수 있는가

- 기본 역할은 `company.org_type` + `app_user.role`. 조달 담당관 `owner_officer`, 현장 관리자 `site_manager`, 작업자 `worker`, 운영자 `platform_admin`을 구분한다.
- 후보 현장과 실제 권한은 다르다. 담당관 후보는 조달 계약 범위에서 오고 실제 배정은 `site_member`; 현재 배정은 `left_on IS NULL` 기준이다. 계정 승인·활성 상태도 확인해야 한다.
- 서버가 인증한 신원으로 매 트랜잭션의 `app.actor_id/role/company/sites`를 채우고 RLS의 `can_access_site()`가 범위를 제한하는 설계다. 클라이언트가 보낸 현장 ID·역할을 그대로 세션 권한으로 쓰지 않는다. 연결 풀에서 이전 요청의 scope가 남지 않는지 검증한다.
- RLS 행 가시성과 동작/컬럼 수정 권한은 별개다. 트리거·전용 함수가 권한 상승·타 현장 쓰기·경보 종료 등을 제한한다. 0행 응답을 성공으로 표시하지 않도록 API 결과 계약이 필요하다.
- **061의 `is_site_officer`는 별도 부여 속성이며 `owner_officer`와 같은 말이 아니다.** 조달 확정 원장의 org_type·속성 조건을 생체 관제 권한으로 확대하지 않는다.
- **사용자 역할 확정:** 주 대상은 contractor/site_manager다. ERD §17의 본인+배정 현장 관리자 생체/위치 열람 의도에 맞춰 검증한다. owner_officer 생체 열람 제외의 미결 문구는 이 앱의 주 대상 결정 차단점에서 제거한다. 다만 실제 서버의 계정·배정·업무 권한은 여전히 검사하며 현장 배정만 있으면 모든 자료를 읽는 것으로 일반화하지 않는다.

따라서 로그인 후 화면 범위는 **유효한 계정/세션 → 현재 현장 배정 → 업무별 역할/속성 → 해당 데이터의 읽기/쓰기 정책** 순으로 결정한다. 최초 기관 계약 확인·직원 승인 두 층은 TOTP의 두 단계 인증과 다른 개념이다.

### 2.4 경보: 중복 방지와 오프라인 따라잡기

`kind`는 위험 종류, `detail_key`는 그 안의 항목, `source_kind/source_ref`는 판정 주체/원본이다. 앱은 서버 판정·단위·출처를 보존하며 `manual` 값이 있다는 이유로 담당관이 임의 경보를 생성해도 된다고 보지 않는다.

`dedup_key` UNIQUE는 **동일 사건을 중복 저장하지 않는** 기회를 준다. 구간 경보는 같은 행에 종료가 반영되고 재발은 새 행, 환경 주의→위험은 별도 행이 될 수 있다. 그러므로 **dedup_key는 정렬 커서가 아니고, 한 번 본 alert.id도 변경 사항을 다시 받아야 한다.**

ERD의 alert 데이터 사전에는 시작·종료·생성 시각이 있지만 모든 변경을 빠짐없이 이어 받을 증가 버전/변경 커서 계약이 확인되지 않는다. `started_at > 마지막 동기화`만 조회하면 과거 경보의 종료, 늦게 적재된 경보, 다른 담당관의 대응 확인을 놓칠 수 있다. `env_condition_state` 현재값만으로 끊긴 동안의 이력을 복원할 수도 없다.

**필요한 API 계약 후보:** (A) 서버가 확정한 변경 커서/상한점과 페이지를 제공하거나 (B) 한정 범위에서 진행·미대응 전체 스냅숏과 겹치는 최근 이력을 재대조한다. B는 보존·조회 구간 밖의 완전한 따라잡기를 보장하지 않는다. UUID를 시간 순서로 가정하지 않는다. 커서는 현장·계정·범위와 결합하고 모든 페이지를 로컬 트랜잭션에 반영한 뒤 확정한다. 만료 커서는 재초기화한다.

`alert_ack`의 `ack_by/ack_at/status/note`는 확인·조치 기록이며 `alert.ended_at` 위험 종료와 다르다. 화면에서 본 것/전송 예약/서버 대응 확인/위험 종료를 구분한다. 오프라인 대응 입력을 허용한다면 서버 재인가·중복·경보 변경 후 처리 계약이 추가된다. FCM은 새 자료를 확인하라는 신호로 사용하고 재접속 REST 동기화가 누락 복구를 담당한다.

### 2.5 세션: 폐기 문제는 해결되어 있는가

**스키마는 회수 표현을 수용하지만 실제 요청 차단은 미확인이다.** `app_session`은 user·client_kind·issued/expires/revoked_at·device_info를 갖고 토큰 평문을 저장하지 않는다. 그러나 ERD에 행이 있다는 사실은 API가 매 요청 이 행을 확인한다는 증거가 아니다. access 수용 시 세션 ID·사용자·용도·만료/회수·계정 상태를 확인할지, 캐시 유예를 둘지 서버 계약으로 정해야 한다.

현재 v2의 회전 refresh 토큰 해시·재사용 탐지와 신규 app_session의 구체적인 저장/검증 결합, TOTP 완료/등록 상태 전달은 이 ERD만으로 확정할 수 없다. 072 `app_device_login`은 워치 QR 로그인 코드이며 담당관 태블릿 세션이나 TOTP를 대신하지 않는다. 이 설계와 새 DB 실행 코드를 확인하는 작업은 전환 트랙 협의 사항이다.

### 2.6 주석·메모 감사 추적

`audit_log`는 앱/서버 업무 행위 기록, `record_change`는 선택한 핵심 테이블의 변경 이력이다. ERD는 후자를 돈·권한·임계 중심 일부 표에만 적용한다고 설명한다. **새 주석이나 모든 media_comment 수정이 자동으로 record_change에 남는다고 보장할 근거는 없다.** media 삭제 감사가 존재한다는 설명과 모든 변경 감사는 구별한다.

**권고:** 업무 증빙 주석의 게시·정정·삭제/철회는 감사 대상에 포함할지 결정하고, 포함 시 아래 최소 연결을 설계한다. 모든 펜 움직임을 audit_log에 쌓는 방식은 피한다.

| 구분 | 기존 감사 구조에 담을 정보 | 주석/리비전 계약에 추가할 후보 |
|---|---|---|
| 누가·어디서 | actor_id, site_id — 서버가 인증/인가 후 확정 | session 연계·기기 식별은 필요 범위 결정 |
| 무엇을 | action, target_table, target_id | 원본 media ID·버전/해시, 주석 ID·revision·상위 revision |
| 언제·어떤 요청 | occurred_at, trace_id | 작성 단말의 작성시각은 별도 참고값, 전송 작업 ID와 처리시각 구분 |
| 변경과 결과 | detail에 변경 요약·정정 사유·결과 | 산출 객체 식별자·해시·schemaVersion·좌표계 |

위 후보가 기존 컬럼으로 이미 존재한다는 뜻은 아니다. `trace_id`는 요청 추적이고 재시도 중복 방지 작업 ID와 목적이 다르다. 저장 성공과 감사 기록을 같은 업무 처리 경계에서 보장하고 외부 파일/DB 부분 실패를 회복한다. 스트로크 원문·사진·음성·토큰·연락처를 감사 JSON에 통째 복제하지 않는다. 보존·삭제·사고 증빙 분류는 도메인 정책을 먼저 정한다.

071의 `incident_report`는 수동 사고 원장이고 `incident_archive`는 경보 사본이다. 일반 주석을 자동으로 사고 기록으로 만들거나 두 원장에 임의 저장하지 않는다. 이 초안은 기존 보존 정책의 존재를 분석하며 법적 적정성 자체를 판정하지 않는다.

### 2.7 현재 라이브와 미래 전환을 동시에 만족시키는 경계

| 현재 라이브 작업 | 향후 전환 호환 조건 |
|---|---|
| 현재 API로 인증·조회·기록 기능을 구현하고 필요한 서버 확장을 별도 산정 | 태블릿은 HTTPS 업무 API만 사용하고 DB 연결·테이블명·SQL에 의존하지 않음 |
| API 응답을 앱의 안정된 업무 모델로 해석 | 식별자는 불투명 값, 촬영/서버 시각/캘린더 날짜·권한·오류 의미를 명시한 API 계약 |

**아직 ‘전환해도 절대 안 깨진다’고 증명한 것은 아니다.** 이를 인수 조건으로 둔다. 전환 트랙은 API 연속성·큐 처리·재로그인/캐시 재검증 절차·복구 방안을 제공해야 한다. 신규 스키마를 수정해 구 DB를 흉내 내도록 요구하지 않는다. DB 전환은 현재 앱 계획/HTML 및 현재 API 구현의 선행조건이 아니다.

## 3. 결정사항과 남은 쟁점 D-1~20

`태곤`은 제품·업무·비용·운영 조건을 선택하고, `구현팀`은 그 조건 안에서 Claude와 Codex가 방법을 결정한다. `공동`은 사용자 정책 선택 후 기술 결정을 뜻한다. **이 문서의 D 번호는 태블릿 계획 전용**이며 ERD §15의 D-1~5와 다르다.

### D-1. 주 업무와 첫 출시 범위

- **상태/선택지:** **사용자 제외 범위 확정.** 안전관리비·보조금 검증은 역할 불일치, ERP·주간보고는 현장 비직결로 제외. 나머지 현장 직결 포함 후보의 동작·우선순위는 화면 토론에서 확정한다.
- **트레이드오프:** 현장 문제 해결에 집중하고 사무 기능을 범위에서 뺀다. 포함 후보별 세부 읽기/쓰기·온라인 의존성은 여전히 다르다.
- **추가 정보:** 신호등·작업자·가스·AED·CCTV·기록·경보·어시스턴트의 실제 업무 동작, 안전뉴스 낮은 우선순위 반영. 제외 네 기능을 다시 묻지 않는다.
- **결정권/권고:** **태곤 확정**, Claude 전달 2026-09-12. ‘역할이 범위를 결정한다’를 기준으로 IA를 만든다. 제외 네 기능은 후속 필수 범위로 자동 이월하지 않는다.
- **차단/본문:** 전체 화면·API 목록·최초 인수 범위 / 1·3·4·10장.

### D-2. 주석 대상·저장 방식·재편집 수준

- **상태/선택지:** **사용자 지시로 화면 확인 후 선택 보류.** 사진 위/일정/날짜 필기 대상과 함께 **A 합성 / B 벡터 / D 합성+댓글**를 화면으로 비교한다. C는 조사 이력으로 남기되 이번 선택 후보에는 포함하지 않는다.
- **트레이드오프:** §2.2 비교표 참조. A/D는 빠른 게시, B는 편집·버전, C는 단순 합성에 유리. 로컬 편집·기기간 편집·웹 표시/편집은 각각 다른 보장이다.
- **추가 정보:** 원본 보호, 타인 사진에 주석, 동료 재편집, 정정 이력, 웹 편집 필요, 허용 서버 공수.
- **결정권/권고:** **태곤**이 화면을 보고 선택, **구현팀**이 데이터 규격. 공통 로컬 원본+벡터를 보관해 A/B/D 게시를 모두 가능하게 설계한다. 로컬 편집 가능성과 서버 공유 편집 보장은 구분한다.
- **차단/본문:** 주석 모델·서버 저장·캔버스·큐 / 9·11장.

### D-3. 단절 중 가능한 업무와 로컬 보관

- **상태/선택지:** **사용자 업무 범위 확정:** 조회 캐시+기록 초안+댓글·사진·일정 지연 전송。경보 대응 확인 예약은 미채택(감사 시각 문제). 캐시 대상/기간·용량은 남은 세부 정책이다.
- **트레이드오프:** 기록 연속성을 확보하되 재시도 중복·충돌·권한 재검증이 필수다. 새 생체/경보/CCTV 수신을 뜻하지 않는다. 대응 확인은 연결 후 실제 서버 결과로 완료 처리한다.
- **추가 정보:** 단절 시간·사진 규모·개인/공용·캐시 대상과 보존 기간, 댓글/일정 생성·수정·삭제 중 지연 전송 세부 범위.

- **차단/본문:** 음성 입력 인수·모델 채택 / 5·6·12장.

### D-11. 신규 촬영과 OCR 범위

- **선택지:** 기존 OCR 사진 조회·주석 / 태블릿 촬영+온디바이스 OCR / 촬영 후 온라인 OCR.
- **트레이드오프:** 조회만 하면 순찰 기록을 태블릿에서 끝내지 못할 수 있다. 온디바이스는 단절 대응에 좋지만 모델·한국어·숫자·촬영 품질 확인 필요. 온라인은 전송·서버·지연 증가.
- **추가 정보:** 실제 촬영 필수 여부, OCR 스탬프·날짜·좌표 계약, 원본 해상도/회전, GPS/OCR 실패 시 표시.
- **결정권/권고:** **태곤**이 업무 범위, **구현팀**이 방식. Digital Ink와 이미지 OCR을 구분하며 Lens 선탑재를 공개 API 보장으로 읽지 않는다.
- **차단/본문:** 촬영 동선·입력 모델·업로드 / 9장.

### D-12. 화면 구조와 한 손·펜 동작

- **선택지:** 업무 목록+상세 / 신호등·지도 중심 / 순찰 절차 중심. 창 너비에 따라 패널 전환, 좌/우 도구 위치 비교.
- **트레이드오프:** 정보량·도달성·필기 면적 충돌. 한 손으로 들고 반대손 펜을 쓰는 자세와 파지한 손 엄지로만 누르는 동작을 구분한다.
- **추가 정보:** 실제 담당관 파지·장갑·햇빛·빈번한 작업, 가로·세로·분할창·IME. OS 모서리 Easy Jot/빠른 노트와 앱 제스처 충돌, 기본 IME 강제 변경 여부. 관리자 계정의 실물 관찰만으로 담당관 일상 업무를 확정하지 않는다.
- **결정권/권고:** **태곤**이 Claude/Codex HTML 토론 시안을 선택. 실물의 상위 6+하위 4탭·3단 달력을 그대로 줄이지 않고 작업 동선으로 비교한다.
- **차단/본문:** UI/UX 상세 / 5장·UI/UX 설계서.

### D-13. 경보 수신·재접속 따라잡기·대응 확인

- **선택지:** 전경 갱신 / 푸시+REST 따라잡기 / 운영 알림 수단 병행. 따라잡기는 변경 커서 방식 또는 범위 제한 스냅숏 재대조. **경보 대응 확인 예약은 D-3에서 미채택**, 온라인 서버 완료만 제공한다.
- **트레이드오프:** 전경만은 앱 종료 중 수신을 못 한다. 푸시는 서버 발송·기기 등록·절전·권한·누락 복구 필요. 단절 중 새 경보를 보장하지 못함. 원장 dedup은 변경 동기화를 대체하지 않음.
- **추가 정보:** 주/보조 경보 단말, 요구 지연, 알림 보존·페이지·변경 시각, 다른 담당관 대응 반영。오프라인 확인 예약을 다시 선택지로 제시하지 않는다.
- **결정권/권고:** **공동**. 태곤은 수신 책임·대응 의미, 구현팀은 커서·재조회·중복 방지. FCM은 후보, 전체화면 알림/상시 서비스/진동을 필수로 자동 채택하지 않는다.
- **차단/본문:** 알림 서버·업무 완료·복귀 인수 / 8·10·11장.

### D-14. CCTV 연결 범위

- **선택지:** 현재 LAN 안 / 승인된 원격망·VPN·릴레이 / 현장별 접근 가능 채널.
- **트레이드오프:** LAN 유지는 변경이 작지만 이동 후 불가. 원격 확대는 앱 외 인프라·접근·비용 작업이다.
- **추가 정보:** 실제 현장망, 카메라별 프로토콜·TLS·티켓/헤더·만료, 동시 시청·대역폭.
- **결정권/권고:** **태곤**이 범위·투자, **구현팀**이 연결 설계. 불가 시 원인을 표시하고 무기한 로딩하지 않는다.
- **차단/본문:** 외부망 CCTV 약속 / 10장.

### D-15. 지도와 오프라인 현장 배경

- **선택지:** 온라인 지도+오프라인 목록/좌표 / 허용된 오프라인 지도·현장 도면 / 다른 지도 서비스.
- **트레이드오프:** 배경 없는 단절 화면은 정보 감소, 오프라인 타일은 사용조건·다운로드·갱신 검토 필요.
- **추가 정보:** 실물은 VWorld, 코드 요약은 Esri로 차이 있어 실제 공급자·출처·조건 확인. 현장 도면, 실내외 GPS 정확도·시각/오차.
- **결정권/권고:** **공동**. 키 없이 접근 가능함이 저장 허용을 뜻하지 않는다. 나침반 방향은 약속하지 않는다.
- **차단/본문:** 지도 서비스·오프라인 지도 인수 / 2·10장.

### D-16. 전화·문자·NFC 없는 기기의 업무 대안

- **선택지:** 연락처 표시/복사·공유 / 담당관 전화기 연계. AED는 조회만 또는 목록·QR 등 대체 식별 후 점검.
- **트레이드오프:** 전화기 연계는 운영 절차가 필요. NFC와 다른 식별을 동등한 점검 증빙으로 자동 취급할 수 없다.
- **추가 정보:** 현장 연락 절차·동행 전화기, 태블릿 AED 점검 필수 여부·장비 식별/완료 증빙.
- **결정권/권고:** **태곤**이 업무 방식, **구현팀**이 가능성 검증.
- **차단/본문:** SOS·AED 끝까지 완료 시나리오 / 10장.

### D-17. 서버 작업공간·시험 환경·운영 설치

- **선택지:** 분리된 개발/시험 환경 / 합의된 운영 시험 계정·현장·기능. 내부 설치·관리 배포 방식도 선택.
- **트레이드오프:** 분리 환경 준비 비용과 운영 직접 시험의 데이터 오염·복구·병렬 충돌 위험.
- **추가 정보:** 격리 경로·수정 담당·DB/스토리지 분리·배포 창·기기 수·서명키와 업데이트 책임.
- **결정권/권고:** **태곤**이 운영·비용, **구현팀**이 절차. 공유 safetymonitor는 계속 읽기 전용. 실제 변경 허용 경로를 먼저 정한다.
- **차단/본문:** 서버 쓰기·통합 시험·배포 / 12·14장. 문서/HTML은 차단하지 않음.

### D-18. 툴체인·의존성·앱 내부 구조

- **선택지:** 안정된 Flutter 기본 API 중심 / 필요한 검증 패키지 / 일부 Kotlin 네이티브. 로컬 관계형 저장은 Drift·직접 SQLite 등 후보.
- **트레이드오프:** 의존성 유지보수와 직접 구현 비용의 균형. 최신이라는 이유로 alpha·낮은 채택 패키지를 선택하지 않는다.
- **상태/추가 정보:** **툴체인 준비 해소:** Flutter 3.47.4 / Dart 3.13.3 / SDK 36.1.0, doctor Android toolchain 정상·TB373FU 인식(Claude 보고). cmdline-tools 설치 완료, 라이선스는 이미 승인 상태였다는 정정 반영. 새 앱의 실제 빌드·패키지 호환·실펜 성능 시험은 아직이다.
- **결정권/권고:** **구현팀**, 신규 설치 필요 목록은 **Claude 메인에게** 전달해 사용자 경로 이용. compile/target/min SDK는 별개다. Dart 분석의 한글 경로 문제도 실제 확인한다.
- **차단/본문:** 환경 준비 차단은 해소. P3 계획서 선행 및 필요한 의존성 선택은 유지 / 6장·P4.

### D-19. API 전환 호환과 미전송 데이터 연속성

- **선택지:** 동일 업무 API 계약 유지 / 버전 API 병행 / 명시적 앱 업데이트·큐 전환 절차를 동반한 변경.
- **트레이드오프:** 동일 계약 유지도 권한·ID·보존 의미가 변하면 별도 처리가 필요하다. 새 버전은 전환 기간 관리가 필요하고 강제 업데이트는 현장 단절 단말을 고려해야 한다.
- **추가 정보:** 전환 트랙의 API/식별자 안정성, 세션 재인증, 캐시 재검증, 미전송 작업 ID·부모 대상 연속성, 지원 기간.
- **결정권/권고:** **공동**. 태곤이 전환 운영 조건, 구현팀/전환 담당이 계약. 현재 태블릿이 두 DB에 직접 쓰거나 DB 이름으로 UI를 분기하는 구조는 피한다.
- **차단/본문:** 전환 호환 합격 판정 / 11·13장. 현재 라이브 앱 개발의 선행조건 아님.

### D-20. 주석 정정 이력·감사·보존

- **선택지:** 게시 행위 감사만 / 게시+정정 리비전 이력 / 증빙 분류별 보존·철회 규칙 추가.
- **트레이드오프:** 이력이 많으면 추적성은 높지만 파일/로그 저장과 보존 범위 증가. 모든 주석을 사고 보존물로 분류하면 목적이 달라진다.
- **추가 정보:** 업무 증빙의 정정·작성자·사유 필요, 삭제 창, 사고와의 연결, 타인 기록 편집 권한, 신규 감사 트리거/정책 적용 범위.
- **결정권/권고:** **태곤**이 업무 기록 기준, **구현팀/DB 담당**이 audit_log·리비전·record_change 적용 방식. §2.6 최소 연결을 기준으로 검토한다.
- **차단/본문:** 주석 데이터 수명·서버/DB 확장·감사 인수 / 9·11·12장.

### 4.1 앱만으로 가능한 일과 한계

| 초안·파일·큐 영속화 | 재시작 복구, 상태 표시 | 보존·계정 격리·파일/DB 부분 실패·공간 부족 |
| OS/온디바이스 인식 | 필기·음성·OCR 연결 | 모델·한국어·오프라인·라이선스 |
| 기존 앱 수용 API 소비 | v2로 캘린더·사진·댓글·챗 재사용 후보 | 라이브/역할/메서드별 실제 확인 |

앱만으로 관제 세션 전용 API 인가, 서버 중복 방지, 기기간 주석 공유, 원격 즉시 회수, 끊긴 인터넷의 새 경보 수신, 사설 CCTV의 외부망 접근을 보장할 수 없다.

### 4.2 서버·운영 작업 묶음

| 묶음 | 변경 범위 | 필수/조건부 |
|---|---|---|

| S-4 재시도·충돌 | 작업 ID·서버 중복 방지·파일/DB 실패 회복·수정 버전·부모/자식 전송 | **D-3 확정으로 필수.** 댓글·사진·일정 대상, 대응 확인은 제외. 기존 계약 확인 후 보강 |

### 5.1 중요한 완료 기준의 초안

- **조회:** 승인된 역할/현장만 보이며 미수신·오래된 값·데모·단위가 구분된다. 실패·0행을 정상 안전 상태로 바꾸지 않는다.
- **대응:** 보기/대응 확인/위험 종료의 의미가 분리되고 서버 결과 확인 전 완료로 표시하지 않는다.
- **기록:** 저장한 초안이 프로세스 종료 뒤 복구되고, 응답 유실 후 재시도에서도 선택한 계약에 따라 손실·중복 없이 게시된다.
- **펜:** 원본 확대/회전 후에도 위치가 맞으며 손바닥·펜 전환·취소로 원치 않는 선이나 기록 손실이 생기지 않는다.
- **한국어:** 실제 업무 문장을 이어 써 입력하고 오인식을 수정할 수 있다. 사전 준비/비행기모드/모델 없음 상태를 각각 시험한다. 지연·정확도 수치 기준은 사용자 시나리오와 P4 표본을 정한 뒤 확정한다.
- **재접속:** 놓친 생성 경보뿐 아니라 과거 경보의 종료·다른 사람의 대응 변화까지 합의한 조회 범위 내에서 반영한다.
- **회귀:** 기존 웹 로그인·워치 수집·사진 업로드 등 변경과 맞닿은 기존 경로가 계속 동작한다.
- **미래 호환:** 신규 backend의 독립 시험 환경에 같은 업무 계약을 적용하고 전환 전후 미전송 자료·권한·세션 동작을 검증한다.

## 부록 B. 소스 검토 위치와 유보

- `apps/dashboard-web/lib/app-jwt.ts:180`의 verifyAppJwt와 `:186`의 verifyMobileAccessJwt 포함관계를 확인했다.
- `app/api/mobile/v1/session/login/route.ts`에서 조건부 TOTP와 twoFactorPending 발급을 확인했다. `session/me`도 토큰 검증과 계정/세션 DB 확인을 구분해서 읽어야 한다.
- `app/api/app-media/route.ts`는 앱 JWT/별도 업로드 토큰을 받으며 랜덤 객체키와 행 ID를 만든다. 읽은 핸들러 범위에서는 client 작업 ID 중복 방지 계약을 찾지 못했으나 DB/트리거 전체 감사 결론은 아니다. 공유 업로드 토큰을 태블릿 인증 기본으로 채택하지 않는다.
- `app/api/calendar/media/route.ts`의 mediaWriteScope는 owner 또는 workerId 소유 범위를 확인한다. 조사 요약의 ‘admin·owner 수정’만으로 타인 사진 수정권을 정하지 않는다.
- 위 파일은 모두 기존 safetymonitor 트리에서 읽기만 했다. 코드 검토는 실제 라이브 호출 성공 증거가 아니다.

## 부록 C. 다음 개정 조건

사용자 선택을 받은 D는 선택·근거·일시·결정자를 기록한다. Claude와 서버 범위·실험 기준을 맞춘 뒤 최종 tab_plan 본문과 UI/UX 설계서 두 묶음을 작성한다. 이 파일 자체를 최종 계획서나 DB/앱 구현 승인으로 사용하지 않는다.
