## 서버는 이미 준비됐다 (계약)

`POST /api/app-media` 가 **잉크를 받는다.** 이 계약에 맞추는 것이 이번 일이다.

| | |
|---|---|
| Content-Type | **`application/json`** → 서버가 `media_type='ink'` 로 기록 |
| 필수 필드 | **`annotationOf`** = 원본 사진의 id. 없으면 **400** |
| 본문 | JSON. **최상위에 정수 `v`** 가 없으면 **400** |
| 크기 | **2,097,152 바이트** 초과 시 **413** |

## 1. 지우개를 **획 통째 삭제**로 바꾼다 (태곤 님 결정)

### 지금 무엇이 문제인가

```dart
// record_editor.dart:63
if (stroke.tool == InkTool.eraser) paint.blendMode = BlendMode.clear;
```

지우개가 **또 하나의 획으로 저장**되고, 그릴 때 덮어서 지운 것처럼 보이게 한다.
**원래 획 데이터는 그대로 남는다.** 합성 PNG 로 올릴 때는 결과 픽셀만 가서 드러나지 않았지만,
**벡터를 그대로 보내면 한 번도 게시할 생각이 없던 초안의 지운 낙서까지 서버로 간다.**

### 어떻게 바꾸나

**지우개가 닿은 획을 `strokes` 목록에서 제거한다. 지우개 획 자체는 저장하지 않는다.**

- 판정: 지우개 경로의 점들과 **각 획의 선분 사이 거리**가 지우개 반경 안이면 그 획을 지운다.
  좌표가 정규화(0~1)이므로 반경도 같은 기준으로 다뤄라 — `width` 주석이 *"원본 너비 대비 비율"* 이다.
- 드래그 한 번에 여러 획이 닿으면 **전부** 지운다.
- **`paintAnnotation` 에서 지우개 분기를 없애라.** `BlendMode.clear` 도, 그것 때문에 있던
  `saveLayer`/`restore`(`:54`·`:89`)도 **필요 없어진다.**
  ⚠ 다만 `saveLayer` 가 지우개 말고 다른 이유로도 쓰이는지 **먼저 확인하고** 지워라.
- `InkTool.eraser` 는 **도구로는 남긴다**(사용자가 고르는 도구다). 저장되는 획이 아닐 뿐이다.

### 대가를 알고 한다

**선의 일부만 지우기가 안 된다. 그은 선이 통째로 사라진다.**
태곤 님이 이 대가를 알고 고른 것이다. **"부분 지우기를 살리자"는 절충안을 만들지 마라.**

### 되돌리기

되돌리기(undo)가 이미 있으면 **획 삭제도 되돌려져야 한다.** 없으면 이번에 만들지 마라.
어느 쪽인지 **확인해서 보고해라.**

## 2. 잉크를 벡터로 올린다

### 지금

`record_editor.dart:361 save()` → `render()`(`:345`)가 **원본 해상도로 합성한 PNG** 를 만들어
`publish(png, annotationFields(origin))` 로 올린다. **사진을 PNG 로 저장하면 JPEG 원본보다 3~10배 크다.**

### 바꾼 뒤

**원본은 이미 따로 올라가 있다**(`capture_ocr.dart:415` 가 촬영 직후 JPEG 를 올린다).
그러니 편집기는 **잉크만** 올리면 된다.

```json
{ "v": 1, "strokes": [ { "tool": "pen", "color": 4278190080, "width": 0.004, "points": [[0.1,0.2,0.5], ...] } ] }
```

- `InkStroke.toJson()`(`:21`)이 이미 있다. **그걸 쓰고 형식을 새로 만들지 마라.**
- 최상위에 **`v: 1`** 을 넣어라. 서버가 요구한다.
- `render()` 는 **지우지 마라** — `SaveResult` 화면이 합성 이미지를 보여준다. **로컬 표시용으로 남긴다.**
  바뀌는 것은 **업로드 내용뿐**이다.

### 원본과 잇는다 — ★ 지금은 제목 문자열로만 이어져 있다

```dart
// record_origin.dart:20
'title': '현장 이미지 (주석) — 원본 … · ${original.id}',
```

원본 id 가 **제목 안에만** 있다. 구조적 연결이 아니다. 그래서 서버에 `annotation_of` 를 만들었다.

→ `annotationFields` 에 **`'annotationOf': original.id`** 를 더해라. 제목은 그대로 둔다(사람이 읽는 것).

### 업로드 경로

`publish(Uint8List bytes, Map<String, String> fields)` 시그니처(`field_contracts.dart:100`)를
**바꿔야 할 수도 있다** — 지금은 Content-Type 을 이미지로 고정할 가능성이 크다.
`live_gateway.dart` 의 구현을 **먼저 읽고**, 가장 적게 고치는 방법을 골라라.
계약(`field_contracts.dart`)을 바꾸면 `mock_gateway.dart` 도 짝을 맞춰야 한다.

## 3. 재편집 — **버전을 쌓는다. 덮어쓰지 않는다**

재편집은 이미 로컬에서 된다(`record_editor.dart:160-180` · `published:<원본id>` 별칭).
고친 잉크를 다시 올리면 **새 잉크본이 하나 더 생긴다.** 서버가 최신 하나만 목록에 노출하므로
**앱은 그냥 새로 올리면 된다.** 이전 것을 지우거나 덮어쓰는 요청을 보내지 마라.

⛔ **왜 덮어쓰면 안 되는지 코드 주석에 남겨라** (태곤 님 지시):

> 산업재해 기록이다. 현장에서 `균열 있음` 으로 적었다가 나중에 `이상 없음` 으로 고쳤을 때
> 이전 기록이 사라지면 **그 자체가 위변조다.** 원본 사진을 지키려고 잉크를 분리한 것과 같은 이유다.
> 이 프로젝트는 담당관 확정 원장에 이미 정정 사유 컬럼을 뒀다 — 같은 원칙이다.

## 4. 오프라인

원본이 이미 서버에 있으므로 **잉크는 오프라인에서도 그대로 편집·저장**할 수 있고,
연결되면 올라간다. 기존 오프라인 큐(`status` 가 `draft`/`uncertain`/`sending`/`sent` 로 도는 흐름)를
**그대로 쓰고 새 큐를 만들지 마라.**

⚠ 잉크 JSON 이 2MB 를 넘으면 서버가 413 을 준다. **한 버전의 직렬화 크기를 아무도 잰 적이 없다**
(`:272` 가 점 수 제한 없이 `points.add`). → **전송 전에 크기를 재고, 넘으면 사용자에게 말해라.**
조용히 실패하게 두지 마라. **실제로 몇 KB 가 나오는지 테스트에서 측정해 보고해라 — 그 수치가 필요하다.**
