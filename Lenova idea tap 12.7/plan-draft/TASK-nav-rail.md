# 작업 지시 9 — 하단 네비를 **왼쪽 레일**로 (`C-6`·`C-7`)

작성: Claude / 수신: 코덱스(astra) / 2026-09-12
선행: `TASK-bg-painter.md` 를 끝낸 뒤에 시작할 것.

## 태곤 님 지시

> *"지금 앱 보면 구조 내가 준 dashboard 이미지처럼 기능별로 구조화 좀 시켜"*

레퍼런스 골격은 `artifacts/design-constraints.md` **§9** 에 확정돼 있다. **먼저 읽어라.**
관련 규칙: `C-6`(왼쪽 레일) · `C-7`(접힘) · `V-6`(레일 불투명) · `T-1`(56dp) · `T-5`(간격 16dp)

## 이걸로 한 번에 풀리는 문제가 3개다

| 문제 | 어떻게 풀리나 |
|---|---|
| **세로 공간 부족** | 하단 네비가 사라져 **약 100dp 가 돌아온다.** `R-04` 캔버스가 화면 가로의 35% 로 작아진 원인이 이것이다 |
| **2층 탭(상위6+하위4)을 어떻게 접나** | **접지 않는다.** 레일에 묶음 제목으로 세로 전개한다. 가로 1385.4dp 면 자리가 있다 |
| **12.7인치를 못 쓴다** | 가로 화면에 맞는 배치가 된다 |

## 구조 — 이대로 만들어라

목적지는 **4개 확정**이다(`screen-inventory.md:19-32`). **늘리거나 줄이지 마라.**
영상은 목적지가 아니고(상세에서 진입), 챗봇은 태곤 님이 제거했다.

```
┌─ 레일 (불투명) ─┐┌─ 콘텐츠 ────────────────
│ 모의 현장    〈 ││  마지막 수신 2026-09-12 22:07:34
│ [모의 데이터]   ││ ─────────────────────────
│                 ││
│ 상황            ││
│  🏢 현장        ││       (선택한 목적지)
│  🔔 경보        ││
│                 ││
│ 기록            ││
│  📝 기록   ●    ││
│  📤 전송함      ││
│                 ││
│ ─────────────   ││
│ 👤 모의안전관리자││
│    로그아웃     ││
└─────────────────┘└─────────────────────────
```

### 묶음을 이렇게 나누는 이유 — 장식이 아니다

| 묶음 | 항목 | 성격 |
|---|---|---|
| **상황** | 현장 · 경보 | **서버에서 들어오는 것.** 보고 판단한다 |
| **기록** | 기록 · 전송함 | **내가 만들어 내보내는 것** |

담당관의 일이 실제로 이 둘이다 — **상황을 보고, 기록을 남긴다.**
⛔ **레퍼런스처럼 보이려고 빈 묶음을 만들지 마라.** 항목이 4개면 묶음은 2개다.

## 치수 — 레퍼런스에서 읽되 **우리 값으로 조정한 것**이다

21st 컴포넌트(`w-64`/`w-20`/`py-3`/`space-y-2`)에서 읽은 값이지만
**두 개는 우리 규칙을 어겨서 바꿨다.** 조정본을 써라.

| 항목 | 레퍼런스 | **쓸 값** | 근거 |
|---|---|---|---|
| 레일 펼침 | 256 | **256** | 가로 1385.4dp 의 18.5% |
| 레일 접힘 | 80 | **80** | 56dp 타깃이 들어간다 |
| 항목 높이 | 44 | **56** | ★ `T-1` — 44 는 위반이다 |
| 항목 세로 간격 | 8 | **16**(`vgGapTap`) | ★ `T-5` — 조준 편향 13.2dp 보다 커야 한다 |
| 항목 가로 패딩 | 16 | 16 | |
| 모서리 | 8 | 8 | |
| 아이콘 | 20 | 20 | |

**세로가 들어가는지 계산했다**: 가로 안전높이 865.9 − 헤더·푸터 약 160 = 약 700dp.
항목 4개 × 72(56+16) = 288 + 묶음 제목 2개 ≈ **350dp.** 넉넉하다.

### 선택 표시 — **색 하나로 말하지 마라**

레퍼런스는 **채움 + 오른쪽 흰 점** 두 가지로 말한다. 이게 규칙 `V-3` 이다(색맹·햇빛).
**점을 빼지 마라.**

⚠ **채움색은 레퍼런스의 파랑→보라 그라데이션을 쓰지 마라.**
**`VgColors.primary` `#0D74CE`** 를 쓴다 — 흰 글자 **4.77:1** 로 검증된 값이다.
보라 그라데이션은 대비를 안 쟀고 `V-9`(장식으로 계층 만들지 않기)와도 부딪힌다.

## ★ 접힘과 방향 — 여기가 까다롭다

### 접힘(`C-7`)

- 레일 헤더에 **접기 버튼**. 접히면 **아이콘만**(80dp), 묶음 제목과 글자는 사라진다
- **펜 캔버스(`R-04`)에 들어가면 자동으로 접어라.** 가로를 넓게 써야 한다
- 접힘 상태를 **기억해라**(같은 계정·기기 기준). 매번 다시 접게 하지 마라

### 방향 — ⚠ **고정할 수 없다**

Android 16 이라 **실행 중에 가로↔세로가 바뀐다.**

- **세로(865.9dp 폭)에서 256dp 레일은 30%다. 너무 넓다.**
  → **세로에서는 기본을 접힘(80dp)으로.**
- `MediaQuery` 로 갈라라. **레일 자체를 없애지는 마라** — 목적지 이동 경로가 사라지면 안 된다

| 지금 위치 | 어디로 |
|---|---|
| 현장명(`모의 현장`) | **레일 헤더** — 맥락이므로 항상 보인다 |
| `모의 데이터` 배지 | **레일 헤더**, 현장명 아래 |
| `로그아웃` | **레일 푸터**, 사용자 이름과 함께 |

⚠ **`마지막 수신` 을 레일로 옮기지 마라.** 이건 **보고 있는 데이터가 언제 것인지**를 말한다.
데이터 옆에 있어야 한다. 레일로 가면 무엇에 대한 시각인지 흐려진다.

### 접혔을 때 사라지는 정보를 **버리지 마라**

접히면 현장명·사용자 이름이 안 보인다.
→ **툴팁**(길게 누르면)으로 살려라. ⛔ 정보가 그냥 없어지면 안 된다.

## 비어 있는 목적지 — ★ "준비 중" 이라고 쓰지 마라

`현장`·`전송함`·`경보` 는 아직 화면이 없다. **왜 없는지가 다르다. 같은 문구를 쓰지 마라.**

| 목적지 | 문구 |
|---|---|
| **경보** | **`경보는 아직 이 앱에서 볼 수 없습니다. 관제 화면에서 확인해 주세요.`**<br>서버가 앱에 안 열려 있다(`alerts` 가 관제 전용). **우리가 안 만든 게 아니다** |
| 현장 · 전송함 | 다음 슬라이스. **만들 예정**이라고 써도 된다 |

⛔ **경보 건수를 0 으로 표시하지 마라.** 0건이 아니라 **모르는 것**이다(`N-1`).
