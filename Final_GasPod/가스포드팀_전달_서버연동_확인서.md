## 2. 확정된 데이터 계약 (펌웨어와 일치 확인)

가스포드 펌웨어가 보내는 JSON을 서버가 **그대로** 받도록 맞췄습니다. 필드별 대조.

| 필드 | 타입 | 펌웨어 전송 | 서버 수신 | 정합 |
|---|---|---|---|---|
| `device_id` | string | `"gaspod-01"` | 필수 (40자 컷) | ✅ |
| `o2` | number | 산소 % | 숫자 저장 | ✅ |
| `temp` | number | ℃ (BME280) | 숫자 저장 | ✅ |
| `humidity` | number | % | 숫자 저장 | ✅ |
| `pressure` | number | hPa | 숫자 저장 | ✅ |
| `mq7_raw` | number | CO 원시 ADC 0~4095 | 숫자 저장 | ✅ |
| `mq136_raw` | number | H₂S 원시 ADC 0~4095 | 숫자 저장 | ✅ |
| `vbat` | number | 배터리 V | 숫자 저장 | ✅ |
| `state` | string | `CLEAR`/`WARNING`/`DANGER` | **필수·이 3값만 허용** | ✅ |
| `acked` | bool | ACK 버튼 눌림 | true/false 저장 | ✅ |

- **서버 필수값** = `device_id` + `state`(세 값 중 하나). 나머지는 없어도 400 안 나고 0으로 채워집니다(부분 전송 안전).
- **응답** = 정상 `201 {"ok":true}` / JSON 깨짐 `400` / (해당 없음) 잘못된 인증 헤더 `401`.
- 서버가 수신 시각 `ts`(ISO)를 자동으로 붙입니다 — 펌웨어가 시각을 보낼 필요 없습니다.

> 결론. **펌웨어 페이로드를 한 글자도 바꾸지 않아도 됩니다.**

## 3. 인증 — 지금은 토큰 불필요

- 현재 서버는 **무토큰 전송을 그대로 수용**합니다(soft 모드, 기존 CCTV/생체 수집과 동일 정책).
- 펌웨어가 `Content-Type: application/json` 만 보내고 토큰을 안 보내는 현 상태로 **정상 수신**됩니다.
- (참고) 발표 후 보안 강화 시 공유 토큰(`X-App-Upload-Token` 헤더)을 요구할 수 있습니다. 그때 헤더 한 줄만 추가하면 되며, 필요해지면 값을 따로 전달드리겠습니다. 지금은 신경 쓰지 않으셔도 됩니다.

## 4. 하드웨어 측 검증 방법 (배포 후)

서버 재배포가 끝나면, 가스포드 쪽에서 아래 두 가지로 연동을 직접 확인할 수 있습니다.

**① 시리얼 로그** — 5초마다 찍히는 전송 로그의 코드가 바뀝니다.
```
[net] POST 404   ← 배포 전 (엔드포인트 없음)
[net] POST 201   ← 배포 후 = 서버 수신 성공 ✅
```

**② 서버에 실제로 쌓였는지 조회** — 브라우저나 curl로(누구나, 인증 불필요).
```
curl "https://vitalguard-dashboard-569797426568.asia-northeast3.run.app/api/gaspod/telemetry?n=5"
```
→ 최근 5건과 `latest`(가장 최근 1건)가 JSON으로 옵니다. 여기에 `device_id: "gaspod-01"` 과 방금 센서값이 보이면 연동 성공입니다.

**문제 시 빠른 진단**
| 시리얼 로그 | 의미 | 조치 |
|---|---|---|
| `[wifi] 실패` | WiFi 미접속 | 현장 WiFi AP·비번 확인 |
| `[net] POST 404` | 서버 미배포 | 서버 담당 배포 대기 |
| `[net] POST 400` | state 누락/오타 또는 JSON 깨짐 | `state` 값이 CLEAR/WARNING/DANGER 인지 |
| `[net] POST 201` | **정상** | 확인 끝 |

## 5. 펌웨어 검토 피드백

보내주신 `gaspod_v4.ino` 를 서버 관점에서 검토한 결과입니다. **수정 필요 없음**, 참고 사항만.

- ✅ **전송 주기·즉시 전송 설계 좋음** — 5초 주기 + 상태 변화/ACK 순간 즉시 POST. 서버·대시보드가 바로 반영하기에 이상적입니다.
- ✅ **`SERVER_URL` 정확** — 라이브 관제웹 주소·경로(`/api/gaspod/telemetry`)가 맞습니다.
- ✅ **오프라인 모드 안전** — WiFi 없으면 경보는 로컬에서 정상 동작하고 전송만 스킵. 좋은 처리입니다.
- ✅ **`state` 를 장치가 계산해서 보냄** — 서버가 임계값을 다시 판정하지 않고 그대로 신뢰합니다(AED와 동일 방식). 임계값 튜닝은 펌웨어 상수만 고치면 서버 무변경으로 반영됩니다.
- ℹ️ **`mq7_raw`/`mq136_raw` 는 무보정 원시값** — 명세대로 ppm 아님을 대시보드에도 "원시값"으로 표기하겠습니다. 클린에어 베이스라인 튜닝 후 임계값이 바뀌어도 서버는 손댈 것 없습니다.
- ℹ️ **`WiFiClientSecure setInsecure()`** — 인증서 미검증(HTTPS 평문 수용). 교육용 프로토타입 범위에서는 괜찮습니다(RPi AED 단말과 동일). 상용화 시 인증서 고정 검토 대상.
- ℹ️ **다중 단말 확장 시** — 지금은 `gaspod-01` 단일. 여러 대를 붙이면 `DEVICE_ID` 만 서로 다르게 주면 서버가 자동으로 구분해 쌓습니다(코드 변경 불필요).

## 6. 서버가 값을 다루는 방식 (대시보드 참고)

- **상태 색** = `state` 그대로 표시 (CLEAR=초록 · WARNING=노랑 · DANGER=빨강, AED 신호등과 동일).
- **ACK 표시** = `DANGER` 이면서 `acked=true` → "현장 확인됨" 배지(경보는 지속, 소리만 음소거된 상태).
- **연결 끊김** = 마지막 수신이 15초를 넘으면 대시보드가 "연결 끊김"으로 판정(5초 주기 기준 여유값).
- **저장** = **PostgreSQL 영구 저장 완료**(`gaspod_telemetry` 테이블) — POST 수신마다 DB에 누적·GET은 DB에서 최신·누적 건수 반환(인스턴스 재시작/스케일아웃 무관하게 보존, 메모리 링버퍼는 DB 장애 시 폴백). 관제웹 가스 탭 하단에 "가스 누적 N건·DB 영속"이 5초마다 갱신. 하드웨어·계약과 무관(펌웨어 무수정).
