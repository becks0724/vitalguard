# 1. 엔드포인트 구현 가이드 (팀원용)

## 요약
가스포드(ESP32)가 **5초마다** 아래 주소로 JSON을 POST합니다. 받는 라우트 하나만 추가하면 됩니다.

- **URL**: `POST https://vitalguard-dashboard-569797426568.asia-northeast3.run.app/api/gaspod/telemetry`
- **추가할 파일**: `기존_조달청모듈/safetymonitor/apps/dashboard-web/app/api/gaspod/telemetry/route.ts`
- 동봉된 `route.ts`를 그대로 복사하면 됩니다 (cctv/event와 같은 soft 토큰 수집 패턴 사용 — `lib/ingest-auth`의 `ingestAuthStatus` 재사용)

## 배포
평소 대시보드 배포 방식 그대로:
```
gcloud builds submit --config cloudbuild.dashboard.yaml .
# 이후 Cloud Run 서비스에 새 이미지 배포
```

## 검증 (배포 후)
```
# 수동 POST 테스트
curl -X POST https://vitalguard-dashboard-…run.app/api/gaspod/telemetry \
  -H 'Content-Type: application/json' \
  -d '{"device_id":"test","state":"CLEAR","o2":20.9}'
# → {"ok":true} (201)

# 최근 수신 데이터 확인
curl https://vitalguard-dashboard-…run.app/api/gaspod/telemetry?n=5
```
배포되면 가스포드 시리얼 로그의 `[net] POST 404` 가 `[net] POST 201` 로 바뀝니다.

## 참고
- 현재 저장은 메모리 링버퍼(최근 720건 ≈ 1시간)입니다. Cloud Run 인스턴스 재시작/스케일아웃 시 초기화 — 시연용으로 충분. 영구 저장 원하면 기존 `lib/db` 패턴으로 확장하세요.
- 상태값은 AED와 동일한 `CLEAR / WARNING / DANGER` 3단계입니다.
