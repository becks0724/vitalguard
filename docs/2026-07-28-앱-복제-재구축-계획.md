1. 소스가 완결돼 있다 — 누락 파일 없음, Git LFS 미사용

막는 것은 코드가 아니라 **계정·식별자·capability 뿐**이다.

### 2-1. 중요 — `.mlmodel` 미컴파일 진단은 오진이었다

`2026-07-27-앱-조율요청-iOS앱담당.md` ①번(최우선)과 `2026-07-26-낙상-오탐-수정요청-iOS앱담당.md` ②번의 진단은 **사실과 다르다.**

빌드 로그에 CoreML 컴파일이 3회 실제 실행된다.

```
coremlc compile .../Watch/ML/work_veto.mlmodel .../VitAlGuardWatch.app/
  --platform watchos --container bundle-resources
```

`--container bundle-resources` 가 곧 "Resources 빌드페이즈의 모델"을 뜻한다. Xcode는 Compile Sources 가 아니어도 `.mlmodel` 을 컴파일한다.

번들 확인 결과 시뮬레이터·실기기 **양쪽 모두** 원본 `.mlmodel` 은 없고 컴파일 산출물만 있다.

```
VitAlGuardWatch.app/
  impact.mlmodelc/    (coremldata.bin, metadata.json, model0/, model1/)
  recovery.mlmodelc/  (동일 구조)
  work_veto.mlmodelc/ (coremldata.bin, metadata.json, _B0000.DAT)
  ml_selfcheck.json  thresholds.json
```

`work_veto` 메타데이터도 유효하다 — `MLModelType_treeEnsembleClassifier`, 입력 `features` → 출력 `label`·`classProbability`. 따라서 `FallMLPipeline` 의 `Bundle.main.url(forResource:"work_veto", withExtension:"mlmodelc")` 는 **nil 이 아니다.**

**계획에 미치는 영향** — `project.yml` 의 `buildPhase: resources` 를 sources 로 옮기는 작업은 **불필요하다. 하지 않는다.**

**단서** — Xcode 26.6 기준이다. 기존 릴리스에 쓰인 Xcode 버전이 다르면 결과가 다를 여지는 남는다. 다만 `--container bundle-resources` 는 설계된 동작이라 가능성은 낮게 본다.
