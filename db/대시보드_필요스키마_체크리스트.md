# 최종본 대시보드 — 필요 스키마 체크리스트

> **대상**: `기존_조달청모듈/safetymonitor/apps/dashboard-web` (배포 Cloud Run 대시보드, main `b63492c`)
> **스키마 원천**: `lib/db.ts` `ensureSchema()` — **단일 출처**. DB = 캠퍼스 PostgreSQL `public`
> **자동화**: ensureSchema가 **`CREATE TABLE IF NOT EXISTS` + `ALTER ... ADD COLUMN IF NOT EXISTS`** 로 첫 쿼리 시 자동 생성·마이그레이션. → 본 체크리스트는 **배포 DB 검증/이관 확인용**(앱 1회 기동 시 대부분 자족).

## A. 필수 테이블 — `public` 11개

| ✔ | 테이블 | 용도 | PK / 핵심 제약 | 컬럼수 |

| ☐ | **worker_profile** | 직급/직책 오버라이드 | PK `worker_id` | 3 |
| ☐ | **weather_log** | 현장환경 스냅샷 | PK `id` · idx(recorded_at) | 16 |
| ☐ | **site_info_daily** | 현장정보(일별) | PK `id` · **UNIQUE(snapshot_date)** | 9 |

## B. `users` 신규 컬럼 — 마이그레이션 확인 ⚠️ (최근 커밋 추가분)

| ✔ | 컬럼 | 타입 | 비고 |
|---|---|---|---|
| ☐ | `carrier` | TEXT | 통신사 (회원가입 추가항목) |
| ☐ | `email_verified` | BOOLEAN NOT NULL DEFAULT false | 이메일 인증 여부 |
| ☐ | (기존) `company`·`phone`·`email`·`auth_provider`·`google_sub` | TEXT | B2B/Google 연동 |
| ☐ | `password_hash` | TEXT **NULL 허용** | Google 전용 계정은 null |

> 구버전 DB라도 앱 1회 기동 시 `ALTER ADD COLUMN IF NOT EXISTS`로 자동 보강. 수동 확인은 §D 쿼리.

## C. 현재 대시보드가 **요구하지 않는** 스키마 (선택/미사용)

| | 스키마 | 사유 |
|---|---|---|
| ⬜ | **SafeProcure** (`notice`·`safety_cost_check`·`risk_tag`·`risk_profile`·`safety_cost_rate`) | **안전관리비 검증 탭 = 계산 전용**(mock g2b + in-memory, DB 미참조). 영속 연동 시에만 `db/integrated/vitalguard_safeprocure_full.sql`의 safeprocure 파트로 추가 (단독본은 `feat/safeprocure-schema`의 `db/schema.sql`) |
| ⬜ | **T_\*** (T_COMPANY·T_WORKER·T_SENSING…) | aquerytool 정형 모델 — 이 대시보드 미사용(별도 모델/시드) |
| ⬜ | **캘린더 / companies / email-verify** | 별도 DB 테이블 **없음**(무상태 또는 `users` 컬럼 사용). 캘린더는 클라이언트/외부 |

## D. 라이브 검증 쿼리 (campus DB)

```sql
-- ① 필수 11테이블 존재 (기대: 11행)
SELECT tablename FROM pg_tables WHERE schemaname='public' AND tablename IN
 ('vital_samples','alerts','cctv_fall_events','fall_labels','worker_profile',
  'weather_log','site_info_daily','aed_inspections','weekly_report_inputs',
  'weekly_report_submissions','users')
ORDER BY tablename;

-- ② users 신규 컬럼 존재 (기대: carrier, email_verified 2행)
SELECT column_name FROM information_schema.columns
 WHERE table_schema='public' AND table_name='users'
   AND column_name IN ('carrier','email_verified');

-- ③ 각 테이블 컬럼수 대조(선택)
SELECT table_name, count(*) AS cols FROM information_schema.columns
 WHERE table_schema='public' GROUP BY table_name ORDER BY table_name;
```

## 결론
- 최종본 대시보드는 **`public` 11테이블만 요구** → 전부 `ensureSchema`가 자동 생성·마이그레이션.
- 구 배포 DB에서 **`users.carrier` / `users.email_verified`** 두 신규 컬럼만 확인하면 됨(없으면 앱 기동 시 자동 추가).
- **SafeProcure·T_\*** 는 현재 불필요(선택) — 안전관리비 검증을 **영속화**하기로 하면 그때 `safeprocure` 스키마 추가.
