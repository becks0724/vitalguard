# ADR — 안전조달 통합 결정 기록

> 클로드↔코덱스 토론·리뷰에서 확정된 통합 결정. 나중에 흔들리기 쉬운 판단을 고정.

## ADR-001 — 통합 위치 = 대시보드 상단 고정 섹션 (+ /safeprocure 병행)

- **맥락**: 사용자 요구 = "기존 대시보드에 안전조달을 추가". 후보 = (a) 작업자 캐러셀 페이지 추가, (b) WidgetCarousel 추가, (c) 대시보드 상단 고정 섹션, (d) 독립 라우트만.
- **결정**: **(c) 상단 고정 섹션** + 모듈 기본 **(d) `/safeprocure` 독립 라우트** 병행.
- **이유**:
  - 작업자 캐러셀은 `autoRotate=false` → 시연자가 안 넘기면 **심사위원이 안전조달을 못 본다**(공모전 데모에 치명적).
  - 그 캐러셀 도메인은 "착공 **후** 현장 관제" → "착공 **전** 조달 선별"을 넣으면 보조 위젯처럼 보임.
  - `WidgetCarousel`은 `pages.map` 전부 렌더 → 숨은 페이지도 mount되어 불필요 fetch/effect.
  - 상단 고정 섹션은 로그인 직후 첫 viewport에 조달 데이터 노출 → 동점 우선순위(공공데이터활용)에 유리.
- **결과**: DemoDashboard 수정 = import 1줄 + section 1개. 로그인 없는 데모는 `/safeprocure`로 커버.
- **고려(코덱스 리뷰)**: 상단 섹션이 기존 관제 첫 화면을 아래로 밀어낸다. 데모 임팩트가 과하면 **접힘 가능(collapsible) 상단 패널** 또는 공모전 데모 전용 표시로 조정 — 4단계 dev 육안 후 결정.

## ADR-002 — 드롭인 최소 침습 (기존 코드 수정은 기본 3곳)

- **맥락**: 모듈은 "기존 코드 무수정 드롭인" 설계지만, "대시보드에 추가" 요구는 기존 파일 수정을 불가피하게 함. CLAUDE.md는 surgical change·신규 패키지 사전합의를 요구.
- **결정**: 기존 파일 수정을 **기본 3곳**으로 한정 — `package.json`(테스트 글롭 1줄), `DemoDashboard.tsx`(섹션 1개), `.env.example`(키 템플릿). 신규 12파일은 전부 신규 경로 추가(충돌 0).
- **단(코덱스 리뷰 반영)**: 검증(typecheck/build/test/lint)이 **추가 수정을 요구하면**(예: 타입 export 누락, server-only 미선언, env 검증) 근거를 Runbook §변경기록에 남기고 허용한다 — **diff 개수보다 빌드 정확성이 우선**. "3곳"은 목표지 상한이 아니다.
- **이유**: diff가 요구사항에서 벗어나지 않게 + 롤백 단순화 + 기존 38세션 자산 보호.
- **결과**: 신규 npm 패키지 0(CLAUDE.md 무위반). 통합 diff = 추가 12 + 수정 3(±근거 있는 추가).

## ADR-003 — 검증 범위에 `next build` 포함, build를 마지막 게이트로

- **맥락**: 모듈은 Route Handler·`server-only`·dynamic fetch·env fallback을 쓴다. `tsc --noEmit`은 이들을 다 잡지 못한다.
- **결정**: 검증 = `typecheck → test → lint → build` (빠른 실패 우선, **build는 마지막 통과 게이트**).
- **이유**: 단위 테스트/린트 실패는 일찍 잡고, App Router 라우트/서버 컴포넌트/프리렌더 문제는 `next build`에서만 드러나므로 최종 관문으로.
- **결과**: build 통과 없이는 통합 완료로 보지 않음.

## ADR-004 — AI는 fetch 직접 호출 + 타임아웃·룰 폴백 (SDK 미추가)

- **맥락**: 위험작업 태깅에 LLM 사용. anthropic SDK 추가는 CLAUDE.md "신규 패키지 사전합의"에 걸림.
- **결정**: 모듈 기존 설계 유지 — `fetch("https://api.anthropic.com/...")` 직접 + `AbortSignal.timeout(8000)` + 키 없거나 실패 시 **규칙 기반 폴백**.
- **이유**: 의존성 0, 데모 중 API 지연이 패널을 멈추지 않음, 키 없이도 시연.
- **결과(코덱스 리뷰 반영)**: 신규 패키지 0 유지. API 안정성 보강은 모듈에 **이미 구현됨** — `anthropic-version` 헤더 고정, 모델명(`claude-haiku-4-5`) 고정, 응답 JSON 파싱 검증, evidence 원문 부분문자열 검증(환각 방지). 제출 전 **모델명 유효성만 재확인**.

## ADR-005 — 심사 내러티브 = 조달이 첫 입력인 "착공 전 관문" (구현된 것만 주장)

- **맥락**: "기존 안전모니터링 데모에 조달 모듈을 끼웠다"로 보이면 독창성·공공데이터활용 점수가 약해질 위험.
- **결정**: 동선을 **나라장터 공고 → 공고문 AI 위험태깅 → 산안비 예비검증 → 착공 전 리스크 리포트 → 착공 후 SafetyMonitor(본체) 연결**로 고정. 첫 viewport에서 `SafeProcure/안전조달` 강조.
- **단(코덱스 리뷰 반영)**: **KOSHA/기상청은 이번 12파일에 미구현**(import·fetch 없음)이므로 안전조달 자체 기능으로 주장하지 않는다. 본체의 기존 KOSHA/기상 연동은 "착공 후 관제 연결"로만 언급한다(idea.md §4 정직성). 소개서·데모에서 **구현 안 된 데이터원을 과장하지 않는다.**
- **이유**: 조달청 OpenAPI를 "또 하나의 위젯"이 아니라 **분석의 첫 입력**으로 보이게 + 과장 리스크 제거(표현 수위 = "의심/예비검증").
- **결과**: 통합 배치(ADR-001)·qa-report·소개서가 이 내러티브를 일관·정직하게 반영.
