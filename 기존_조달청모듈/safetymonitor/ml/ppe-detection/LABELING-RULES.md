| | 무엇에 | 무엇이 중요한가 |

⟹ **빼지도 넣지도 말고 `불확실` 태그를 단다.** 어느 쪽으로 쓸지는 나중에 정한다.

## 1. 절대 규칙 셋

### ① v6 예측을 보지 않는다
`geom-v6.json` 에 v6 의 검출 결과가 있다. **열지 않는다.**
v6 는 현장에서 `helmet` 을 하나도 못 봤다. 그 결과를 보고 그리면 **못 본 것이 정답에서도 빠져**
recall 이 부풀려진다. 자기 답안지로 자기를 채점하는 것이다.

### ② 애매한 것을 빼지 않는다
안 그리면 학습에서 그 자리가 **배경**이 된다. 「이 맨머리는 배경이다」를 가르치는 셈이다.
⟹ **그리고 `불확실` 을 단다.**

### ③ 박스 정의를 중간에 바꾸지 않는다
이 프로젝트에서 「같은 이름, 다른 박스 정의」 사고가 **두 번** 났다
(SH17 `head`↔`helmet` 78.2% 겹침 · `foot` 1.79% vs 507 17.70%).
헷갈리면 멈추고 이 문서를 고친 뒤 이어서 그린다. 기억으로 버티지 않는다.

## 2. `head` 와 `helmet` — 배타다. 그리고 둘 다 「머리 전체」다

**실측으로 확정했다**(추측 아님).

```
HHW train 3,000장 표본 — 안전모 최대 출처(41,450개)
  head    종횡비 w/h  중앙 0.618
  helmet  종횡비 w/h  중앙 0.641      ← 차이 3.7%. 같은 모양이다
  head ↔ helmet  IoU>0.3 겹침  2,921쌍 중 6건 = 0.21%

CSS train 2,500장 표본
  Hardhat ↔ NO-Hardhat  IoU>0.3 겹침  2,451쌍 중 0건 = 0.00%
```

⟹ **안전모만 따로 그리는 게 아니다.** 모자만 그렸다면 종횡비가 가로로 길어져 `head` 와
크게 달랐을 텐데 거의 같다. **박스 하나가 「머리」를 감싸고, 그 머리가 덮였으면 `helmet`,
맨머리면 `head`** 다.

```
맨머리        →  head    박스 하나
안전모 착용    →  helmet  박스 하나        ← head 를 같이 그리지 않는다
```

### 판정은 하나로 가른다 — 「안전모를 썼는가」

| 상황 | 클래스 |
|---|---|
| 안전모 착용 | `helmet` |
| 맨머리 | `head` |
| **야구모자 · 두건 · 비니 · 방한모** | **`head`** — 안전모가 아니다 |
| 안전모를 손에 들거나 바닥에 놓음 | 그리지 않는다 — 쓴 게 아니다 |
| 용접면 · 방진마스크만 | 머리 덮개 기준으로만 판단한다 |

⚠ 「안전모인지 아닌지」가 흔들리면 **더 흔한 쪽으로 찍지 말고 `불확실`** 을 단다.

## 3. 박스 경계

### `head` · `helmet`
```
위     머리(또는 안전모) 꼭대기
아래   턱 끝           ← 목은 넣지 않는다
좌우   귀 바깥 또는 안전모 챙 바깥, 둘 중 더 넓은 쪽
```
- 안전모 **챙이 튀어나오면 챙까지** 포함한다.
- 옆모습이면 코 끝·뒤통수까지가 좌우 경계다.
- 머리카락이 뻗쳐 있으면 **머리 윤곽까지만** — 흩날리는 끝은 뺀다.

### `safety_vest`
```
형광 조끼가 실제로 보이는 범위만 감싼다.
  어깨끈만 보이면  → 어깨끈이 보이는 범위
  팔·목은 넣지 않는다
```
CSS 실측 종횡비 중앙 **0.629**(세로가 김) — 상체 세로 박스다.
⚠ **일반 작업복·점퍼는 조끼가 아니다.** 형광 재질 + 반사띠가 기준이다.

### `shoes`
```
신발 한 짝마다 하나씩. 신발 외곽선만.
발목 위 바지는 넣지 않는다.
```
⚠ `no_safety_shoes` 클래스를 **쓰지 않는다.** 507 에서 그것은 신발이 아니라
「사람 박스 세로 0.71~1.00 · 너비 60%」의 **하반신 영역**이라 정의가 충돌한다.
안전화 여부는 **`신발` 태그**로 단다.

## 4. 그린다 / 안 그린다

| | 그린다 | 안 그린다 |
|---|---|---|
| **가림** | 절반 이상 보이면 그린다 | 거의 안 보이면 뺀다 |
| | 30~50% 보이면 그리고 `불확실` | |
| **화면 잘림** | 보이는 부분만 감싼다 | |
| **크기** | 확대 없이 「머리다」라고 보이면 그린다 | |
| | 확대해야 보이면 그리고 `불확실` | |
| **흐림** | 사람이라고 알아보면 그린다 | 형체를 못 가리면 뺀다 |
| **사진 속 사진·포스터** | | 안 그린다 — 실제 사람이 아니다 |
| **거울·유리 반사** | | 안 그린다 |
| **작업자냐 행인이냐** | **가리지 않는다 — 전원 그린다** | |

### ★ 작업자와 행인을 가르지 않는다 (2026-09-11 사용자 결정)

배치 도메인인 **산업현장 CCTV 에는 행인이 있을 수 없다.** 화면에 사람이 있으면 작업자다.
⟹ 라벨링에서도 「이 사람이 작업자인가」를 판단하지 않는다. **보이는 사람은 전부 그린다.**

```
판단이 필요 없다 = 라벨러마다·사진마다 흔들릴 자리가 하나 없어진다
운영 논리와도 맞는다 = violation_count = count(head) 가 그래서 성립한다
```

⚠ 이 35장은 CCTV 가 아니라 **보도에서 찍은 폰 사진**이라 실제로 행인이 많다. 규칙은 그대로
전원 라벨이지만, **여기서 나온 미착용 비율(9/110 ≈ 8%)을 현장 비율로 인용하면 안 된다** —
현장이면 전원 착용이 기준이다.

⚠ **최소 픽셀 기준을 지금 정하지 않는다.** 다 그린 뒤 크기 분포를 보고 채점 하한을 정한다.
지금 숫자를 박으면 그 숫자가 어디서 왔는지 모르는 자가 된다.

## 5. 태그

| 태그 | 언제 | 값 |
|---|---|---|
| **방향** | 모든 박스 | `정면` · `뒷면` · `불명` |
| **색** | `helmet` 만 | `초록` · `흰색` · `노랑` · `파랑` · `기타` |
| **신발** | `shoes` 만 | `안전화` · `일반화` · `불명` |
| **확신** | 모든 박스 | `확실` · `불확실` |

### 방향
얼굴이 보이면 `정면`, 뒤통수면 `뒷면`, **옆모습은 `불명`** 이다.
⚠ 애매한 각도를 억지로 가르지 않는다 — `불명` 은 실패가 아니라 정보다.

### 색 — 이게 `helmet` 0 의 원인을 가르는 유일한 재료다
현장에서 `helmet` 0 이 나온 원인 후보가 **초록 안전모 / 뒷모습 / 한국 현장 / 근접**이다.
색과 방향을 같이 달아야 나중에 어느 것이 지배적인지 가를 수 있다.

### 확신
크기·가림·흐림·안전모 판정 중 **하나라도 흔들리면** `불확실` 이다. 넉넉하게 단다.

