# 런북 — 연출 낙상 촬영 (2026-09-08 오후 예정)

준비 완료 · 사용자 결정으로 오후 진행. 근거 = `PPE-낙상-통합-리서치.md` §4 · 판정 기준은 `context-notes.md`
「낙상 판정 기준」 절.

## 0. 왜 필요한가 — 지금 절반만 검증됐다

```
확인됨    정상 상황에서 오탐 0        90초 · 사람-프레임 약 14,000 · 낙상 0 · 누움 0
미확인    진짜 넘어졌을 때 잡는가      ★ 시스템은 낙상을 한 번도 본 적이 없다
```

오탐 0 은 "아무것도 낙상이라 하지 않는 모델" 도 만족한다. **놓치지 않는지를 재지 않으면 오탐 0 은 아무것도
보증하지 않는다** — 6차 안전화 게이트가 음성 표본 없이 P 0.941 을 냈던 것과 같은 자리다.

## 1. 안전 — 이것부터

```
✅ 매트·이불 위에서만. 맨바닥 금지
✅ 감시자 1명이 옆에 서 있는다(촬영자와 별도)
✅ 뒤로 넘어지기 금지 — 머리 위험. 앞·옆·주저앉음만
✅ 한 사람이 연속 3회 이상 하지 않는다
❌ 실제 실신 재현·의식 잃은 척하며 머리 먼저 닿기 — 하지 않는다
```

연출 낙상은 실제 낙상과 다르다(사람이 손을 짚고 속도를 조절한다). **그 차이를 알고 쓴다** — 이 데이터로
"잡힌다"가 확인돼도 실제 낙상에서 잡힌다는 보장은 아니다. 반대로 여기서 못 잡으면 실제로도 못 잡는다.

## 2. 사전 확인 (5분) — ★ 이게 진짜 관문이다

**넘어질 자리가 카메라에 보여야 한다.** 지금 화각은 책상이 바닥을 대부분 가린다. 사람이 쓰러지면 책상 뒤로
사라져 **키포인트가 통째로 없어질 수 있다** — 그러면 낙상이 아니라 `판정불가` 가 된다.

```
1. 브라우저로 http://yahboom-1:8444/ 열기
2. 매트를 놓을 자리에 사람이 서 본다 → 화면에 골격이 그려지는지 확인
3. 그 자리에 쭈그려 앉아 본다 → 골격이 유지되는지 확인   ← 여기서 사라지면 자리를 옮긴다
4. 좌측 목록에서 그 사람의 "근거" 가 A 또는 A+ 인지 확인  ← B 면 엉덩이가 안 보이는 자리다
```

자리를 못 찾으면 카메라를 조금 더 낮추거나 각도를 트는 것이 촬영보다 먼저다.

## 3. 시행 목록 — 낙상 5종 · 반례 6종

각 3회. 한 시행은 **정지 3초 → 동작 → 바닥에서 5초 유지**(판정에 0.8초 지속이 필요하므로 충분히 머문다).

### 낙상 (매트 위)

| 라벨 | 동작 | 무엇을 보는가 |
|---|---|---|
| `넘어짐-앞` | 앞으로 엎어지듯 | 몸통이 앞으로 수평 · 표준 신호 |
| `넘어짐-옆` | 옆으로 쓰러지듯 | 옆에서 본 몸통 수평 — 각도 계산이 되는지 |
| `넘어짐-주저앉음` | 다리 풀리듯 그 자리에 주저앉아 눕기 | 낙하는 있으나 몸통이 늦게 수평 |
| `넘어짐-의자미끄러짐` | 의자에서 미끄러져 바닥으로 | **실제 현장에서 흔한 유형** |
| `넘어짐-천천히` | 실신하듯 천천히 무너짐 | ★ 낙하 속도가 낮아 **현 기준으로 놓칠 가능성이 높다.** 이걸 재야 임계를 안다 |

### 반례 — 더 중요하다

낙상이 아닌데 낙상처럼 보이는 것들이다. **여기서 오탐이 나오면 그게 곧 현장 오탐이다.**

| 라벨 | 동작 | 왜 위험한가 |
|---|---|---|
| `반례-물건줍기` | 바닥 물건을 줍고 3초 머물기 | ★ **09-09 08:11 실제로 터졌다**(몸통 76.2도·다리 13.1도). 현 기준에서 가장 위험 |
| `반례-책상숙이기` | 선 채로 책상 위로 상체 숙이기 | 위와 같은 신호 · 현장에서 훨씬 흔하다 |
| `반례-신발끈` | 쭈그려 앉아 끈 묶기 | 허벅지 수평 + 몸통 굽음 |
| `반례-빠르게앉기` | 의자에 털썩 앉기 | 낙하 속도가 임계를 넘을 수 있다 |
| `반례-책상아래` | 책상 밑으로 몸 숙이기 | 몸통 수평 + 하반신 가림 |
| `반례-스트레칭` | 서서 상체 굽히기 | 몸통 90° 인데 서 있다 |
| `반례-바닥에앉기` | 바닥에 다리 뻗고 앉기 | 누움과 가장 헷갈린다 |

## 4. 촬영 절차

★ **촬영 전에 기록율을 되돌린다.** 상시 기록은 `POSE_LOG_EVERY=3`(4 fps)으로 솎여 있는데,
낙상은 1초 안에 끝나는 사건이라 솎으면 결정적 프레임을 놓친다.

```
ssh jetson@yahboom-1 'pkill -f "^python3 gopro_ppe_edge"; sleep 2; cd ~/vg_edge_poc && \
  POSE_FALL=1 POSE_LOG=1 POSE_LOG_EVERY=1 nohup python3 gopro_ppe_edge.py > gopro_edge.log 2>&1 &'
```

재기동하면 라벨이 풀린다 — 첫 시행 전에 `/mark` 를 다시 건다.
확인 = `curl -s localhost:8444/health` 의 `pose_log.every` 가 1 인지.

```
시행마다
  1. curl -s "http://yahboom-1:8444/mark?label=넘어짐-앞"      ← 동작 직전
  2. 동작 (정지 3초 → 넘어짐 → 5초 유지)
  3. curl -s "http://yahboom-1:8444/mark"                      ← 라벨 해제
  4. 다음 시행

라벨은 해제할 때까지 이후 모든 기록에 붙는다. 해제를 잊으면 다음 시행이 앞 라벨로 섞인다.
브라우저 주소창으로 열어도 된다(GET). 한글은 그대로 쳐도 된다.
```

## 5. 채점

```
python3 ~/pose_log_stat.py ~/pose_log/pose-*.jsonl
```

두 표가 나온다.

- **라벨별 자세 판정 분포** — 어긋나는 칸이 오탐이고, 그 칸의 특징값 범위가 임계다.
- **★ 다리 각도 분포** — 진짜 낙상 5종에서 `lg`(다리) 값을 모은다. **이번 촬영의 최우선 수확이다.**
  09-09 08:11 에 첫 낙상 오탐이 났는데 몸통 76.2도(수평)에 다리 13.1도(수직)였다 — 선 채로 허리만
  굽힌 자세다. 「몸통 수평 + 다리 수직 = 굽힘, 낙상 아님」 조건을 넣고 싶은데, **진짜 낙상의 다리가
  몇 도인지 모르면 여백을 정할 수 없다.** 같은 자리에서 이미 두 번 틀렸으므로 재고 나서 고친다.
- **구간 단위 채점** — 시행 1회를 한 줄로 세어 `낙상 시행 N회 중 검출 M회 → recall` 과
  `반례 시행 N회 중 낙상 오탐 M회` 를 낸다. **낙상은 비율이 아니라 "그 한 번을 잡았나" 로 센다.**

### 판정선 (이번 촬영의 성공 기준)

```
낙상 recall   15회 중 12회 이상(0.80)      못 미치면 임계를 내린다(TORSO_DOWN·FALL_HOLD·DROP_RATE)
반례 오탐     18회 중 0회                   1회라도 나오면 그 반례의 특징값을 보고 조건을 더 건다
```

⚠ 둘을 동시에 만족하지 못하면 **임계를 타협하지 말고 조건을 늘린다**(예: 수평 + 낙하 + 이후 정지).
한 축을 깎아 다른 축을 맞추면 현장에서 둘 다 잃는다.

## 6. 예상 시간

```
사전 확인   5분
낙상 5종×3   15시행 × 약 40초 = 10분 (안전 확인 포함 15분)
반례 6종×3   18시행 × 약 30초 = 9분
채점·판단    10분
합계        약 40분 · 인원 2명(연기 1 · 감시 1) + 촬영 조작은 원격 가능
```

## 7. 촬영 뒤에 할 것

```
1. 채점표로 임계 조정 → 같은 로그로 재채점(재촬영 불필요 — 로그에 키포인트 원본이 있다)
2. 로그를 YOLO ML DATA/ 로 백업(젯슨에만 두지 않는다)
3. 잡히지 않은 시행의 특징값을 개별 확인 — 왜 못 잡았는지가 다음 설계다
4. 4단계(시간 분류기) 착수 여부 판단 — 규칙으로 판정선을 넘으면 학습은 미룬다
```

⚠ **로그는 젯슨 NVMe 에만 쌓인다**(약 2 MB/분). 촬영 뒤 반드시 맥으로 회수한다 —
`scp jetson@yahboom-1:'~/pose_log/*.jsonl' <백업경로>`.
