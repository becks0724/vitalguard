## A. 젯슨 자원 측정 — ✅ 2026-07-27 완료

Tailscale 원격으로 실측·정리까지 끝냈다. **다시 할 필요 없다.** 아래는 확정된 값이다.

### 실측 결과 (정리 후)

| 항목 | 값 | 비고 |
|---|---|---|
| 여유 RAM | **2.8GB** (정리 전 1.4GB) | 헤드리스 전환으로 확보 |
| 여유 디스크 | **50GB** (정리 전 9.0GB) | ollama 모델 40GB·apt 캐시 삭제 |
| 스왑 | **8GB 파일 + zram 1.8GB (구성 완료)** | 추가 작업 불필요 |
| DLA | **없음 확정** | GPU 오프로딩 불가 |
| 전력 모드 | **MAXN_SUPER** | 이미 최대, 조치 불필요 |
| JetPack | 6.2 (L4T R36.4.3), TensorRT 10.7.0 | |
| torch | 2.5.0a0+nv24.08, CUDA True | NVIDIA 빌드 |

### 실측 추론 성능 (PyTorch FP16 @960, 프록시 모델)

| 모델 | 속도 | 메모리 사용 |
|---|---|---|
| yolo11s | **14.8 fps** (68ms) | 약 1.1GB |
| yolo11m | **10.4 fps** (96ms) | 약 1.3GB |

**TensorRT 로 변환하면 이보다 빨라지고 메모리도 준다.** PyTorch eager 는 오버헤드 바운드라
젯슨에서 실제 속도를 대표하지 않는다.

### ★ 결론 — yolo26m 도 후보에 남는다

정리 전 여유 1.4GB 기준으로는 "엣지 추론 포기" 구간이었지만, **2.8GB 확보 후에는 m 도 들어간다.**
yolo11m 이 PyTorch 만으로도 10.4 fps 로 목표선(≥10 fps)을 이미 넘겼고, TensorRT 면 여유가 더 생긴다.

| 여유 RAM | 판단 | 현재 |
|---|---|---|
| 2.5GB 이상 | yolo26s @960 여유, **yolo26m @960 시도 가능** | **← 여기** |
| 1.5–2.5GB | yolo26s @640 또는 yolo26n | |
| 1.5GB 미만 | 엣지 추론 포기 → 현행 서버 추론 유지 | |

따라서 코랩에서 **s 와 m 을 모두 학습**해 정확도 차이를 보고, 젯슨 TensorRT 실측으로 최종 결정한다.

### 남은 변수 — 카메라 파이프라인 메모리

위 2.8GB 는 **카메라 파이프라인이 꺼진 상태**의 값이다. ROS2 Orbbec 드라이버 + 푸셔를 띄우면
그만큼 줄어든다. 엔진 변환 후 **파이프라인을 켠 상태에서 재측정**해야 최종 판정이 선다.

### 이때 함께 바뀐 것 (인지 필요)

- **데스크톱 GUI 없음** — 젯슨에 모니터를 직접 연결해도 화면이 안 나온다.
  되돌리려면 `sudo systemctl set-default graphical.target && sudo reboot`.
- **Rosmaster 자동시작 중단** — 로봇 컨트롤러(`rosmaster_main.py`)가 데스크톱 세션 자동시작이었다.
  CCTV 용도엔 불필요하지만, 필요하면 수동 실행하거나 systemd 서비스로 등록해야 한다.
- **ollama 비활성화** — 모델 40GB 삭제됨. Docker 이미지 30GB 는 보존했다.

## B. 코랩 진행

`ppe_yolo26_colab.ipynb` 를 코랩에서 열고 위에서부터 실행한다. 단계별 확인 포인트만 적는다.

### B-1. 런타임·설치 (2분)

`nvidia-smi` 출력에 GPU 가 보이는지 확인. 안 보이면 런타임 유형을 GPU 로 바꾼다.

### B-2. 설정 셀

**스모크런에서는 여기만 바꾼다.**

```python
MODEL  = 'yolo26s.pt'
IMGSZ  = 960
EPOCHS = 3          # ← 스모크런. 통과하면 150 으로
BATCH  = -1
```

`BATCH = -1` 은 VRAM 자동 산정이다. OOM 이 나면 `8` 로 고정한다.

### B-3. 데이터 다운로드 (10–20분)

`kaggle.json` 업로드 프롬프트가 뜨면 파일을 올린다. Roboflow 키는 입력창에 붙여넣는다.

### B-4. ★ 구조 확인 셀 — 여기서 반드시 멈춰서 눈으로 볼 것

**가장 잘 막히는 지점이다.** 데이터셋 배포본은 버전마다 디렉터리·클래스 순서가 다르다.

확인할 것 두 가지.

1. `find` 출력에 `images/` `labels/` 디렉터리가 실제로 있는가
2. `data.yaml` 의 `names` 순서가 노트북의 `SH17_NAMES` 와 맞는가

**어긋나면** 다음 셀의 `SOURCES` 에서 `root` 경로를 실제 경로로 고치고,
SH17 클래스 순서가 다르면 `SH17_NAMES` 를 출력값으로 교체한다.
매핑은 인덱스가 아니라 **이름**으로 하므로, 이름 목록만 맞으면 순서가 바뀌어도 안전하다.

### B-5. 리매핑 — 출력 판정

클래스별 인스턴스 수가 나온다. 이렇게 읽는다.

| 상황 | 의미 · 대응 |
|---|---|
| `person`·`helmet` 수천 이상 | 정상 |
| `shoes`·`gloves` **500 미만 ⚠️** | 소형 객체 학습이 어렵다. 결과 해석 시 감안 |
| 어떤 클래스 **0 ⚠️** | 매핑이 안 걸린 것. B-4 로 돌아가 이름 대조 |
| `제외` 수가 유지 수보다 많음 | 매핑 표에 걸린 클래스가 너무 적다. 이름 확인 |

### B-6. 학습

스모크런이 끝까지 통과하면 `EPOCHS = 150` 으로 올리고 설정 셀부터 다시 실행한다.

**세션이 끊기면** — 체크포인트는 Drive 에 있다. 설정 셀에서 `RESUME = True` 로 바꾸고 학습 셀만
다시 실행하면 이어서 간다. 코랩 무료는 12시간 제한과 유휴 끊김이 있으니 탭을 열어둔다.

시간이 부족하면 순서대로 줄인다 — `EPOCHS 150 → 80` → `IMGSZ 960 → 640`.
단 **`IMGSZ` 를 줄이면 안전화·장갑 recall 이 떨어진다**. 이 트레이드오프 자체가 측정 대상이므로
가능하면 960 을 유지하고 에포크를 줄이는 쪽이 낫다.

### B-7. 평가 — 무엇을 볼 것인가

전체 mAP 는 person 에 묻힌다. **클래스별 표에서 recall 이 낮은 순으로** 본다.

- `helmet`·`safety_vest` recall — 이게 실제 판정 성능이다
- `shoes`·`foot` — 원거리에서 잡히기는 하는지 (이번 단계 목표는 여기까지)
- `head` recall — 낮으면 안전모 미착용을 놓친다. **안전 관점에서 가장 중요**

### B-8. 착용 판정

`judge_ppe()` 가 person↔helmet/vest 를 묶는다. 결과가 이상하면 두 상수를 조정한다.

- `CONTAIN_MIN = 0.5` — 장비가 사람 박스에 얼마나 들어와야 귀속할지
- `HEAD_ZONE = 0.4` — 안전모로 인정할 상단 영역 비율

박스가 겹치는데 미착용으로 나오면 `CONTAIN_MIN` 을 낮추고, 엉뚱한 사람에게 붙으면 올린다.

### B-9. 기준선 비교

현행 `vyra_ppe.pt` 를 받아 같은 이미지에 태운다. 클래스 이름이 출력되면
`BASE_ALIAS` 표가 실제 이름과 맞는지 확인하고 필요 시 고친다.

**주의** — 위반 건수만으로는 우열을 못 가린다. 어느 쪽이 정답에 가까운지는 라벨과 대조해야 한다.
내일은 "두 모델이 얼마나 다르게 판정하는가"까지 보고, 정확도 결론은 그다음이다.

### B-10. 내보내기

`.pt` 가 Drive `vitalguard-ppe/weights/` 에 저장된다. 파일명에 `-nc` 가 붙었는지 확인한다.

## 막혔을 때

| 증상 | 원인 · 대응 |
|---|---|
| `CUDA out of memory` | `BATCH = -1` → `8` 또는 `4`. 그래도 나면 `IMGSZ = 640` |
| 리매핑 후 클래스 0건 | 클래스 이름 불일치. B-4 출력의 `names` 를 그대로 매핑 표에 반영 |
| `collect_pairs` 0장 | 경로에 `images` 디렉터리가 없는 레이아웃. `find` 출력 보고 `root` 수정 |
| 세션 끊김 | `RESUME = True` 후 학습 셀 재실행 |
| Kaggle 403 | `kaggle.json` 권한. `chmod 600` 확인, 데이터셋 페이지에서 규정 동의 필요할 수 있음 |
| Roboflow 버전 없음 | `version(27)` 숫자를 프로젝트 페이지의 최신 버전으로 교체 |
| `vyra_ppe.pt` 다운로드 실패 | HuggingFace 경로 변경 가능. `cctv-ai/README.md` 재취득 절차 참조 |
| 젯슨 SSH 막힘 | Tailscale check 만료. 출력 URL 브라우저 승인 1회 |
| 젯슨에서 `yolo26` 모델 로드 실패 | **설치된 ultralytics 8.3.59 는 yolo26 미지원.** 아래 함정 참조 |

### ★ 젯슨 ultralytics 업그레이드 함정 (엔진 변환 시점에 해당)

젯슨의 ultralytics 는 **8.3.59** 라 yolo26 을 모르는데, 그냥 올리면 CUDA 가 죽는다.

```bash
# ✗ 절대 이렇게 하지 말 것 — PyPI torch 가 NVIDIA 빌드 torch 를 덮어써 CUDA False 가 된다
pip install -U ultralytics

# ✓ 의존성 건드리지 않고 올린다
pip install -U --no-deps ultralytics
python3 -c "import torch,ultralytics; print(ultralytics.__version__, torch.__version__, torch.cuda.is_available())"
# → CUDA 가 True 인지 반드시 확인. False 면 torch 를 NVIDIA 빌드로 복구해야 한다.
```
