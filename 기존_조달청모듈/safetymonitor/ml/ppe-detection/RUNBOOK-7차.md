      - [ ] 부족하면 새로 찍는다. 세션 단위로 학습/홀드아웃 분리. 국내 야외 근접 · 자리 고정 후 자세 변경 · 세션 단위로 학습/홀드아웃 분리 · **조끼·신발까지 전 클래스 라벨**(LABELING-RULES). GDUT 는 보조(라이선스 확인 · vest·shoes 없으므로 helmet/head 만 기여하게 마스킹 없인 못 섞는다 → `exclude` 와 같은 이유로 **첫 실행엔 안 넣는다**). 지역난방공사 100장은 박싱 전 학습 불가.
- [ ] **A4 홀드아웃 재촬영(폰 가능 · 젯슨 불필요)** — ⚠ **ppe.sample 59장으로 대체할 수 없다.**
      59장과 시험지 35장은 같은 폴더로 온 같은 조직·지역이라 **약한 홀드아웃**이다. 다른 날·다른 자리가 필요하다. — 정면 쪼그림 20~30장 · 「앉아서 뒤돌아·가림 없이」 20~30장 · 둘 다 머리 45~70px · 다른 날·다른 자리. 낙상 촬영과 겸용 불가(이미지 미저장).
      중단. 쪼그림 수·크기 칸·세션 분리 중 하나라도 안 맞으면 `VEST_CROUCH` 를 안 채운다.
- [ ] **A5 `train_v7.py` 정렬** — epochs 30 · batch 64(v6 와 동일 · 09-12 반영 · 파일럿이 5 epoch·batch 16 으로도 helmet 을 크게 움직여 **자료 효과가 지배**한다는 정황이지만 v6 대비 A/B 는 같은 설정으로) · `a507_mode` None 이면 중단 · 클래스별 게이트 상수 · manifest(커밋 해시·스크립트 sha256·병합 data.yaml·labels.jpg).
- [ ] **A6 기준선 재현(젯슨 복귀 후)** — v5 엔진으로 38/133 · 439/470 을 같은 자로 다시 얻는다. 안 나오면 자가 바뀐 것이니 7차 채점 전에 멈춘다.
- [ ] ★ **A7 `.pt` ↔ 엔진 7.5%p 의 정체** — 같은 v5 가중치인데 `.pt` 0.211 · 엔진 0.286 이다(엔진이 더 나쁘다).
      ⛔ 「학습본이 달라서」는 **아니다** — v5 는 640 으로만 학습했고 엔진 이름의 960 은 **내보내기 해상도**다(09-12 확인).
      ⛔ **② 전처리 경로도 기각됐다(09-12 저녁 · 측정).** 푸셔의 `cv2.resize(960,540)` 선축소는
         젯슨 실제 입력 1920×1080 에서 **무동작**이다 — letterbox 배율이 어차피 0.5 라 최종 텐서가 **바이트 동일**하다
         (`np.array_equal True`). 세로 사진에 이 선축소를 흉내 내면 2.37배 왜곡이 생기는데 **젯슨엔 없는 입력**이다.
      남은 후보. ① **FP16**(`half=True`) ← 유력 · ③ 프레임 자체가 다름(맥 추출본 vs 라이브) · ④ NMS·후처리 구현 차.
      ⟹ 전처리가 같으므로 **같은 프레임만 쓰면 된다.** 특별한 통제가 필요 없다.
      **왜 필요한가.** 후보 선별을 `.pt` 로 하면 7.5%p 만큼 낙관 편향이 붙는다. 재현되면 상수 보정(`.pt` 게이트를 0.21 로),
      값이 들쭉날쭉하면 **`.pt` 선별 자체를 못 쓰고** 후보마다 엔진 변환이 필요하다([CCTV/ML] 지적).

### B. 학습을 돌려야 답할 것

- [ ] **B1 7차-A = v5 소스 그대로 + 새 야외 근접 안전모 자료(전 클래스 라벨) + 쪼그림 조끼** · 507 제외. 30 epoch · 640 · scale 0.8(변경 금지).
- [ ] **B2 클래스별 P-R 게이트** — 현장 35장(재현 gate) vest ≥ 0.835−δ · shoes ≥ 0.926−δ · E63 홀드아웃 helmet R ≥ 0.575−δ · head 검출 ≥ 0.934. **δ 는 학습 전에 고정**(제안 0.05). 하나라도 깨지면 망각이다 — 배포 후보 아님.
- [ ] **B3 운용 게이트(젯슨 엔진)** — 착용자 오경보 < 0.286 · 맨머리 ≥ 0.934. mAP 는 보고만 하고 판정에 안 쓴다.
- [ ] **B4 7차-B(선택 · ★ 우선순위 내려감)** — 507 을 `openvocab` 으로 넣은 실행.
      ⛔ **pilot2 가 5 epoch 짜리 답을 이미 줬다** — GDUT 위에 507 1,989장 + 의사라벨 1,032개를 얹어
      **목표 도메인(현장) helmet +0.030 뿐**이다. 망각도 그대로다. **507 은 지렛대가 아니다.**
      ⚠ 근거를 정확히 쓴다 — 「507 이 GDUT 를 해친다」가 **아니다**. GDUT holdout 에서는 helmet·head 둘 다 **오른다**
      (.908→.922 · .785→.804). **인도메인은 좋아지는데 배포 도메인이 안 움직이는 것**이고, 6차 `fair_eval` 이
      회귀를 희석했던 것과 같은 모양이다.
      ⟹ 되넣는다면 B1 이 통과하고 안전화 클래스가 필요해졌을 때의 일이다.
      ⚠ 이때 9클래스로 돌아가므로 `NAMES`·`expect`·엣지 `NAMES` 를 함께 되돌려야 한다.
- [ ] **B5 배포 후보 승격** — B2·B3 통과 + 누수 검사(세션 분리·manifest 대조) 통과. `/deploy` 는 사용자.

### 실패할 가장 그럴듯한 이유 넷

1. **국내 형태 격차가 GDUT 로 안 닫힌다** — v5 는 SH17 스톡 안전모 ~460박스를 봤는데도 현장 0/101 이었다. 국내 촬영 없이는 「야외 근접」까지만 닫힐 수 있다. → A3 국내 촬영을 GDUT 보다 앞에 둔다.
2. **helmet 을 얻고 오경보를 얻는다** — 파일럿이 현장 head R 도 0.111→0.667 로 올렸다. 착용자에 head 가 늘 수 있다. → A1 이 먼저다.
3. **507 의사라벨이 편향을 복제한다** — 교사가 그 도메인에서 약하면 무라벨 안전모가 다시 배경으로 남는다. → 교사는 개방어휘 + 사람 검수, 검수 표본에서 누락이 나오면 `openvocab` 폐기.
4. **개선처럼 보이는 누수·설정 차이** — 현장 35장은 86초 한 촬영 · epoch·batch 가 다르면 자료 효과가 아니다. → 세션 분리 · v6 와 같은 설정 · manifest 와 labels.jpg 대조.

### codex 1차 초안에서 고친 것 (2차 검토 기록)
- 「helmet 은 조건부 · 일반 자료 추가엔 근거 없음」 → **파일럿 이후 「올릴 수 있다」**. 초안은 파일럿 전에 쓰였다.
- 초안이 잡은 어긋남 넷은 전부 원문 확인 — `train_v7.py` 20/16 vs v6 30/64(수정) · a507 결정 플래그 부재(수정) · 이 런북의 v5 교사·크기 가설·scale 조정(⛔ 표시) · 「112박스」는 조끼·신발 보강 전 값이고 최종은 315.
- 초안에 없던 것 — 클래스별 P-R 게이트 · SH17 누수 0.4% 종결 · 홀드아웃 폰 촬영 · 개방어휘 교사(런북 대응 D 에 이미 있었다).

## Phase 1 — 라벨링 (사람 손이 필요한 유일한 구간)

### 클래스 4종만

```
person            사람 전신
head              맨머리 (안전모 미착용)
helmet            안전모 (착용 상태의 안전모 물체)
no_safety_shoes   안전화를 신지 않은 사람의 무릎~발 영역
```

**`no_safety_shoes` 박스를 507 정의와 맞춘다** — 사람 박스 기준 **세로 0.71~1.00**,
너비는 두 발을 포함해 사람 너비의 약 **60%**. 대조용 `AI HUB DATA/high/507_A03_vs_C06.jpg`.

> 정의가 어긋나면 채점이 무효가 된다. `helmet`↔`head` 78.2% 겹침으로 1차를 망친 것과
> 같은 종류의 사고다. **"같은 이름, 다른 박스 정의" 가 이 프로젝트에서 두 번 났다.**

### 함정 케이스의 정답

```
inhand    안전모를 손에 듦    → helmet 박스를 붙이지 않는다. head 로 라벨한다
onground  안전모를 바닥에 둠  → 같다. head 로 라벨한다
```

이 두 케이스가 **공개셋으로는 잴 수 없는 것**이고, 현장에서 흔하다.

### 도구

`labelImg` 또는 `CVAT` **로컬 실행**. Roboflow 무료 플랜은 데이터가 공개될 수 있어
상용 자산 라벨링에 부적합하다.

### ★★ 6차 모델의 예측을 초안 라벨로 쓰지 않는다

라벨링을 빨리 끝내려면 6차 모델을 돌려 예측을 초안으로 깔고 손보는 것이 편하다.
**시험지에서는 이것이 치명적이다.**

```
모델이 놓친 head 는 초안에도 없다 → 라벨러가 빈 화면을 보고 "없구나" 하고 넘긴다
→ 정답에서도 빠진다 → recall 이 부풀려진다
```

**모델이 자기 답안지를 채점하는 꼴이 된다.** `head`·`helmet`·`no_safety_shoes` 는
반드시 맨바닥에서 라벨한다.

`person` 만은 예외로 둘 수 있다 — 게이트 판정에 쓰이지 않고, COCO 사전학습(`yolo11x`)은
**우리 모델과 독립**이라 동조가 생기지 않는다. `no_safety_shoes` 박스를 507 정의
(사람 박스 세로 0.71~1.00)에 맞출 때 기준선으로 쓰면 오히려 정확해진다.

### 검수 — 내가 스크립트로 자동화한다

```
□ 클래스 인덱스가 통합 9클래스와 맞는가 (0 person · 1 head · 2 helmet · 8 no_safety_shoes)
□ 좌표가 0~1 범위인가 · 0×0 축퇴 박스가 없는가
□ no_safety_shoes 박스가 person 박스의 세로 0.71~1.00 구간에 있는가   ← 507 정의 대조
□ 파일명의 조합(helmet/bare · safety/sneakers)과 실제 라벨이 일치하는가 ← 라벨 오타 검출
□ head 와 helmet 이 같은 머리에 겹쳐 있지 않은가                      ← 배타 라벨 확인
```

**⑤번이 핵심이다** — 파일명이 정답표이므로 라벨과 어긋나면 채점 결과가 조용히 틀린다.

## Phase 3 — 7차 학습 (대응 C)

### 노트북에 넣을 변경 — 딱 한 가지

**a507 train 분할에 `helmet`·`shoes` 자동 라벨을 추가한다.**
person 자동 라벨 셀(6차 17번) 바로 뒤에 같은 구조의 셀을 하나 더 둔다.

```python
PPE_PSEUDO         = True
PPE_PSEUDO_WEIGHTS = DRIVE / 'weights' / 'ppe_yolo26s_640_v5_nc.pt'
PPE_PSEUDO_CLASSES = ('helmet', 'shoes')
PPE_PSEUDO_CONF    = 0.5
```

### 설계 근거 다섯 — 왜 이렇게만 하는가

**① 자동 라벨 모델은 v6 이 아니라 v5 다.** ⛔ 09-12: v5 도 507 흰 안전모를 13/110 밖에 못 잡아 교사 부적합 — 계획 v2 A2(`openvocab` + 사람 검수 또는 `exclude`).
v6 은 고치려는 그 회귀를 **자기가 갖고 있다**(홀드아웃 helmet R 0.465).
v6 으로 라벨하면 회귀를 그대로 증폭한다. v5 는 R 0.575 로 회귀 이전 기준선이고,
6차 사전 분석의 "13.4% / 26.3%" 실측도 v5 로 낸 값이라 근거와 도구가 일치한다.

**② 대상은 a507 뿐이다.**
E63·HHW 에도 라벨 없는 신발이 있지만 **그건 5차에도 있었고 회귀하지 않았다.**
측정된 원인만 건드린다.

**③ `hands`·`gloves` 는 넣지 않는다.**
507 실측 `hands 9.9%` 로 영향이 작고, 자기 증류는 넣을수록 v5 오검출이 함께 굳는다.
회귀가 확인된 둘만 고친다.

**④ `SOURCE_CLASSES['a507']` 은 `{'no_safety_shoes'}` 그대로 둔다.**
자동 라벨은 **학습에만** 기여하고 평가 대상은 건드리지 않는다.
평가 집합을 바꾸면 6차와의 전후 비교가 성립하지 않는다 —
5차에서 `SOURCE_CLASSES['sh17']` 에 head 를 넣었다가 P 가 0.136 떨어져
"모델이 나빠진 것" 처럼 보인 적이 있다.

**⑤ `A507_HOLDOUT_SITE = 'C06'` 을 유지한다.**
C06 은 로프작업이라 시험지로는 무효지만, **빼면 학습 데이터가 273장 늘어난다.**
그러면 helmet 개선이 대응 C 때문인지 데이터가 늘어서인지 갈리지 않는다.
**대응 C 의 효과만 재려면 나머지를 전부 고정해야 한다.**

### 안전장치 — 코드에 박을 것

```
assert  v5 가중치의 클래스 이름이 UNIFIED[:8] 과 일치        ← 인덱스 어긋나면 전부 오라벨
assert  추가된 라벨 > 0                                      ← 조용한 0 은 미달과 구별되지 않는다
마커     .ppe_pseudo_done (person 것과 별도)                  ← 재실행 시 박스 2배 방지
스킵     이미 해당 클래스 라벨이 있는 이미지                   ← 중복 박스 방지
집계     클래스별 추가 개수를 출력                            ← 13.4%/26.3% 실측과 대조
```

> `res.path` 에 의존하지 않고 **입력 리스트와 `zip` 으로 1:1 대응**시킨다.
> `ultralytics 8.4.112` 는 리스트 소스에서 `image0.jpg` 순번 이름을 돌려주고,
> 이 함정이 5차 평가를 조용히 무효화한 적이 있다.

### 판정 기준

```
□ E63 예약 홀드아웃  helmet R ≥ 0.575        ← 5차 수준 복원 (6차 0.465)
□ E63 예약 홀드아웃  head R ≥ 0.95 유지      (6차 0.964)
□ 안전모 미착용 알림 게이트 유지             (R ≥ 0.90 @ P ≥ 0.85)
□ fair_eval R_변화   -0.05 아래 클래스 0건
```

**helmet R 이 안 오르면 대응 C 가 원인이 아니었다는 뜻이다** — 그때는 507 편입 자체의
비용으로 보고 `A507_FRACTION` 축소를 검토한다.

### 왜 필요한가 — 실측

                     → helmet 은 '큰 안전모' 를 한 번도 본 적이 없다
⛔ 09-11~12: 크기 가설 기각(GDUT 20~40px 0.679 · CAM-03 imgsz 320~1280 전부 0). 원인은 **자료에 그 형태가 없는 것**(GDUT 5 epoch 로 0→0.614). 아래 실측 표는 기록으로만 남긴다.

**모델 용량·해상도·가림 탓이 아니다.** 셋 다 실측으로 기각했다.

```

         CAM-03 83% · 조경 근접 95% 검출     → 이미지가 어려운 게 아니다
```

**`head` 는 왜 살아남았나.** 5차에서 SH17 선별 부활로 도메인·크기 다양성을 얻었다.

소형**이다. 같은 모델 안에서 한쪽만 무너진 이유가 여기 있다.

### 데이터 — 장수보다 조합이다

```
① CAM-03 녹화        배포 도메인 그 자체. 엣지에 프레임 저장을 붙인다
② 자체 근접 촬영      실내·실외 · 안전모 색/부착물 변형
③ 기존 원거리 축      E63·HHW·CSS 는 그대로 둔다 (빼면 원거리가 무너진다)
```

⚠️ **같은 영상의 연속 프레임은 독립 표본이 아니다** — 507 에서 겪은 함정이고
ppe.sample 59장도 독립 장면은 30개였다. **초당 1장 이하로 솎고 조합으로 센다.**

```
목표 조합   인물 3명 이상 × 안전모 3종 이상(흰색/유색 · 부착물 유무) ×
            시간대 3(주간·석양·야간조명) × 거리 3(근접·중간·원거리)
            = 81 조합 · 조합당 최소 10장 → 800장 내외
```

### ★ 자동 라벨 교사를 개방어휘 모델로 둔다

```
helmet   개방어휘 자동 라벨(CAM-03 83% · 근접 95%) + 사람 검수
head     ✗ 자동 라벨 금지 — 개방어휘는 미착용을 개념적으로 못 잡고(0/40),
                          v5 자기 증류는 지금 고치려는 오탐을 그대로 굳힌다. 손 라벨.
```

**자기 증류 함정에 걸리지 않는다** — 개방어휘 모델은 우리 학습 계보 밖이라
`person` 자동 라벨에 COCO `yolo11x` 를 쓴 것과 같은 논리다(Phase 1 참조).

### 시험지 — 학습에 넣지 않는다

```
ppe.sample 59장(조경·실외·부착물 있는 안전모)      ← 실외 반례

```

### 설계 판단

**① C 와 한 번의 학습에 병합한다.** A100 1.6시간을 두 번 쓸 이유가 없다.

**② 증강(`scale`)을 건드리지 않는다.** 4차에서 스케일 증강으로 사고가 났고,

**③ 원거리 축을 빼지 않는다.** 근거리만 넣으면 E63 이 무너진다 — 5차에서 `head` 를
