## 확정

1. **원인 = `sh17_head_filter` 가 SH17 의 helmet 박스를 전부 버리는 것.**
   버린 자리에 아무 박스도 안 남아 그 화소가 **배경**이 된다 → 「착용 안전모는 아무것도 아니다」.
   pilot6→pilot8 은 **476개 박스만** 다른데 helmet 이 2 → 65.
2. **237장이 라벨 11,274개를 이긴다.** 「있다」는 한 곳을 가리키고, 「없다」는 사진 전체에 대고 한다.
3. **시작 가중치는 무죄** (pilot4 — COCO 출발도 90/100).
4. **E63 은 무죄** (pilot5 — 더하니 90→94). E63 에 무라벨 착용 안전모가 **있는 것은 사실**이지만
   제대로 붙인 helmet 4,359개가 그것을 압도한다. **기전이 있다 ≠ 그 기전이 지배한다.**
5. **처방은 「사진째 빼기」(77)가 「박스 살리기」(65)보다 안전모에 낫다.**
   박스 정의가 다르기 때문(SH17 = 모자만 · 우리·GDUT = 머리 영역 w/h 0.79).

## 미확정

- **어느 처방도 아직 게이트를 못 넘었다.** 7차는 재설계가 필요하다

### pilot11 (pilot10 + SH17 사진 제외) — 교환을 없앨 수 있는지 묻는다

`pilot10_data` 15,180장 + `pilot7_data` 의 `sh17_*` 3,726장 = **18,906장**.
SH17 분은 pilot7 것을 **그대로 가져온다** — 같은 규칙을 두 번 구현하면 갈린다.

구성 검사(전부 통과).
```
helmet 25,622  = pilot10 과 정확히 동일   → SH17 이 안전모를 0개 더했다 = 제외가 먹었다
shoes   2,007  = pilot7 과 정확히 동일    → 안전화 공급원이 그대로 들어왔다
8클래스 전부 pilot10+pilot7SH17 합과 등호 일치 · 빈 라벨 0
통제군  제외 전 pilot6 에 같은 검사 → 안전모 사진 237장 검출(검사 생존)
```
⚠ 기대값을 처음에 「shoes > 3000」으로 **추측**해 넣었다가 걸렸다(실제 2,007).
임계값을 낮추는 대신 **실측 합으로 등호 검사**로 바꿨다. 7차-D 조끼 하한과 같은 실수였다.

사전 판정 규칙(착수 전 고정).
