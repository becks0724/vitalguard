## 지금의 제약 — 원 계정 컴퓨팅 단위 소진

**원 계정(changwoojin)은 Colab 컴퓨팅 단위가 없다.** 따라서

```
학습 + 평가 전부   →  팀원 계정 (GPU 필요)
젯슨 변환 + 도메인 교차 검증 →  원 계정 (Colab 불필요 · 실물 하드웨어)
```

교대(릴레이)는 성립하지 않는다. **팀원 세션이 끊기면 팀원이 이어받아야 한다**
(원 계정은 단위가 없어 이어받을 수 없다).

### ⚠️ 그래서 가장 중요한 규칙

> **학습과 평가를 같은 세션에서 끝낸다.**

평가를 나중에 따로 하려면 `/content` 가 비워져 있어 **데이터셋을 30분 재구축**해야 하고
(4차에서 실제로 겪었다), 그 비용을 낼 수 있는 계정은 팀원뿐이다.
학습이 끝나면 그 세션에서 6~10장을 이어서 돌린다.

평가표는 **자동으로 공유 Drive 에 CSV 로 저장된다**(`results/<RUN_NAME>/`).
화면 캡처에 의존하지 않으므로 세션이 죽어도 숫자는 남는다.

| # | 누가 | 할 것 | 확인 |

| 3 | 팀원 | `공유 문서함` → `vitalguard-ppe` 우클릭 → **정리 → 바로가기 추가** → `내 드라이브` **루트** | 설정 셀이 `e63_yolo.tar 2.06 GB` 를 찍는다 |
| 4 | 팀원 | Kaggle API 토큰 **본인 것** + [SH17 페이지](https://www.kaggle.com/datasets/mugheesahmad/sh17-dataset-for-ppe-detection)에서 Download 1회 눌러 규정 동의 | 토큰은 채팅·문서에 붙여넣지 말 것 |

**3번이 핵심이다.** 바로가기가 `내 드라이브` 루트에 있어야
`/content/drive/MyDrive/vitalguard-ppe` 가 그대로 열린다. 빠지면 설정 셀에서 바로 드러난다.

> ⚠️ 팀원 내 드라이브에 `vitalguard-ppe` 라는 이름이 **이미 있으면** Drive 가 새 바로가기를
> **`vitalguard-ppe (1)`** 로 붙인다. 실제로 이 일이 일어났고, 이름으로 하드코딩된 경로는
> 조용히 엉뚱한 폴더를 가리켰다. 설정 셀의 `_resolve_drive()` 가 이름이 아니라
> **`datasets/e63_yolo.tar` 보유 여부**로 찾으므로 이제 자동 흡수된다
> (`★ 경로 자동 해결 — [...] 중 "..." 선택` 이 찍히면 그 경우다).

⚠️ **자격증명은 계정 귀속이라 공유하지 않는다.** 각자 발급해 `getpass` 로 입력한다.
⚠️ **팀원 계정으로 대신 로그인하지 말 것** — ToS 위반이고 계정 잠금 위험이 있다.
편집이 필요하면 팀원 본인이 자기 계정에서 실행한다.

## 2단계 — 학습 (팀원)

설정 셀에서 두 값만 확인하고 **맨 위부터 순서대로** 실행한다.

```python
RESUME = False        # 처음이므로 False
RUNNER = '<본인 이름>'
```

### 반드시 눈으로 확인할 4곳

**① 설정 셀**

```
GPU  : NVIDIA A100-SXM4-40GB · CPU 12코어 → batch 64 · workers 8
E63  : .../e63_yolo.tar → 2.06 GB
runs : .../runs (쓰기 가능)
```

`batch 16 · workers 2` = T4 다(5~6배 느려 완주 불가). `⚠️ 없음` = 준비 3번 미완.
**`runs 쓰기 불가` 가 나오면 뷰어 권한이다** — 여기서 잡지 않으면 4.8시간 뒤 체크포인트를 잃는다.

**② 리매핑 직후 — `★ SH17 필터` 줄이 있어야 한다**

```
   ★ SH17 필터 — 안전모 쓴 머리 제외 N · helmet 박스 제외 M
시퀀스 43개 중 12개를 홀드아웃으로 예약
★ helmet : head = 1 : 0.5~0.7
```

이 줄이 **없으면 5차의 절반이 동작하지 않은 것**이다(`SH17_HEAD_FILTER` 확인).
제외 건수가 0 이면 매핑이 빠진 것이니 멈춘다.

**③ 자동 라벨 셀 — `person` 총량이 늘어야 한다** (3~6분 소요)

```
person 자동 라벨 대상 N장 (train 분할·person 라벨 없는 것만 · conf 0.5)
★ person 라벨 M개 추가 · 이미지 K장
```

`대상 0장` 이면 `e63_*`·`hhw_*` 가 train 분할에 없다는 뜻이니 ② 출력을 다시 본다.

**④ 홀드아웃 누수 검사**

```
홀드아웃 시퀀스 12개 → 2,166장 (학습 미노출)
  누수 검사: 통과 (학습셋과 교집합 0)
```

`assert` 로 강제하므로 실패하면 자동으로 멈춘다.

그 다음 **잠금 셀 → 학습 셀**. 화면의 ETA 는 무시하고 **완료된 에포크 실측**으로만 판단한다.
모자이크는 마지막 10에포크에서 꺼지고, **그 구간에서 지표가 가장 많이 오른다** — 끝까지 돌린다.

### 끊겼을 때 (팀원이 직접 이어받는다)

```python
RESUME = True         # ★ 이것만 바꾼다
RUNNER = '<본인 이름>'   # 그대로
```

**다른 값은 절대 건드리지 말 것.** 특히 `SH17_FRACTION`·`HHW_FRACTION`·`SCALE`·`EPOCHS`·
`E63_HOLDOUT_SEQ_RATIO` 를 바꾸면 학습 데이터가 달라져 이어받기가 무의미해진다.

실행 순서는 **설치 → 설정 → 데이터 → 리매핑 → 자동 라벨 → 홀드아웃 → 잠금 → 학습**.
`/content` 가 세션마다 비워지므로 데이터를 다시 만들어야 한다.
해시가 결정적이라 **같은 12개 시퀀스·같은 분할이 재현된다** — 그래서 이어받기가 성립한다.

### 잠금 셀 출력별 대응

| 출력 | 뜻 | 할 것 |
|---|---|---|
| `잠금 기록 → 본인` 만 | 잠금 없음 | 진행 |
| `<본인> ... last.pt 갱신 N분 전` | 본인의 직전 런 | 진행(`RESUME=True` 확인) |
| `⛔ <상대> 의 세션이 살아있다` | 다른 사람이 가동 중 | **멈추고 확인.** 우회 금지 |
| `⚠️ last.pt 가 있는데 RESUME=False` | 0에포크부터 덮어쓴다 | `RESUME=True` 로 바꾸고 다시 |
| `⚠️ RESUME=True 인데 last.pt 가 없다` | 이어받을 것이 없다 | 첫 실행이면 `False` |

## 3단계 — 평가 (★ 같은 세션에서 이어서, 팀원)

학습이 끝나면 **런타임을 끊지 말고** 6~10장을 순서대로 돌린다.
전부 합쳐 10~20분이면 끝난다(학습 4.8시간에 비하면 무시할 만하다).

| 장 | 무엇 | 저장 파일 |
|---|---|---|
| 6 | 공정 평가 `fair_eval` | `1_fair_eval.csv` |
| 7 | 인도메인 2층 판정 | `2_bare_head_indomain.csv` |
| 8 | **예약 홀드아웃 1층·2층** | `3_holdout_perclass.csv` · `4_holdout_bare_head.csv` |
| 8 | 임계 스윕 (운영 conf 결정) | `5_holdout_sweep.csv` + `.txt` |
| 9 | 현행 `vyra_ppe.pt` 대비 비교 | `6_baseline_ours.csv` · `7_baseline_vyra.csv` |
| 10 | 가중치 내보내기 | `weights/ppe_yolo26s_640_v5_nc.pt` |

전부 `vitalguard-ppe/results/<RUN_NAME>/` 에 자동 저장된다 → **원 계정에서 그대로 읽는다.**
10장 셀이 마지막에 저장된 파일 목록을 찍는다. **비어 있으면 평가를 안 돌린 것이다.**

### 성공 기준

```
helmet R (공정 평가)      ≥ 0.70              ← 4차 0.433 의 복원이 5차의 존재 이유
홀드아웃 head P           ≥ 0.70              ← 4차 0.800 에서 회귀하면 실패
미착용 알림 (홀드아웃)     R ≥ 0.90 @ P ≥ 0.85 ← 4차 0.941 / 0.999 유지
```

### ⚠️ 홀드아웃 통과만으로 5차 성공이 아니다

**5차의 목적은 도메인 얽힘 해소이고, 그것은 홀드아웃으로 측정되지 않는다.**
예약 홀드아웃도 E63 도메인이라 4차의 결함을 가렸던 구조가 그대로다.

```
★ E63 밖에서 head 검출 > 0 건   ← 4단계(젯슨·GoPro)에서만 측정된다
```

홀드아웃 수치가 4차보다 좋아도 이게 0 이면 **5차는 목적을 달성하지 못한 것이다.**

## 4단계 — 판정·배포 (원 계정 · Colab 불필요)

컴퓨팅 단위가 없어도 이 단계는 전부 할 수 있다.

1. **가중치 수령** — 공유 Drive `weights/ppe_yolo26s_640_v5_nc.pt` 내려받기
   → `~/Documents/조달청-공모전 관련자료/YOLO ML DATA/` 에 보관
2. **평가 결과 확인** — 공유 Drive `results/<RUN_NAME>/*.csv` 7개
3. **젯슨 엔진 변환** — `.pt` 를 젯슨에 올려 변환.
   ⚠️ **변환 전 GUI 를 내릴 것**(`sudo systemctl isolate multi-user.target`) —
   켜두면 TensorRT 가 최적 커널을 건너뛰어 가짜 저성능이 나온다(실증됨)
4. **★ GoPro 도메인 교차 검증** — 5차 성패의 실질 판정.
   `gopro_ppe_edge.py` 로 사무실·비-CCTV 장면을 비추고 **`head` 검출이 0을 벗어나는지** 본다.
   `/health` 의 `head_size` 로 박스 크기가 학습 분포에 들어오는지도 함께 확인
5. **라이브 반영** — `PPE_ENGINE=<새 엔진>` 으로 릴레이 재기동 → CAM-03 즉시 반영
   ⚠️ cctv-ai 는 `--min-instances 1` = 상시 과금. 테스트 후 반드시 OFF

10장 셀이 3~5번의 명령을 그대로 출력해 준다.
