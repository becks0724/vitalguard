### ⚠ 이 과정에서 드러난 것 — 저장소본이 배포본보다 **뒤처져 있다**

`cctv-ai/edge/gopro_ppe_edge.py` 는 **저장소가 운영본의 정본이 아니다.**
[CCTV/ML]·[WATCH.APP] 두 세션이 **따로 재서 같은 값**이 나왔다.

```
명령   diff <저장소본> <젯슨본> | grep -c '^[<>]'
결과   저장소 1,157줄 · 젯슨 1,203줄 · diff 54줄
       저장소에만 4 · 젯슨에만 50        (4 + 50 = 54)
통제군 저장소↔저장소 = 0줄               ← 비교 자체가 살아 있나
```
⚠ 「64줄」로 적지 말 것 — hunk 헤더(`53,54c56,61`)까지 세면 나오는 값이고 내역(4+50)과 안 맞는다.

**운영 치명 항목 대조** (두 측정 완전 일치)

| | 젯슨 (구동본) | 저장소 |
|---|---|---|
| `ENGINE` | `ppe_yolo26s_rect544x960_v5_nc.engine` | `ppe_yolo26s_960_v5_nc.engine` |
| `PPE_IMGSZ` | `"544,960"` (직사각) | `960` (**정사각**) |
| `HEAD_CONF` | **0.30** + head 전용 문턱 필터 | **없음** |

**저장소본을 젯슨에 올리면 09-12 수리가 통째로 되돌아간다** — 직사각이 정사각이 되고
head 전용 문턱이 사라진다. 실측 = 정사각 오경보 .128 / 검출 .991 vs
직사각 **.048 / .9935** → **착용자 오경보 2.7배**.
이 레포엔 스냅샷이 계약 파일을 덮은 사고가 **3회** 있었고 같은 모양이다.

### ✅ 09-14 해소 — 동기화 완료

젯슨본을 저장소로 되반영했다(`cctv-ai/edge/gopro_ppe_edge.py`). **판단이 필요 없었다** —
`diff` 훅이 `c` 3 · `a` 4 · **`d` 0** 이라 **저장소 고유 내용이 하나도 없었고**,
「저장소에만 4줄」은 고유분이 아니라 **젯슨이 갱신한 줄의 구판**이었다.

```
덮은 뒤 젯슨과 diff        0줄        ← 일치
구판과 diff               54줄       ← 측정한 격차와 같다
통제군(잘라낸 사본)        d 훅 잡힘  ← 「d=0」이 검사 무력이 아님을 확인
py_compile · 이름 해석     통과
시크릿·디버그 잔여물 0 · 젯슨 절대경로 4 → 4 (증가 없음)
```

**⚠ 그런데 복사는 오늘 것만 고친다.** 다음에 또 갈라지고, 갈라진 걸 알아채는 장치가 없다.
이번에도 **배포하다 우연히** 발견했고 CI 는 젯슨에 닿을 수 없다. 그래서 아래를 같이 넣었다.
