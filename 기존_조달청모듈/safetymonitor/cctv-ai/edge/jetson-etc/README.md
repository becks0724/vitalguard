## ⛔ 막힌 곳 셋 — 다음 사람이 같은 데서 멈춘다

**① 예비기에 인터넷이 없다.** USB 장치모드로 붙이면 `192.168.55.1` 만 생기고
기본 경로가 기존 젯슨을 가리키지만 **그 너머로 안 나간다**(NAT 이 없다).
```

```

**② apt 가 잠겨 있다.** 갓 켠 우분투는 `packagekitd` 가 먼저 apt 를 잡는다.
```

해법  죽이지 말고 기다린다 — 실측 15초 만에 풀렸다
```

**③ Tailscale 은 기기마다 새로 가입해야 한다.** 계정은 공유하되 신원은 복제 불가다.
설치는 **키를 새로 받지 말고 기존 젯슨 것을 복사**한다(이미 신뢰하는 바이트 그대로).
```
sudo cat /usr/share/keyrings/tailscale-archive-keyring.gpg > /tmp/ts-key.gpg
scp /tmp/ts-key.gpg <예비기>:/tmp/      # 키
grep -rhs pkgs.tailscale.com /etc/apt/sources.list.d/ > /tmp/ts.list
scp /tmp/ts.list <예비기>:/tmp/          # 저장소
# 예비기에서
sudo cp /tmp/ts-key.gpg /usr/share/keyrings/tailscale-archive-keyring.gpg
sudo cp /tmp/ts.list /etc/apt/sources.list.d/tailscale.list
sudo apt-get update && sudo apt-get install -y tailscale
sudo tailscale up --hostname=<역할이 드러나는 이름>   # 링크가 뜨면 사람이 승인
#   2호기는 yahboom-ipcctv 로 지었다. 두 대 다 호스트명이 yahboom 이라 이름을 안 주면 구분이 안 된다
```
⚠ **이름을 지정한다.** 두 대 다 호스트명이 `yahboom` 이라 그냥 두면 `yahboom-2` 가 붙어
어느 쪽이 예비기인지 이름으로 구분이 안 된다.

# 2호기 개명 — 신원을 갈랐다 (2026-09-18)

같은 이미지로 구운 탓에 두 대가 이름도 고유번호도 같았다. **지금 당장 깨지는 것은 없었지만**
(avahi 실제 이름 충돌 0건 · 아무도 `.local` 로 접속하지 않아서다) 언젠가 깨진다.
예비기가 **꺼져 있을 때** 하는 것이 싸다.

```
            hostname          machine-id
기존        yahboom           5dbfb12414a3456d9014d88183e338b1
2호기 전    yahboom           5dbfb12414a3456d9014d88183e338b1   ← 같았다
2호기 후    yahboom-ipcctv    d9bcfd2566d84b2c83cad379c88dd48c
```

## ★ 접속 이름이 바뀌었다

```
ssh jetson@yahboom-ipcctv      ← 이것으로 쓴다 (옛 yahboom-spare 는 사라졌다)
ssh jetson@192.168.219.50      랜 주소는 그대로
```

## 바꾼 방법

```bash
sudo hostnamectl set-hostname yahboom-ipcctv
sudo sed -i 's/^\(127\.0\.1\.1[[:space:]]\+\)yahboom$/\1yahboom-ipcctv/' /etc/hosts   # 백업 /etc/hosts.bak-0918
sudo rm -f /etc/machine-id /var/lib/dbus/machine-id
sudo systemd-machine-id-setup            # 무작위로 새로 만든다(도구 설명 그대로)
sudo cp /etc/machine-id /var/lib/dbus/machine-id   # ⚠ 두 곳이 별도 파일이다. 한쪽만 바꾸면 어긋난다
sudo tailscale set --hostname=yahboom-ipcctv       # 재인증 없이 이름만 바뀐다
sudo shutdown -r now                                # machine-id 는 재부팅해야 완결된다
```

## ⛔ 여기서 한 번 헛디뎠다 — 「접속된다」를 「재부팅됐다」로 읽을 뻔했다

Tailscale 이름을 바꾸는 순간 **옛 이름이 즉시 사라져** 재부팅 명령이 전달되지 않았다.
그런데 새 이름으로는 접속이 되니 화면에는 「복귀」로 찍혔다. **내려간 적 없는 기계였다.**
```
판정은 「접속되나」가 아니라 uptime -s 가 바뀌었나로 한다
  10:58:04 → 12:48:24   이걸 봐야 재부팅이다
```
⟹ 이름을 바꾸는 작업은 **자기가 타고 있는 가지를 자르는 일**이다. 순서를 뒤집어
재부팅을 먼저 걸고 이름을 바꾸거나, 판정 지표를 미리 잡아 두어야 한다.
