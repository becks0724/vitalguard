# 구 4GB 모듈 병렬 사용 조사 — 젯슨 2호기

2026-09-08 · 아티팩트 https://claude.ai/code/artifact/cac8d616-12cf-4573-ba41-1ded1728808a
전제 = 09-07 8GB 모듈 교체 완료([RUNBOOK-8GB모듈교체.md](RUNBOOK-8GB모듈교체.md)) · 구 4GB(P3767-0004)는 정전기 봉투 보관.

## 0. 결론

**가능하다. 부족한 것은 저장장치 하나뿐이고 우분투 x86 호스트 없이 뜬다.**
단 4GB 는 8GB 의 **절반짜리 GPU**라 한 작업을 나눠 지는 용도가 아니라 다른 작업을 따로 맡기는 용도다.

```
부품        4GB 모듈 · P3768-0000 캐리어 · DC 어댑터 = 있음        저장장치 = 없음(유일한 공백)
OS          현 NVMe 통째 복제(경로 A · 권장)                       x86 플래시(경로 B)는 우분투 머신이 없어 반나절
용도 1순위  실험대·빌드 서버 (카메라 불필요 · 오늘 값을 낸다)
용도 2순위  두 번째 카메라 엣지 (서버 /cctv/ingest2 가 이미 열려 있음 · 서버 수정 0)
비용        NVMe 512GB ~5.5만 + USB M.2 케이스 ~1.5만  (2순위면 USB 웹캠 ~2~3만 추가)
```

## 0-1. ★ 8GB + 4GB = 12GB 는 되지 않는다 (사용자 질문 · 09-08)

**메모리는 합쳐지지 않는다.** 두 모듈은 각자 SoC·GPU·LPDDR5 를 가진 별개의 컴퓨터이고 메모리는 모듈 기판에
납땜돼 있다. 랜선으로 이으면 12GB 한 대가 아니라 **컴퓨터 두 대**가 된다. NVLink 급 통합 연결은 이 계열에 없다.

PCIe 엔드포인트 모드가 NVIDIA 문서에 있지만 해당 없음. ⓐ BAR 영역을 창처럼 여는 **MMIO 전송로**이지 통합
메모리가 아니고(포럼 실사용자도 20KB 중 4KB 만 전달되는 등 제약 보고) ⓑ `CONFIG_STRICT_DEVMEM` 해제 +
커널 재빌드가 필요하며 ⓒ **연결에 쓸 M.2 Key M 을 양쪽 다 부팅 디스크가 차지**한다(슬롯 1개).

**8GB 단독보다 빨라지지도 않는다 — 지금 하는 일에서는 오히려 느려진다.**

```
추론 한 번 (960 엔진 · 8GB 실측)              14.0 ms
그 한 장(960×540 BGR 1.5MB)을 1GbE 로 전송     12.4 ms   ← 아끼려는 시간과 맞먹는다
4GB 에서 같은 추론 (규격 기준 추정)            ~28 ms    ← 느린 쪽이 전체 속도를 정한다
```

JPEG 로 줄이면 선로 시간은 줄지만 인코드·디코드 CPU 로 옮겨 갈 뿐이다. 남는 것이 없다.

**애초에 지금 자원이 남는다.**

```
        유휴          라이브 송출 중     여유
메모리  1.1/7.6 GB    3.6/7.6 GB        4 GB
GPU     0%            39%               절반 이상
CPU     ~0            6코어 중 0.7      대부분
```

→ 12GB 가 있어도 쓸 데가 없다. 09-07 조사에서 확인한 진짜 병목은 **전송(푸시)과 추론 입력 해상도**였고 둘 다
코드로 해결했다. **두 대의 값어치는 "더 빠르게"가 아니라 "더 많이·따로"다**(§4 용도 순위).

## 1. 저장장치가 필수인 근거 (셋)

- **0004 는 eMMC·microSD 둘 다 없다.** 캐리어에 SD 를 붙이는 우회로도 없다 — NVIDIA 답변(ChrisB_NV)
  "Orin NX/Nano 는 SD 신호를 SO-DIMM 커넥터로 내보내지 않아 캐리어에서 SD 를 지원할 수 없다."
  개발자 키트의 SD 슬롯은 **0005 모듈 위**에 있다(SKU5 만 보유).
- **실측 대칭 증거** — 4GB 가 꽂혀 있던 기간 내내 이 시스템에 `mmcblk` 장치가 0개였다.
- **NVMe 공유 불가** — 이 캐리어의 M.2 Key M 슬롯은 실측 1개(`lspci` = C1 WiFi RTL8822CE · C4 NVMe · C8 Ethernet RTL8111).

부팅 매체는 NVMe 또는 USB 뿐이다. USB 부팅은 JetPack 6 이 `l4t_initrd_flash.sh --external-device sda1` 로
지원하지만, 현 기계 UEFI 부팅 목록에 USB 항목이 없어(**NVMe·PXE·HTTP·Shell 뿐**) 실물 확인 전에는 미검증이다.

## 2. 성능 — 4GB 는 절반이다

```
                4GB (0004)        8GB (0003/0005)
CUDA 코어       512               1024
텐서 코어       16                32
메모리 대역     34 GB/s           68 GB/s
AI 연산         20 TOPS           40 TOPS
CPU             6코어 A78AE       6코어 A78AE      ← 여기만 같다
Super 전원      10W·25W·MAXN      15W·25W·MAXN
640 엔진 추론   ~15 ms (추정)     6.71 ms (실측 09-07 무부하)
960 엔진 추론   ~28 ms (추정)     14.03 ms (실측)
```

⚠ **교체 전 4GB 실측 15.32 ms 는 DVFS 가 풀린 값이라 비교 근거가 못 된다.** 위 추정은 코어·대역 절반에서
나온 계산이고 2호기가 뜨는 날 `bench_engine.py` 로 실측해 갈아 끼운다.
→ **640 엔진이면 4GB 로도 12 fps 파이프라인이 무리 없다. 960 엔진은 여유가 얇다.**

## 3. OS 를 넣는 경로

### 경로 A — 현 NVMe 통째 복제 (권장 · 우분투 호스트 불필요)

USB M.2 외장 케이스에 새 NVMe → 가동 중인 젯슨에서 통째 복사 → 박스 캐리어로 이설.
**4GB 모듈 QSPI 가 이미 36.4.3** 이라 복제한 rootfs(36.4.3)와 정확히 맞는다.
(대조 — 현 8GB 는 QSPI 36.4.7 > rootfs 36.4.3 불일치라 캡슐 업데이트 금지 규칙이 붙어 있다. 4GB 는 해당 없음.)

복제 후 **켜기 전에** 바꿀 것.

```
hostname · /etc/machine-id · SSH host key · /var/lib/tailscale · 고정 IP
/etc/nvpmodel.conf 심링크   nvpmodel_p3767_0003_super.conf → nvpmodel_p3767_0004_super.conf   (4GB 표는 이미 시스템에 있다)
```

⚠ 켜져 있는 루트를 복사하는 것이라 복제 후 `e2fsck -f` 필요. 푸셔·서비스 정지 상태에서 한다.
⚠ **같은 256GB 라도 바이트 수가 다르면 dd 가 끝에서 실패한다** — 현 디스크 256,060,514,304 B(p1 159G · 실사용 103G).
   **512GB 를 사면 이 위험이 사라진다.**

### 경로 B — x86 우분투 + SDK Manager / BSP

4GB 전용 DTB·전원표가 정확히 들어간다. 문제는 **우분투 x86 머신이 없다는 것**(맥 불가 · MSI 는 윈도우 휴면).
MSI 에 우분투 라이브 USB 로 가능하나 반나절. WSL 은 리커버리 USB 통과가 불안정해 권하지 않는다.

## 4. 병렬 용도 순위

1. **실험대 겸 빌드 서버 (권장)** — 09-07 NVDEC 실측(CPU 0.42→0.13 코어)을 프로덕션에 못 넣은 이유가 정확히
   "시연 기계를 실험대로 겸할 수 없다"였다. 엔진 빌드 525초·파이프라인 교체·JetPack 시험을 밖에서 돌린다.
   **카메라 불필요 → 오늘 값을 낸다.**
2. **두 번째 카메라 엣지** — 서버가 이미 `/cctv/ingest2`(CAM-02 낙상 슬롯 · display-only · 서버 추론 없음)를
   열어 뒀다. **서버 수정 0.** USB 웹캠 하나면 관제웹 4분할 중 2칸이 실사가 된다. 640 엔진이면 4GB 로 충분.
3. **예비기** — 복제본이라 소프트웨어가 같다. 시연 당일 드라이브 이설만으로 인계. 1순위와 배타적이지 않다.
4. ✗ **추론 분산 — 하지 말 것.** 8GB 가 GR3D 39% 밖에 안 쓰고 4GB 는 절반 성능이라 느린 쪽이 속도를 정한다.
   남는 것은 네트워크 왕복뿐이다.

## 5. 함정

- 복제본을 신원 정리 없이 켜면 같은 호스트명·SSH 키 두 대가 서로를 밀어낸다(tailscale 포함).
- 전원표 심링크를 안 바꾸면 4GB 에 8GB 표가 걸린다 — 교체 전 실제로 그 상태였고 굴러가긴 했다.
- **GoPro 는 옮겨 갈 수 없다** — USB-net(172.23.102.51/52)이라 한 대 전용. 2호기 영상은 별도 카메라.
- 공유기 랜 포트 1개 추가 필요(젯슨 랜선 상시 유지가 운영 규칙).

## 6. 착수 순서

```
1. 구매        NVMe 512GB + USB M.2 외장 케이스(이후 백업용 재사용)
2. 복제        푸셔 정지 → 케이스 연결 → 통째 복사(40~60분) → e2fsck -f
3. 신원 정리   위 6가지
4. 조립·첫 부팅 박스 캐리어 + 4GB 모듈 + 어댑터 + 모니터 (8GB 교체 때와 같은 방식)
5. 실측        nvpmodel -m 2 · jetson_clocks · bench_engine.py 640/960 → §2 추정치 교체
6. 역할 부여   실험대 우선 · 카메라 확보 후 2순위로
```
