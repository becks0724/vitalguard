# CCTV 엣지 — 최종 구현 기록 (2026-10-07 장비 반납 시점)

젯슨 두 대가 카메라 영상을 받아 현장에서 보호구·자세를 판정하고, 1호기 게이트가 관제웹 브라우저에
영상과 통계를 직접 내보내는 구조였다. **2026-10-07 두 젯슨을 반납했다.** 관제웹 코드는 손대지 않고
그대로 둔다(10-07 결정). 이 문서는 반납 직전에 돌던 모습을 한곳에 적는다. 출처는 각 줄의 파일이다.

## 구조

```
CAM-03  GoPro HERO9 ─ USB 네트워크(UDP 8554) ─▶ 1호기 yahboom-1
                                                cctv-pusher  :8444   PPE·조끼·자세 추론
CAM-01  IP캠 TP-Link VIGI C340S ─ RTSP(사내 LAN) ─▶ 2호기 yahboom-ipcctv
                                                cctv-pusher-cam1 :8445   같은 추론
                                                        │ Tailscale
1호기  cctv-gate :8443 HTTPS (Tailscale 인증서) ◀──────────┘
        /cctv/stream{1,3} · /cctv/stats{1,3} · /cctv/connection{N}
        │ Tailscale 안에서만 닿는다
        ▼
관제웹 브라우저  CctvQuadView → CctvGateStream (일회용 서명 티켓)
```

두 젯슨은 서로 다른 공유기 뒤에 있어 게이트가 CAM-01 을 Tailscale 로 받았다
([edge/jetson-etc/dropins/cctv-gate--cam1.conf](edge/jetson-etc/dropins/cctv-gate--cam1.conf)).

| 기기 | 서비스 |
|---|---|
| 1호기 `yahboom-1` | `cctv-gate`(:8443) · `cctv-pusher`(CAM-03 · [edge/cctv-pusher.service](edge/cctv-pusher.service)) · `tailscale-cert-renew.timer` · `jetson-clocks` |
| 2호기 `yahboom-ipcctv` | `cctv-pusher-cam1`(CAM-01 · GPU 디코드 `CAP_BACKEND=gst`) · `jetson-clocks` |

## 젯슨 — 추론과 판정 ([edge/gopro_ppe_edge.py](edge/gopro_ppe_edge.py))

| 항목 | 값 |
|---|---|
| 입력 | 프레임을 960×540 으로 줄인다 |
| PPE | `ppe_yolo26s_rect544x960_v7e_nc.engine` · 입력 544×960 · conf 0.30 (76·79·135행) |
| 자세 | `yolo11s-pose.engine` · 640 · conf 0.25 · 기본 꺼짐, 유닛이 켠다 (144~151행) |
| 조끼 | `vest_yolo26s_rect544x960_v2.engine` · 2프레임마다 · 사람이 있을 때만 · **화면·통계에 내지 않는다**(09-25 결정) |
| 추론률 | `infer_fps` 12 · 30fps 입력의 100ms 칸에 맞춰 실제 약 10회/초 |
| 판정 구역 | `zone1.json`·`zone3.json` 둘 다 비움(09-21~) — 화면 전체가 판정 구역 |

위반 규칙은 **안전모 하나**다. 사람 상자 안에 안전모가 있으면 착용, 맨머리가 있으면 미착용이고
`violation_count` = 미착용 수다. 사람 밖의 머리는 `unknown_count` 로 따로 센다(586~638행).
`no_vest_count` 는 0 으로 고정이다(367행).

낙상은 규칙 기반 1단계다([edge/pose_fall.py](edge/pose_fall.py)). 몸통이 수직에서 65° 넘게 0.5초 이상
누워 있고 직전 2.5초 안에 초당 프레임 높이 0.15 이상 떨어졌으면 「낙상」, 아니면 「누움」이다.
**경보는 내지 않는다** — 오탐을 세기 위한 단계라 영상 위 표시에만 쓰고 `fall_count` 는 0 이다.

## 젯슨 — 게이트 ([edge/cctv_gate.py](edge/cctv_gate.py))

- 8443 HTTPS. 인증서는 Tailscale 발급(1호기 Tailscale 이름 · 10-27 만료 예정)이고 매일 04:20 에 갱신했다.
- 인증은 `Authorization` 헤더의 Ed25519 서명 티켓 하나다. 서명·시각·카메라·현장(`SITE-01`)·범위(읽기·제어)와
  일회용 id 를 본다. URL 에 티켓을 싣지 않는다.
- IP 당 분당 600회(drop-in) · 동시 스트림 8개 · CORS 는 관제웹 주소와 localhost 만 허용한다.
- 통계는 정해진 숫자 키와 엔진 이름만 내보낸다(`fall_count`·`pose_detail`·`gopro` 차단 · [edge/test_gate_whitelist.py](edge/test_gate_whitelist.py)).
- 상태 확인 `/health` 는 게이트가 아니라 각 푸셔(:8444·:8445)에 있다. 인증 없이 LAN·Tailscale 에서만 닿는다.

## 관제웹 ([CctvQuadView.tsx](../apps/dashboard-web/app/components/CctvQuadView.tsx) · [CctvGateStream.tsx](../apps/dashboard-web/app/components/CctvGateStream.tsx))

- 8칸이다. CAM-01·CAM-03 은 게이트, CAM-02 는 낙상 칸(종전 cctv-ai 경로), CAM-04~08 은 자리 표본이다.
- 게이트 주소는 **빌드 때 번들에 박힌다**(`NEXT_PUBLIC_CAM03_GATE_API`). 배포 스크립트 기본값이 1호기 Tailscale 주소이고
  `CAM03_GATE=` 로 비우면 끈다. 런타임 env 로는 못 바꾼다. 10-07 라이브 번들에 주소가 실린 것을 확인했다(17개 중 1개).
- 영상은 `<img>` 가 아니라 fetch + canvas 로 그린다. 응답이 JPEG 한 장이면 5초마다, 연속 스트림이면 프레임마다 그린다.
  티켓 만료 8초 전에 다시 잇는다.
- 티켓은 관제 로그인으로 `/api/cctv/ticket` 에서, 태블릿 앱은 `/api/app/admin/cctv-ticket`(앱 관리자 · 읽기 전용 · 분당 60회 · 감사 기록)에서 받는다.
  기본 수명 60초다.
- 통계는 팝업에만 나온다. 8초마다 받고 30초가 지나면 낡은 값으로 본다. 「작업자 N · 위반 N건」, 안전모가 있을 때만 준수율,
  조끼 칸은 「판정 범위 외」다.
- 게이트에 못 닿으면 503 은 「현장 장비 신호 없음」, 그 밖은 「연결 실패 · 재시도 중」(5초→30초)이다. cctv-ai 로 자동으로 넘어가지 않는다.
- 서버 중계 경로 `/api/cctv-gate/cctv/*`(ingest·stream·stats)는 배포돼 있지만 쓰지 않는다. 09-18 에 젯슨 쪽 송출(`CCTV_BASE`)을 비워 과금을 0 으로 만들었다.
- 이 동작을 지키는 시험: `lib/2026-09-09-cctv-gate-wiring.guard.test.ts` · `lib/2026-09-16-cctv-gate-server.guard.test.ts` ·
  `lib/2026-09-13-app-cctv-ticket.test.ts` · `lib/2026-09-09-cctv-ticket.guard.test.ts`. 배포 뒤 번들 확인은 `scripts/verify-cctv-bundle.sh`.

## 반납 (10-06 ~ 10-07)

- 두 기기에서 계정 로그인·CCTV 비밀 파일·서비스·Tailscale 을 지웠고, 10-07 오전 Tailscale 관리 콘솔에서 노드 3개를 지웠다.
- 모델 가중치는 드라이브에 남겼다 — [../ml/ppe-detection/MODELS.md](../ml/ppe-detection/MODELS.md). 엔진은 기기 전용이라 남기지 않았다.
- 지금 관제웹의 CAM-01·CAM-03 칸은 이름이 풀리지 않는 게이트를 가리킨다. 「연결 실패 · 재시도 중」이 나올 것으로 보이며, 화면을 열어 확인하지는 않았다.

## 되살리려면

1. 새 젯슨에 [edge/jetson-etc/README.md](edge/jetson-etc/README.md) 의 복원 절차를 따른다. 그 절차는 게이트·cam1 유닛과 일부 drop-in 만 다룬다.
   나중에 더한 tls·ratelimit·display·vest·decode drop-in, `zone1.json`, `edge/cctv-pusher.service`, `jetson-clocks`, 인증서 갱신 유닛은 따로 챙긴다.
2. 저장소에 없는 것 — 비밀 env 파일(`.cctv_ingest.env`·`.cam1_pusher.env`·`.cam1_rtsp_cred`) · Tailscale 신원 · 게이트 공개키 · TLS 인증서.
   ⚠ `CAM_SUFFIX=1` 은 비밀 env 파일에만 있다. 빠지면 CAM-01 푸셔가 조용히 CAM-03 처럼 돈다.
3. 엔진은 새 기기에서 `.pt` 로 다시 굽는다. 굽는 기기의 ultralytics 판본을 학습 환경과 맞춘다.
4. 관제웹은 새 게이트 주소를 `CAM03_GATE=<주소>` 로 주고 다시 배포한다. 브라우저가 그 주소에 닿아야 하고(Tailscale 안 또는 공개 주소),
   게이트 CORS 허용 목록에 관제웹 주소가 있어야 한다.
