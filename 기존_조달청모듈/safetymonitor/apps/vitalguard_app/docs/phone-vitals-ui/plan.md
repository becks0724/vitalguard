## 1. 왜 서버 왕복이 불필요한가

전제 확인이 필요했다. *"PoC 기반으로 워치 생체 데이터가 바로 서버로 가는 것으로 안다"* 는
질문이 있었는데 **실제 구조는 다르다.**

```
워치(HealthKit) ──WCSession──▶ 폰 네이티브 VitalPipeline ──HTTPS──▶ 서버
                                    ↑ 폰이 업로더다
```
워치는 서버로 직접 가지 않는다. 근거 = 08-15 실측에서 서버가 503 을 주자 **폰이** 큐를
1→41 건으로 쌓았고, 화면도 워치 `전송1525` ↔ 폰 `배치 #1526` 으로 동기다.

**`PhoneReceiver.swift:31` 이 워치 payload 의 `samples` 배열을 통째로 받는다.** 그 안에
`bpm`·`spo2`·`ae`·`hrv`·`rhr`·`whr`·`rr`·`stp`·`flt`·`pe`·`dl` 가 전부 들어 있고
이미 `spo2Count`·`aeSum` 을 세어 로그에 찍는다. **데이터는 폰 안에 있고 브리지가 심박만 통과시킨다.**

```
현재 EventChannel "vitalguard/stream"
  type:"hr"        → bpm · seq · channel          ← 여기만 열려 있다
  type:"pipeline"  → pending · uploadOk · authRejected
```

## 2. ★ 절대 어기면 안 되는 제약

**생체 데이터가 Dart 를 "경유" 하게 만들지 않는다.**

폰이 백그라운드면 iOS 는 `WCSessionDelegate` 는 깨우지만 **Flutter 엔진은 깨우지 않는다.**
수집·큐·업로드가 Dart 를 거치는 순간 **폰 강제종료·잠금 생존이 죽는다** — 이 앱의 존재 이유다
(Phase 1a 게이트에서 4분+ 무중단으로 실증한 바로 그 성질).

```
유지   네이티브가 큐·업로드를 전담 → Flutter 에는 표시용 복사본만 밀어준다 (현 구조)
금지   Flutter 가 받아서 저장·업로드에 관여
```
⟹ 이번 작업은 **`VitalBridge.emit` 의 payload 를 넓히는 것**이지 경로를 바꾸는 것이 아니다.

| 항목 | 넣나 | 근거 |

| 심박 + 측정 경과 | ✅ 이미 있음 | — |

| 걸음 · 오른층 | ✅ | 구간 증분 |
| 전송 상태(배치·큐·인증) | ✅ 이미 있음 | — |
| **활동에너지** | ❌ **뺀다** | 2026-08-15 확정 — **4배 과대**(정지 상태 288 kcal/시간). 그대로 띄우면 이상한 값을 사용자에게 보여주게 된다. [heat-activity-axis](../../../dashboard-web/docs/heat-activity-axis/checklist.md) 정리 후 재검토 |

⚠ **워치와 폰의 숫자 의미가 다른 것에 주의.** 워치 `활동 539.3 kcal` 는 **세션 누적**이고
서버로 가는 `ae` 는 **5초 증분**이다. 같은 라벨로 띄우면 헷갈린다 — 표시할 때 무엇을
보여주는지 라벨에 명시한다.

## 6. 착수 전 결정 사항 — 2026-08-16 확정

- [x] **UI/UX 형태 = 카드 나열.** 폰은 화면이 넓고 심박 카드가 이미 그 형태다.
- [x] **갱신 주기 = 값이 바뀐 것만.** 5초마다 전체를 다시 그리면 시선이 흔들려 값이 안 읽힌다.
      구현상으로는 **상대 시각을 심박 한 곳에만** 쓴다 — 매초 바뀌는 문구를 여러 줄에 두는 것이
      실제 흔들림의 정체다. SpO₂·이산 측정은 `14:32` 절대 시각(워치와 같은 규칙).
- [x] **이산 측정 = 풀어 쓴다.** `강도26` → `운동 강도 4.2 MET · 3건`. 워치가 줄인 것은 폭 제약
      때문이고 폰엔 그 제약이 없다. **순서는 워치와 같게** 둔다(두 화면 대조가 §5 검증이다).
- [x] **활동에너지 = 넣지 않는다.** 약 4 배 과대라 그대로 띄우면 틀린 수치를 보여주게 된다.
      재검토 시점 = **활동 축이 바뀐 뒤**([heat-activity-axis](../../../dashboard-web/docs/heat-activity-axis/checklist.md))
      — 날짜가 아니라 조건으로 둔다. 기한 없는 대기가 '확인됨'으로 오독되지 않게 가드로 못 박았다.

### 구현 메모 — 계획과 달라진 것 2건

1. **네이티브가 누적 스냅숏을 통째로 보낸다**(Dart 는 모으지 않는다). Flutter 엔진은 재기동돼도
   앱 프로세스는 살아 있으므로, 누계를 네이티브가 들면 화면이 끊기지 않는다.
   ⚠ 그래도 **iOS 가 앱 프로세스를 재기동하면 0 부터**라 워치 세션 누계와 다를 수 있다 —
   걸음·오른층에 `폰 수신 누계` 를 함께 적어 하루 총량으로 오독되지 않게 했다.
2. **심박 없는 배치도 화면으로 내보낸다.** 종전 emit 은 `if let bpm` 조건이었는데,
   **미착용 구간(심박 0건)이 무동작 지속의 핵심 용도**라 그 조건을 두면 정작 봐야 할 구간이
   통째로 빠진다. 가드로 고정했다(`test/vital_display_test.dart`).
