# 온열 활동 축 — 활동에너지 사용 불가 확정 + 하이브리드 결정 (2026-08-15)

온열 예방 3축(환경·생리·**활동**) 중 활동 축이 실제로 작동하는지 실측한 결과다.
환경 = [wbgt/](../wbgt/checklist.md) · 생리 = [psi/](../psi/checklist.md) · 수집 = [heat-env-inputs/](../heat-env-inputs/checklist.md).

> **결론 먼저 — 온열 ②(저활동·고심박)는 2026-08-13 배포 당일부터 발동한 적이 없고, 발동할 수도
> 없었다.** 원인은 버그가 아니라 **상시 워크아웃 세션의 구조적 대가**다. 그리고 대체 신호로
> 걸음을 단독 사용하는 것은 **사용자 결정으로 기각**됐다 — 앉아서 작업하는 사람은 걸음이 0이다.

---

## 1. 확정 사실 — 활동에너지는 저활동 판정에 쓸 수 없다

### 1-1. 판정이 구조적으로 거짓이다

```
lib/heat-pattern.ts:88
  flagged = hrAvg >= 100 && aeKcalPerMin <= HEAT_PATTERN_LOW_KCAL_PER_MIN(1.5)
```
실측(08-13 이후 · 심박 커버 ≥10 · 12건 온전한 분만 = **2,067분**)
```
분당 최소 2.40 kcal   ← 임계 1.5 보다 크다
평균     4.81
최대    52.79
임계 1.5 이하 분  0건
```
**분당 최솟값이 임계를 넘으므로 어떤 15분 창 평균도 임계 이하가 될 수 없다.** 논증 종결.
⟹ `flagged` 는 영영 false · **온열 ② 주석 + 온열 ③ "경고" 단계(38.0℃ + 이 패턴) 동반 불가**
(주의 37.8℃ 단계만 생존).

⚠ 문서에 *"주석 육안은 자연 발생 대기 — 평시엔 안 뜨는 게 정상"* 으로 적혀 있었는데
**기다려도 오지 않는다.** 재난문자 '대피' 재승격이 한 달간 죽어 있던 것과 같은 형태다.

### 1-2. 값이 상황에 반응하지 않는다

```
① 착용·활동 (심박 101)   0.401 kcal/5초 = 분당 4.82   걸음 893
② 몸에 접촉  (심박  72)   0.404          = 분당 4.84   걸음 0
③ 책상 위    (심박 없음)  0.403          = 분당 4.84   걸음 0
```
⚠ **정확한 서술은 "상수" 가 아니다.** 개별 값은 0.04~4.31 로 흔들리고(표준편차 0.11~0.15)
재착용 순간엔 0.21~0.97 까지 벌어진다. 정확히는 **평균이 상황에 반응하지 않는다**.

### 1-3. 원인 — 우리 코드가 아니다. 상시 워크아웃의 대가다

워치 델타 로직은 계약대로다(`sessionEnergyKcal − energyReportedKcal` · 음수면 기준 재설정 ·
잔여 이월). **건강 앱이 같은 값을 보여준다.**
```
건강 앱  활동 에너지 시간당 240~290 cal · 운동하기 총 472분 · 오늘 총 2,201 cal
검산     2,201 ÷ 472분 = 분당 4.66 kcal
우리 DB  분당 4.77~4.79            ← 일치
```
```
상시 HKWorkoutSession (폰 강제종료·잠금 생존의 핵심 장치)
  → 애플이 하루 7.9시간을 "운동 중" 으로 간주
    → 앉아 있어도 활동 에너지를 시간당 288 cal 로 산출
      → 우리는 그 값을 정확히 5초 증분으로 옮긴다
```
**⟹ 고칠 수 있는 버그가 아니다.** 상시 워크아웃을 포기하면 이 앱의 존재 이유가 사라진다.

⚠ **임계를 4.8 위로 올리는 것은 해법이 아니다.** 1.5 의 근거는 일반 대사 참고값
(휴식~서있기 0~1.5 · 가벼운 작업 3~5)이고 그것은 옳다. 축이 안 맞는 쪽은 워치 값이다.
임계를 맞추면 **근거 없는 숫자**가 된다.

### 1-4. 언제부터인가 — 태생적이다

```
08-13  5,535행  평균 분당 4.74     ← 온열 ① 수집 첫날
08-14  6,734행           4.79
08-15  5,382행           4.77
```
어느 시점에 망가진 것이 아니라 **처음부터 그 상태**였다.

## 2. ★ 결정 — 걸음 단독 금지, 하이브리드로 간다 (사용자 2026-08-15)

> **"온열과 걸음을 복합적으로 하이브리드 기반 — 앉아서 작업하는 사람은 걸음이 측정되지 않음."**

걸음은 오늘 실측에서 세 구간을 완전히 갈랐고(893 / 0 / 0) 실제 움직임에만 발생해 축이 맞다.
그러나 **단독으로 쓰면 앉아서 하는 작업(용접·조립·전장 작업)을 저활동으로 오분류**한다.
그 사람들은 팔로 일하고 심박도 오르는데 걸음이 0이다 — **온열 ② 가 잡아야 할 대상을 오히려
잘못 분류**하게 된다.

### 신호별 사용 가능성 (2026-08-15 실측)

| 신호 | 축이 맞나 | 밀도 | 값이 없을 때의 뜻 |
|---|---|---|---|
| **활동에너지** | ✗ 바닥 4.8 상수 | 촘촘 12/분 | — |
| **걸음** | 보행만 | 산발 364/일 | 안 걸음 / 미수집 / **앉아서 작업** ← 3중 모호 |
| **MET**(`physicalEffortMet`) | ✓ 대사율(ACGIH 표준 입력) | **희소 135/일** | 안 움직임 / 미기록 |
| **심박** | ✓ 생리 | 촘촘 | — |
| **가속도**(`accelMagnitudeG`) | ✓ 팔 움직임 포함 | **미수집(전부 NULL)** | — |

**★ 연속적이면서 축이 맞는 활동 신호가 지금 하나도 없다.**
활동에너지는 촘촘하지만 축이 틀리고, 걸음·MET 는 축은 맞지만 희소하며 부재가 모호하다.
**앉아서 하는 작업을 잡을 수 있는 유일한 후보는 가속도인데 지금 안 보내고 있다.**

### 필수 장치 — "0" 과 "미수집" 을 가른다

걸음·MET 를 쓰려면 반드시 붙어야 한다. `appendCountDelta:380` 이 **1걸음 미만이면 항목 자체를
싣지 않으므로** DB 의 `steps IS NULL` 은 "안 걸었다" 와 "수집 안 됨" 을 겸한다.

**이미 이 코드베이스에 장치가 있다** — 온열 ② 자신의 `lookback 45분` 이다
(08-13 결정: *"에너지 파이프라인 없는 구 앱 워커는 '저활동' 이 아니라 '모름'"*).
**판정 불가(null) ≠ 정상(false)** 원칙을 걸음에 그대로 적용한다. 새 설계가 아니라 입력 교체다.
```
lookback 안에 걸음 항목이 한 번이라도 왔다  → 수집 정상 → 이후 0 은 진짜 0
한 번도 안 왔다                             → 판정 불가(null)
```

## 3. 남은 일

- [ ] **하이브리드 설계 확정** — 사용자 결정(§2)을 어떤 조합으로 구현할지.
      최소한 다음을 정해야 한다 ⓐ 걸음 + 심박 + 환경(WBGT/체감온도)의 결합 방식
      ⓑ 앉아서 작업하는 경우의 처리(판정 불가로 둘 것인가, 다른 신호를 볼 것인가)
- [ ] **가속도 수집 여부 결정** — 앉아서 하는 작업을 잡을 유일한 후보다.
      워치 수집 추가가 필요하고 배터리 영향 확인이 선행(현행 6.46%/h).
      ⚠ 낙상용으로 구 앱이 보내던 필드라 스키마·DB 컬럼은 이미 있다
- [ ] **`HEAT_PATTERN_LOW_KCAL_PER_MIN` 처리** — 임계를 남기면 "언젠가 뜬다" 로 오독된다.
      상수를 지우든, 발동 불가 사실을 코드 주석과 가드에 못 박든 **둘 중 하나는 해야 한다**
- [ ] **온열 ③ 경고 단계 재설계** — 현재 "38.0℃ + 저활동·고심박" 이라 동반 불가 상태다
- [ ] (별건) **구 앱 활동에너지 스파이크** — 06-28~07-25 316행이 분당 261~2,109 kcal 다
      (증분이 아니라 누적치를 실은 것으로 보인다). 판정에는 영향 없으나
      `incident-report.ts` 의 `activeEnergyKcal` 시계열·CSV 에 섞이면 스파이크가 된다

## 4. 하지 않기로 한 것

- **임계 상향(1.5 → 4.8 위)** — 근거 없는 숫자가 된다(§1-3).
- **활동에너지를 저활동 판정에서 쓰기** — 축이 맞지 않는다. 표시·사고 조사용으로는 유지한다.
- **걸음 단독 사용** — 사용자 결정으로 기각(§2).
