## B. 현장 포트포워딩 — 설정 절차

### B-0 현장에서 먼저 확인할 것 (5분)
```
① 공유기 관리자 id/pw 확보
② 젯슨에서  for t in 1 2 3; do ping -c1 -W2 -t $t 8.8.8.8 | grep -oE "From [0-9.]+"; done
   → 2홉이 공인 IP(10.x·100.64~127.x·172.16~31.x·192.168.x 가 아님)면 단일 NAT · 진행 가능
   → 2홉도 사설이면 이중 NAT — 그 위 장비 권한도 필요
   → 공유기 WAN IP 가 100.64.0.0/10 이면 CGNAT — 포트포워딩 불가 → 서버 중계(A-5)로
③ 태블릿 Wi-Fi 상세의 게이트웨이가 공유기와 같은 장비인가(같으면 격리만 풀어도 건물 안은 됨)
```

### B-1 공유기 설정 (관리자 화면)

### B-2 젯슨 — DuckDNS 를 사설 IP 대신 공인 IP 로
- 지금: `/home/jetson/duckdns_update.sh` 가 `duckdns.timer`(5분)로 **사설 IP** 를 올린다.
- 바꿀 것: 스크립트가 `curl -s https://api.ipify.org`(또는 DuckDNS 자동 감지 = `ip=` 비움)로 공인 IP 를 올리게. 토큰은 `~/.duckdns_token` 그대로(채팅·argv 에 안 싣는다).
- 검증: `dig +short cctv-gate.example.invalid` = 공유기 WAN IP · 젯슨 로그에 `OK`.
- ⚠ DuckDNS 가 옛 주소를 조용히 남긴 사고가 있었다(`duckdns-record-stale-gate-dead`) — 갱신 뒤 dig 로 반드시 대조.

### B-3 건물 안 기기 (NAT 루프백이 없을 때)
