## 추론은 우리 엔진이 한다 — 카메라 기능이 아니다

사용자 확인 요청에 대한 실측 답.
```
PPE      v7e (ppe_yolo26s_rect544x960_v7e_nc.engine · 22MB · 09-15 우리가 학습)
자세     yolo11s-pose.engine (22.6MB · 09-13 · sha 6b738c8f592c)
추론시간  15+17ms (PPE+자세) — 젯슨 GPU 가 프레임마다 쓴 시간
카메라가 보내는 것  RTSP 트랙이 video(H264)+audio(PCMA) 둘뿐. 감지 결과·메타데이터 트랙 없음
프레임 오버레이     "CAM-01 IP캠 PPE yolo26 v7e@544x960 · 자세 11s-pose@640" + 박스·스켈레톤 = 젯슨이 그린 것
                  (좌하단 "VIGI C340S 1.0_AED4" 만 카메라가 구운 자기 표기)
```
VIGI 자체 사람감지 기능은 쓰지 않는다 — 우리 판정 기준(안전모·조끼·낙상)과 다르고 앱 안에서만 쓸 수 있다.

## 구조 — 한 파일로 두 대

```
푸셔 gopro_ppe_edge.py  env 로만 갈린다. 기본값이 CAM-03·gopro 라 종전 동작 그대로.
  CAM_SUFFIX  ingest 경로·화면 라벨·로컬 페이지 제목·구역 파일명
  CAM_SOURCE  gopro 면 웹캠 START/STOP 제어, rtsp 면 건너뛴다(IP캠은 스스로 송출)
게이트 cctv_gate.py     접미사별 상류·표 검증·토글. 주소·포트·인증서는 하나로 유지.
  CAMS = {"3": (CAM-03, :8444), "1": (CAM-01, :8445)}   GATE_UPSTREAM_1 로 늘린다
서버·관제웹             db.ts 시드로 cctv_camera 에 CAM-01 등록(없으면 티켓이 unknown camera 로 거부)
                       CctvQuadView 의 CAM-01 을 gateApi + aiKind ppe + suffix 1 로
```

⛔ **[M/L] 이 잡은 결함 — 구역 파일 공유.** `zone.json` 이 스크립트 위치로만 정해져 두 인스턴스가 같은 파일을 읽고 썼다.
한쪽이 구역을 저장하면 다른 카메라 구역을 덮어쓰고, **오류 없이 위반 수만 틀어진다.** `zone{CAM_SUFFIX}.json` 으로 갈랐고
기존 구역은 `zone3.json` 으로 보존했다(5점 폴리곤 107바이트).

## 남은 것

- **서버 중계(앱에서 CAM-01 보기)** — 서버에 `ingest1`·`stream1`·`stats1` 라우트가 없다([M/L] 지적).
  지금 CAM-01 은 `CCTV_BASE` 없이 띄워 push 를 안 한다(`pushed 0` 이 정상). 관제웹(랜)에서만 보인다.
- **카메라 이름** — 관제웹 타일의 ✎ 로 바꿀 수 있으나 localStorage 라 그 브라우저에만 남는다.
  모든 PC 에 같은 이름을 주려면 `CctvQuadView` 의 `location` 기본값을 바꾼다.
- **구역(zone1.json)** — CAM-01 은 아직 구역을 안 찍었다. 찍기 전에는 화면 전체가 판정 대상이다.
- **낙상 로그** — `pose_log_cam1` · `fall_takes_cam1` 로 CAM-03 과 분리했다(섞이면 어느 카메라 것인지 못 가린다).
