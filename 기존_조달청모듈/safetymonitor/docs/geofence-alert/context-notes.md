# 현장 구획 이탈 알림 — 결정·근거

## 2026-07-22 착수 결정

- **판정 위치 = 클라이언트(DemoDashboard)** — 구획 원 중심(주소 지오코딩→캐시 좌표→라이브 평균)이 클라이언트에서 합성되는 값이라, 서버 판정으로 이관하면 화면 원과 판정 기준이 갈릴 수 있다(임계 단일 소스 원칙). 화면에 그리는 원과 정확히 같은 중심·반경으로 판정한다.
- **히스테리시스** — 도심 폰 GPS 오차(5~30m)로 반경 100m 경계에서 이탈↔복귀 플리커 방지. 이탈 = 반경+10m 초과가 연속 3회(2초 폴링 ≈ 6초) 지속 시 발화, 복귀 = 반경−10m 이내. 상수는 `geofence.ts` 에 단일 정의.
- **미수신 ≠ 이탈** — GPS 미수신(미접속·권한 게이트·한국범위 밖)은 판정하지 않는다. 60초 초과 stale 샘플(연결끊김 상태머신과 동일 임계)도 판정 보류 + 상태 리셋(재수신 시 초기부터 다시 판정). stale 좌표로 발화하지 않기 위함.
- **경보 UX = 전용 앰버 모달, 사이렌 없음** — SOS/낙상/생체(SosAlertModal)는 레드 응급 정체성 + 사이렌 결합이라, 주의 수준인 구획 이탈을 거기 얹지 않고 전용 `GeofenceAlertModal`(주의 톤) 신설. 팝업 우선순위는 SOS > 낙상 > 생체 > 이탈.
- **재경보 규칙 = vital 패턴 미러** — 확인/닫기 시 그 작업자 억제, 복귀(반경−10m 이내)하면 억제 해제 → 재이탈 시 재경보. localStorage 영속 ack(`appendAckedAlertKey`)는 이벤트형(SOS/낙상)용이라 레벨형인 이탈엔 vital 과 동일하게 미적용.
- **DB 이력 = `alerts` 테이블 재사용** — `AlertType` 에 `"geofence"` 추가(컬럼 TEXT·CHECK 없음 = additive). 기록은 이탈 전이당 1건, 클라이언트가 신규 `POST /api/alerts`(세션 게이트)로 기록. 서버 자동 기록(addSample)과 달리 클라이언트 기록은 **geofence 종류만 허용**해 SOS/낙상/생체 위조 삽입을 차단.
- **한계(알려진)** — 중심이 라이브 GPS 평균 폴백일 때(주소·캐시 좌표 모두 없음)는 중심이 작업자를 따라가므로 판정 실효가 낮다. 현장정보 주소가 저장돼 있으면(지오코딩 중심) 정상 동작. 작업자 앱 푸시는 별도 트랙(FCM/APNs).
