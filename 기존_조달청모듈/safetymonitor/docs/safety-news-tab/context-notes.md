## N-02 · 결정 — 레이아웃 A안(위=지금 / 아래=참고)

사용자 선택. 다만 재난문자까지 이관하기로 하면서 블록이 3 → **4개**가 되어 A안의 정신
(무거운 것 위, 참고 자료 아래)을 유지한 채 **2×2** 로 확장했다.

```
[재난문자 — 현장 시·도]   [🔴 산업재해 속보]     ← 지금 벌어지는 일
[국내 재해사례]           [산업 안전뉴스]        ← 참고 자료
```

**근거.** 재난문자는 평소 "재난문자 없음"이라 전체폭을 주면 빈 공간이 크고,
속보와 성격(지금·경보)이 같아 한 줄에 묶는 편이 읽기 쉽다.
3열 균등(B안)은 사망 속보를 재해사례·뉴스와 같은 무게로 만들어 묻힌다.

`useMarqueeScroll` 훅은 다른 3개 컴포넌트가 쓰므로 남긴다.

## N-06 · 2차 레이아웃 — 전체 폭 4단 스택 (2026-07-31)

사용자 재지시. 2×2 그리드를 버리고 **전체 폭 4단 스택**으로 바꿨다.

```
1) 산업재해 속보   가로 슬라이딩 카드   (낮음)
2) 긴급재난문자    목록                (h-220)
3) 산업 안전뉴스   섬네일 카드 가로      (낮음)
4) 국내 재해사례   가로 슬라이딩 카드   (낮음)
```

**가로 슬라이딩은 `useMarqueeScroll(speed, "x")` 재사용.** 삭제했던 티커가 쓰던 훅이 그대로 맞는다
(자동 흐름 + 호버 시 정지 + 수동 좌우 스크롤, 2벌 복제로 seamless).
`KoshaAccidentCaseCard` 는 세로(`"y"`) → 가로(`"x"`)로 축만 바꿨다.
산업 안전뉴스는 요청에 슬라이딩이 없어 **수동 가로 스크롤만** 둔다.

## N-07 · ★ 뉴스 섬네일 — 네이버 API 가 이미지를 주지 않아 og:image 를 직접 뽑는다

**문제.** 네이버 뉴스검색 API 응답은 `title / originallink / link / description / pubDate` 뿐이다.
`NewsItem` 에도 이미지 필드가 없었다. **현재 데이터로는 섬네일이 불가능**했다.

**해법(사용자 선택).** `app/lib/og-image.ts` — 서버가 기사 링크를 열어 `<meta og:image>` 를 뽑는다.
링크 미리보기(카톡·슬랙)와 같은 수준의 공개 메타데이터 조회이고 본문은 저장하지 않는다.

**실측(2026-07-31).**
```
기사 10건  성공률 10/10  ·  2,110ms  ·  2회차(캐시) 0ms
```

**설계 다섯 가지.**
1. **캐시 6시간** — 기사 대표 이미지는 안 바뀐다. 뉴스 목록 캐시(15분)보다 훨씬 길게.
2. **`Range: bytes=0-262143`** — og:image 는 `<head>` 에 있다. 지원하면 앞부분만, 무시돼도 동작.
3. **타임아웃 3.5초 · `Promise.allSettled`** — 한 매체가 느려도 나머지를 막지 않는다.
4. **`https` 아니면 버린다** — CSP `img-src` 가 https 만 허용한다.
5. **UA 를 정직하게 밝힌다**(`VitAlGuardBot/1.0`). 브라우저로 위장하지 않는다.

**폴백이 정상 경로다.** 추출 실패(차단·부재·타임아웃)와 **브라우저 핫링크 차단**(`onError`) 둘 다
매체 이니셜 + 해시 색상 블록으로 떨어진다. 가짜 이미지를 만들지 않는다.
`referrerPolicy="no-referrer"` 로 Referer 검사식 차단은 최대한 피한다.
외부 CDN 도메인이 매체마다 달라 `next/image`(remotePatterns) 대신 `<img>` 를 쓴다.

⚠️ **캐시 때문에 첫 확인에서 섬네일이 안 보였다.** `naver-news.ts` 의 15분 인메모리 캐시가
이미지 부착 **이전** 목록을 들고 있었다. dev 서버 재시작으로 해소 — 배포 후에도 최대 15분은
구 데이터가 나온다(정상).

## N-08 · 🐛 `semantic-down/<opacity>` 클래스가 생성되지 않는다

다크모드에서 위 두 패널(속보·재난문자) 프레임만 밝게 튄다는 지적에서 출발해 원인을 찾았다.

**원인.** 색이 `tailwind.config.ts` 에 `"semantic-down": "var(--color-semantic-down)"` 로 잡혀 있고
`globals.css` 의 `--color-semantic-down: #ef4444` 는 **hex** 다. Tailwind 는 이 형태에서
투명도 변형(`/30`, `/5`)을 만들지 못한다(`rgb(var(--x) / <alpha-value>)` 형태여야 한다).

**증상.** 클래스가 아예 생성되지 않아
- `border-semantic-down/30` → 테두리 색 지정 없음 → **기본 gray-200(`rgb(229,231,235)`)** 으로 남는다.
  라이트모드에선 티가 안 나지만 **다크모드에선 밝게 튀어** 다른 패널과 프레임이 갈려 보인다.
- `bg-semantic-down/5` → **투명**(배경 없음).

측정으로 확인했다 — 속보 카드 `borderColor rgb(229,231,235) · backgroundColor rgba(0,0,0,0)`.
**`text-semantic-down`·`bg-semantic-down`(투명도 없는 것)은 정상 동작한다.**

**조치(범위 한정).** 전역 색 정의를 고치면 앱 전체에 영향이 가므로 건드리지 않았다.
안전뉴스 탭 컴포넌트에서만 레포 기본 토큰으로 교체했다 —
`border-hairline dark:border-white/10` · `bg-canvas dark:bg-surface-dark` · 배지는 `bg-surface-strong`.
경보 위계는 테두리가 아니라 **붉은 점·붉은 유형 배지·붉은 글자**가 담당한다.

⚠️ **같은 패턴이 레포 다른 곳에도 남아 있다** — `SiteSafetyTables`(/15) · `DemoDashboard`(/5) ·
`WeatherAlertToast`(/60). 이번 범위 밖이라 손대지 않았다. 전역으로 고치려면
`--color-semantic-down: 239 68 68` + `rgb(var(--color-semantic-down) / <alpha-value>)` 로 바꿔야 한다.

## N-09 · 현장 환경 좌측 호버 패널 (2026-07-31)

관제 탭 밖에서는 현장 환경 스트립이 화면에 없다. 좌측 여백에 손잡이를 두고 호버하면 같은 정보를
**세로 목록**으로 펼친다(가로 오토슬라이딩 금지 — 사용자 요청). 관제 탭(0)에서는 띄우지 않는다.

**컴포넌트를 복제하지 않았다.** `WeatherStrip`(754줄·데이터·정책 모달 포함)에 `layout` prop 만 더해
`"list"` 일 때 마퀴 대신 세로 목록을 렌더한다. 데이터·모달·임계 판정은 그대로 재사용된다.

**⚠️ 발견 — 경보 팝업이 두 벌 뜬다.** `WeatherAlertToast` 가 `WeatherStrip` **안에** 있어서
두 번째 인스턴스가 같은 경보 모달을 또 띄웠다(실제로 테스트 중 클릭이 막혔다).
→ `layout !== "list"` 일 때만 팝업을 띄운다. 확인/조치 기록이 이중으로 남는 것도 함께 막힌다.

**좁은 폭 대응.** 헤더의 `작업자 N명 GPS 평균 (…)`·`Open-Meteo · 항목 클릭 시 정책 근거` 는
340px 패널에서 여러 줄로 뭉쳐 읽기 어렵다 → list 에서는 갱신 시각(HH:MM)만 남긴다.
`data.cached` 의 "캐시" 글자는 우측 좌표출처 배지와 겹쳐 읽혀 혼동되므로 list 에서 생략.

**위치.** `top-44`. 이보다 위면 패널이 상단 탭 바를 덮어 **탭 클릭이 막힌다**(실측으로 확인).
`hidden lg:flex` — 좁은 화면엔 띄울 좌측 여백이 없다.

⚠️ **중복 폴링.** SectionPager 가 모든 페이지를 마운트 유지하므로 관제 탭의 스트립과 호버 패널이
동시에 살아 있어 `/api/weather`·`/api/kma-warning` 호출이 2배가 된다.
두 라우트 모두 **서버 캐시가 앞에 있어 상류(Open-Meteo·기상청) 호출은 늘지 않는다.**
알림도 전이 기반이라 중복 발송되지 않는다. 신경 쓰이면 데이터를 상위로 올려 한 벌만 두면 된다.

## N-10 · 사이드 패널 — 호버 → 클릭 토글 + 분리 (2026-07-31)

사용자 재지시. `SiteEnvHoverPanel` → **`SiteSidePanels`** 로 교체(파일명도 변경 — 더 이상 호버가 아니다).

- 손잡이를 **2개로 분리** — `현장 환경`(WeatherStrip list) / `안전 신호등`(SafetySignalBoard).
  한 번에 하나만 열리고, 열린 손잡이를 다시 누르면 닫힌다.
- **닫기 ✕** 를 패널 우상단 **모서리 바깥**(-right-2 -top-2)에 둔다 —
  패널 자체 헤더의 우측(좌표출처 배지·종합 위험 배지)과 겹치지 않게.
- 활성 손잡이는 파란 배경으로 채워 열림 상태를 드러낸다(`aria-expanded` 도 함께).

**부수 효과 — 중복 폴링이 해소됐다.** 호버 시절엔 패널이 항상 마운트돼 관제 탭의 스트립과
`/api/weather`·`/api/kma-warning` 을 2배로 불렀다(N-09 의 ⚠️). 이제 **열 때만 마운트**되므로
닫아두면 추가 호출이 0 이다.

⚠️ **대신 열 때마다 새로 조회한다** — 처음 1초 남짓 로딩 상태가 보인다(서버 캐시라 대개 빠르다).
검증 중 "클릭 직후 내용이 비어 보이는" 현상이 이것이었다. 계속 열어두면 5분 주기 갱신은 그대로 돈다.
