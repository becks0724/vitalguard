# 사고 조사 뷰 — 컨텍스트 노트 (결정·근거)

## 2026-08-13 — 트랙 착수 결정 (사용자)

- 배경 = 관제웹 목적은 작업자 안전관리이고, **산업재해 발생 시 발생 시점 생체 데이터 기반 보고자료**를 만들어야 함(사용자 요구 = 보관 1년 실정 → 논의 후 **사고 구간 3년**으로 확정, KOSHA 보존 기준 축).
- 체온(심박 추정) 추세 7일 상한 논의에서 파생 — 상한은 유지한다. 상한의 취지는 "추정치의 장기 집계 추세" 방지이고, 사고 조사는 "특정 시점의 상세 재구성"이라 층이 다르다.

## 설계 결정

**D-1. 사고 등록 테이블이 보존 원장을 겸한다.** `incidents`(worker_id·occurred_at·note·created_by) 는 조사 뷰의 앵커이자 **3년 보존 마킹의 단일 원장**이다. 현재 원시 데이터(vital_samples)에는 삭제 정책이 없으므로 "지우는 코드"를 새로 만들 것은 없고, **미래에 리텐션을 도입하는 사람이 이 테이블을 선조회해 등록 구간(발생 ±조사 창 이상)을 제외**해야 한다 — db.ts 테이블 주석에 룰로 박는다. 사고 기록 삭제 API 는 만들지 않는다(감사 자료 성격 — 오등록 정정이 필요해지면 별도 결정).

**D-2. 조회 창 = 전후 대칭.** 사고 조사는 "이전 맥락(전조)"과 "이후 대응(회복·구조)"이 둘 다 필요하다. 기본 24h = 전 12h·후 12h. hours ∈ {6,12,24,48} 화이트리스트(자유 입력은 검증 부담 + 추정 체온 검증 범위 이탈).

**D-3. 추정 체온은 저장하지 않고 재계산한다.** 칼만 추정은 순수 함수(같은 입력 → 같은 출력)라 원시 심박만 보관되면 몇 년 뒤에도 동일 궤적이 재생성된다. 추정치 컬럼 보관은 중복이고, 모델 계수를 개선했을 때 과거 보고서와 화면이 갈리는 문제만 만든다. 보고서에 적히는 것은 "조회 시점의 모델(문헌 계수 고정)로 재계산한 추정"이며 CSV 메타에 그렇게 명시한다.
- 워밍업 공백 대응 — 창 시작 90분 전 심박부터 당겨 계산 후 창으로 잘라낸다(30분 워밍업 + 60분 세션 갭 여유). 그래도 창 초입에 착용 시작 30분 미달 구간이 있으면 점이 없는 것이 정직한 표현.

**D-4. 등록 시각 조회도 허용하되 등록이 원칙.** data 라우트는 workerId+at 로 임시 조회가 가능하지만(등록 전 훑어보기), **보존 마킹은 등록된 사고에만** 적용된다 — UI 에 명시.

**D-5. 인증·배치.** admin/export 와 동일 게이트(`hasAdminMenuAccess`) + 관리자 모달("산업재해 자료" 헤더) 안 탭. 이미 산업재해 자료 내보내기가 사는 곳이라 사용자 동선이 일치한다.

**D-6. CSV 는 클라이언트 생성.** data 응답(JSON)을 받아 브라우저에서 Blob 다운로드 — 서버 라우트 추가 없이 끝나고, 형식 변경이 배포 없이 안 되는 단점은 보고서 도구 특성상 감수(형식 = ts,metric,value 롱포맷 + 이벤트 절 + 메타 헤더 주석).

**기존 자산 재사용** — `heartRateBucketAverages`·`spo2MeasurementsBetween`(구간 조회)·`estimateCoreTempSeries`(칼만)·`aliasIdsOf`(별칭 확장·real.ts 에서 export 로 승격)·alerts 테이블(SOS·낙상 + ack 대응 시각 — "알림→대응 시각" 첨부는 이 테이블의 원래 설계 목적).

**정정 기록** — 착수 전 분석에서 "과거 특정 시점을 화면에서 열 수 없다"고 했는데 **절반만 맞았다**. 추세 차트에 일 단위 커스텀 기간(from/to)이 이미 있다(08-12 실데이터화 때 동반). 이 트랙의 실제 신규 가치는 ① 사고 등록·보존 마킹 ② 시각(시·분) 앵커의 **통합 화면**(4지표+이벤트 동시) ③ 보고자료 내보내기다.

## 2026-08-13 — 구현 중 결정·발견

- **가드 맹점 실증 → 강화** — 인증 게이트 가드를 "호출 문자열 존재"로 썼더니 음성 대조(`true || hasAdminMenuAccess(...)` 우회)가 통과해 버렸다. 가드는 존재가 아니라 **차단 관용구 전체**(`if (!(await hasAdminMenuAccess(request)))`)를 봐야 한다. 음성 대조가 없었으면 장식 가드가 됐다.
- BOM 은 소스에 리터럴로 넣지 않는다(`"﻿"` 이스케이프) — no-irregular-whitespace 가 잡았다(L-10 계열 기존 룰 재확인).
- 검증 = tsc 0 · lint 0err · test 656/656(신규 11: 헬퍼 7 + 가드 6... 정확히는 incident-report 5 + 가드 6) · 음성 대조 2종(보존 문구 훼손·인증 우회 → 각각 가드만 실패).
