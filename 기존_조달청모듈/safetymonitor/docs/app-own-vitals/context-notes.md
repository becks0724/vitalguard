# 폰 앱 본인 생체 조회 — 컨텍스트 노트

## A-01 · 관제 조회를 그대로 열지 않은 이유
`GET /api/monitor/vital` 이 이미 `coreTempEst`·`countsByWorker` 를 담고 있어 재사용이 빨라 보인다.
그러나 인가가 `verifyBasicAuth`(관제 세션·오너 자격)이고 응답은 **전 작업자 + PII** 다.
여기에 앱 JWT 를 통과시키면 작업자 폰이 동료 전원의 생체를 보게 된다 — 권한 범위가 뒤집힌다.
그래서 **본인 스코프 엔드포인트를 새로** 만들었다.

## A-02 · 스코프를 파라미터로 받지 않는다
`?workerId=` 로 받으면 남의 사번을 넣어 조회할 수 있다. 서명된 클레임에서만 읽는다.
수집 라우트가 같은 이유로 `bodyIsBoundToWorker(body, claims.workerId)` 를 강제한다.

## A-03 · 계정 전환은 이미 성립한다(코드 확인)
로그인이 `signAppJwt({workerId})` 로 서버가 뽑은 사번을 서명해 넣는다.
`admin6861 → EMP-6861`(사번 정식화) · `admin7276 → EMP-admin7276`(미설정 폴백)로
관제웹 표기와 일치한다. 폰은 토큰만 갈아끼우면 되고 조회 코드는 그대로다.

## A-04 · ★ 그 확인에서 찾은 결함 — 화면 스냅숏이 계정을 모른다
`PhoneReceiver.snapshot` 에 `workerId`·`AuthStore` 참조 **0건**. 누적 필드(`steps`·
`discreteCounts`)가 앱 프로세스 수명 내내 자라고 배치마다 전량 emit 된다.
업로드 큐는 계정 교체 시 `purgeQueue` 로 폐기되는데(`VitalBridge.swift:158`) **화면은 그 조건을
공유하지 않는다.** 즉 서버 데이터는 정확한데 화면만 직전 작업자 값을 보여준다.

두 곳이 **같은 조건**(`previous != workerId`)을 쓰도록 묶는다 — 조건이 갈리면
"큐는 비웠는데 화면은 남는" 지금 상태가 다시 만들어진다.

## A-05 · ★★ 메모리 링에 기대면 폰에서만 값이 통째로 사라진다
초판은 관제와 같은 `latestByWorker`(인스턴스 메모리 링)를 썼다. 로컬 dev 에서 PSI·스트레스가
전부 null 로 나와 원인을 보니 **그 프로세스가 받은 POST 만** 담는 구조였다.

프로덕션 실측 — `minScale 1 · maxScale 4` 이고 **최근 1시간 인스턴스 2개**. 폰이 자기 샘플을
받은 적 없는 인스턴스에 붙으면 값이 영영 안 나온다. 관제 화면은 여러 워커를 한꺼번에 보므로
덜 드러나지만 **한 사람만 보는 폰에서는 그 사람 값이 통째로 사라진다.**

→ `recentSamplesForWorkers`(DB `raw_json` 복원) + **관제와 같은 `mergeLatestByWorker`**.
같은 병합 함수를 쓰는 것이 요점이다 — 각자 구현하면 활동 필드 TTL 같은 규칙이 갈린다.
store 파일 주석이 이미 원칙을 적어 두고 있었다("인스턴스 메모리 상태 금지").

## A-06 · 안정 심박만 창을 길게 본 이유
180분 창으로 바꾸자 PSI 가 `personalized: false` 로 나왔다. DB 를 재니 이 워커의 마지막
안정 심박은 **하루 전(08-17 08:03)** 이었고, 관제 화면은 인스턴스 메모리가 그 값을 계속
들고 있어 개인화된 값을 쓰고 있었다 — 창이 짧으면 **폰만 값이 갈린다.**

안정 심박은 애플이 하루 단위로 산출하는 **기준값**이라 며칠 전 값도 그 사람의 기준으로 유효하다.
반면 HRV·호흡수는 그 순간의 **상태 지표**라 같은 취급을 하면 며칠 전 값으로 "지금 스트레스"를
말하게 된다. 그래서 안정 심박만 7일 창으로 따로 조회하고 나머지는 180분에 맡긴다.

## A-07 · 끊긴 값으로 계산하지 않는다(관제와 한 곳만 다르다)
sticky 병합은 마지막 실측값을 유지하므로 게이트가 없으면 워치를 벗어도 3시간 전 심박으로
PSI·스트레스를 계산해 "지금 내 상태"로 보여준다. 관제와 같은 기준(`vitalAgeMs` · 60초)으로 막았다.

⚠ **관제 화면은 스트레스 칩에 이 게이트를 안 건다.** 그래서 끊긴 뒤에는 관제에 값이 남고
폰은 빈칸이 된다. 값이 갈리는 것을 알면서 택했다 — 한 사람만 보는 화면에서 **틀린 숫자보다
빈 자리가 낫다.** 관제 쪽을 함께 고칠지는 별도 판단.

## A-08 · 실호출로 확인한 것
로컬 dev(코드는 같고 DB 는 프로덕션)에서 앱 JWT 를 만들어 직접 호출했다 — 읽기 전용.
