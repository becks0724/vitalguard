### `sftyMngcst` = 산업안전보건관리비 확정 근거 3가지

스펙 DOCX 를 열지 못해 **항목명은 간접 근거로 확정**했다. 조달청 확인 필요(아래 미해결 참조).

1. **요율 역산 정합.** 내진보강(건축 5~50억) → 대상액 537,383,772원 = 순공사원가의 **73.0%**.
   리모델링(건축 5억 미만) → 283,022,187원 = **74.1%**. 두 건이 독립적으로 같은 비율대에 떨어진다.
   대상액(재료비+직접노무비)이 순공사원가의 70%대라는 건 정확히 예상되는 값이다.
2. **적용 범위가 산안법 패턴.** 표본 8건 전부 `sftyMngcst` 가 0이 아니다(2,500만원 빈집 해체공사 포함).
   반면 `sftyChckMngcst` 는 한강교량·도로사면 2건에서만 0이 아니다 —
   산안법(4천만원 이상 전면 적용) vs 건진법(대상 제한)의 차이 그대로.
3. **다른 제도 비용이 별도 필드로 분리**돼 있어 혼입 가능성이 없다.

### 커버리지 실측 (2026-07-01~03 계약 300건)

```
계상 의무 대상(4천만원 이상) = 156건
  ├ 공고번호 있음 : 126건 (80.8%)  → sftyMngcst 조회 가능
  └ 공고번호 없음 :  30건 (19.2%)  → 경로 없음 (미연결 계약액 합 1,201억원)
미연결 143건 중 134건이 수의계약. 최대 계약액 809억원 — "소액이라 무시 가능"이 아니다.
```

### 국세청 개방 범위 (실호출 확인)

```
POST api.odcloud.kr/api/nts-businessman/v1/status    → b_stt, b_stt_cd, tax_type, end_dt,
                                                        utcc_yn, invoice_apply_dt, rbf_tax_type
POST api.odcloud.kr/api/nts-businessman/v1/validate  → valid("01"/"02")
```

이 둘이 전부다. 세금계산서 발급사실은 공공 API 가 없어 CODEF 중계를 쓰는데,
**개인 실명 간편인증**(`loginType=5`)이 필요하고 승인 대기로 타임아웃을 280초까지 잡아 두고 있으며,
그렇게 얻는 값은 **`resAuthenticity` 불리언 1개**다. 관제 자동화가 원천 불가한 구조다.

### MCP 현황

공식 정부 MCP 서버는 **없다**. 커뮤니티 구현 2종만 존재한다.

- `Koomook/data-go-mcp-servers` — `pps-narajangteo`(나라장터), `nts-business-verification`(사업자등록)
- `ceami/opendata-mcp` — 범용(`search_api`·`get_std_docs`·`fetch_data`)

둘 다 **기초금액정보 오퍼레이션 포함 여부 불명**이고 요율 계산 같은 도메인 로직이 없다.
붙이면 LLM 이 요율을 기억해서 계산하게 되므로 행정 근거로 쓸 수 없다.
우리는 `g2b.ts`·`nts.ts`·`safety-cost.ts` 가 이미 있어 **MCP 래퍼만 씌우면 된다** — 만든다면 자체 구현이 맞다.

## 별표1 요율표 자체 검증 — 경계 연속성

`SAFETY_COST_RATES`(고시 제2025-11호 별표1)의 정합성을 계산으로 확인했다.
기초액은 임의 값이 아니라 **구간 경계에서 계상액 역전을 막는 값**이다.

| 공종 | 5억 경계 차이 | 50억 경계 차이 |
|---|---|---|
| 건축 | +175,000 (1.13%) | +175,000 (0.15%) |
| 토목 | +200,000 (1.27%) | +200,000 (0.15%) |
| 중건설 | +25,000 (0.14%) | +25,000 (0.02%) |
| 특수건설 | +50,000 (0.48%) | +50,000 (0.06%) |

**8개 경계 전부 연속이고 역전이 없다.** 각 공종에서 두 경계 차이가 정확히 같은 금액인데,
기초액이 불연속을 **정확히 이등분**하도록 설정돼 있기 때문이다.

```
기초액 = [ 5억×(5억미만요율 − 중간요율) + 50억×(50억이상요율 − 중간요율) ] ÷ 2
건축 검산 : (4,150,000 + 4,500,000) ÷ 2 = 4,325,000  ← 별표1 값과 오차 0
```

4공종 전부 성립한다. **3중 교차검증(2026-06)에 이은 사실상 4번째 독립 검증**이다.

### 이 성질로 HWP 파서 가드를 개선할 수 있다

`hwp-prvtext.ts` 의 현재 가드는 요율 범위(0.5~10%)만 본다.

```ts
if (pcts.slice(0,12).some(r => r < 0.005 || r > 0.1)) return null;
```

**파싱 자리가 뒤바뀐 경우를 못 잡는다.** 2.28%와 2.53%는 둘 다 범위 안이라 통과한다.
PrvText 는 표 구조가 사라진 평문이라 파서가 "퍼센트 토큰 12개의 순서"에 의존하므로,
고시가 열 순서를 바꾸면 **파싱은 성공하고 값만 틀린다**(조용한 오답 → 계상액 오류 → 판정 오류).

경계 연속성 검사로 바꾸면 잡힌다.

| 상황 | 5억 경계 차이 | 판정 |
|---|---|---|
| 정상 | +0.14% ~ +1.27% | 통과 |
| 건축↔토목 중간요율 뒤바뀜 | **+9.2%** | 차단 |
| 건축↔토목 5억미만요율 뒤바뀜 | **−0.16%(역전)** | 차단 |

**조건 = "상위 구간 계상액 ≥ 하위 구간 계상액, 단 차이 ≤ 3%".** 정상 최대가 1.27%라 여유가 충분하다.

## 조사 방법 메모

웹 문서로는 조달청·국세청 API 스펙이 **하나도** 안 나왔다(전부 첨부 HWPX·DOCX 안, law.go.kr·moel.go.kr 도 동일).

**스펙 문서가 안 열린다고 "없다"로 결론내면 안 된다** — 1차 초안이 "계상액 미개방"을 1순위로 올렸다가 뒤집혔다.
