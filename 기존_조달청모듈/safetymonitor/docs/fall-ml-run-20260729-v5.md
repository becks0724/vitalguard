## 1. 문제 추적

### 1-1. 경보를 올리는 주체는 `FallDetector` 하나

`MLFirstShadowPipeline` 은 `lastStatus` 문자열만 갱신하고 경보를 올리지 않는다(진짜 관전).
`MLFusion` 은 `work_veto` 가 확신할 때만 기각하고, 모델·윈도가 없으면 통과시킨다(fail-open).
따라서 오탐은 전부 규칙 판정이다.

### 1-2. 규칙의 세 조건이 전부 손목 하나로 충족된다

```
① totalG ≥ 2.8          → 툭 치면 넘음
② |G−1| < 0.3 이 1.2초   → 흔들고 손 내리면 충족
③ 회전 ≥ 6.0 rad/s      → 손목 스냅이면 넘음
```

임계 상향은 답이 아니다 — 낙상 peakG 중앙 3.08 vs 망치질 11.70 이라 올리면 낙상부터 사라진다.

### 1-3. 근본 원인 = 라벨

v4 낙상 173건의 peakG 분포: 최소 1.19 / 25% 1.99 / **중앙 3.08** / 75% 8.60 / 최대 30.12.
**절반 이상이 "조심 낙상"** 으로, 손목에서 보면 허벅지 한 번 치는 것보다 약하다.
이걸 양성으로 학습시켜 모델이 "약한 충격도 낙상"이라고 배웠다.

수집자별로도 갈린다 — A3 프로토콜(admin0740 중앙 2.34 · Worker7276 2.89) vs
무방어 수집(admin3470 6.83 · admin6861 6.12).

## 2. 기각된 가설 (재시도 금지)

전부 v4 586윈도에서 AUC로 측정했다. **넣기 전에 재보는 것**이 시간을 아낀다.

| 가설 | AUC(fall vs 전체 음성) | 기각 사유 |
|---|---|---|
| 자세 변화 각도(중력벡터 전후 각도차) | 0.568 | 걷기 90.7° > 낙상 89.0°. 팔 흔들며 걸으면 손목이 크게 돎 |
| 바뀐 자세 유지율 | 0.735(역방향) | 낙상 0.330 < 걷기 0.622. 넘어진 뒤 팔이 계속 정리됨 |
| 자유낙하 선행(충격 전 1초 최저 G) | 0.511 | 앉기 71.6% > 낙상 49.7%. 조심 낙상엔 자유낙하가 없다 |
| 순회전/총회전 비(`netRotRatio`) | 0.639 | **부분 성공** — 망치질 0.760 으로 기존 최고(peakRot 0.701) 상회. 특징 추가 후보로 보류 |

## 3. 변경

`src/contract.py`
```python
STRONG_FALL_G = 8.0

def label(self, task):
    if task == "impact":
        return int(self.family == FALL and self.peak_g >= STRONG_FALL_G)

def include(self, task):
    # 조심 낙상은 '음성'이 아니라 '제외'. 음성으로 넣으면 모델에게
    # "낙상을 기각하라"고 가르쳐 경계선의 진짜 낙상까지 눌린다.
    if task == "impact":
        return not (self.family == FALL and self.peak_g < STRONG_FALL_G)
    return True
```

`src/impact.py` · `src/export_coreml.py` — 학습 전 `include()` 필터. work_veto·recovery 불변.

## 5. 운영 배선 — 억제기(주 탐지기 아님)

임계를 올려도 정밀도가 0.51~0.56 에서 정체한다(thr 0.71 에서 재현율 0.293/정밀도 0.522).
**단독 경보 금지.** 규칙 후보 위에서 `p < 0.05` 면 취소하는 억제기로만 쓴다.

| 억제 임계 | 강한 낙상 죽임 | walk | sit | throw | hammer | pound |
|---|---|---|---|---|---|---|
| 0.02 | 2.4% | 96.6% | 93.2% | 82.0% | 42.5% | 69.0% |
| **0.05** | **4.9%** | **99.2%** | **100%** | **90.2%** | 50.7% | 74.7% |
| 0.10 | 17.1% | 99.2% | 100% | 93.4% | 75.3% | 78.2% |

0.10 은 망치질을 더 잡지만 낙상 미탐이 17% 로 뛰어 손해. **0.05 채택.**

## 6. ACK 자동 취소 (병행 요구)

경보 카운트다운 중 착용자 움직임이 감지되면 에스컬레이션 대신 자동 취소한다.
크게 다친 사람은 가만히 있고 오탐으로 뜬 사람은 계속 움직인다 — recovery 모델과 같은 논리이고,
**임계를 건드리지 않아 미탐 확률이 오르지 않는다.**

서버는 준비 완료 — `packages/schemas/src/vital-stream.ts` 의 `fallPromptOutcome` 에
`moved_cancelled` 가 이미 있다. 워치 enum 에는 없어 **워치 구현만 남았다**.

파라미터: `movementBandG 0.15` · `movementRotRadS 0.8` · `fallMovementGraceSec 1.5`.
grace 가 없으면 진짜 낙상도 자기 여진으로 취소되므로 필수.
상세 코드는 워치 인계 문서 참조.
