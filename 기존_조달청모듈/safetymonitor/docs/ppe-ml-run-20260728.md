# PPE 탐지 1차 학습 리포트 (2026-07-26 ~ 07-28)

CCTV 엣지 PPE(안전모·안전조끼·안전화) 탐지 모델의 **상용화 전 성능 테스트** 1차 경과.
현행 라이브 모델(CAM-03 Hexmon `vyra_ppe.pt`)을 교체할 수 있는지 숫자로 판정하는 것이 목적이다.

- 작업 폴더 — [ml/ppe-detection/](../ml/ppe-detection/README.md)
- 결정 근거 — [context-notes.md](../ml/ppe-detection/context-notes.md)
- 실행 절차 — [GUIDE.md](../ml/ppe-detection/GUIDE.md)

## 한 줄 요약

**1차 학습 완주. 젯슨 배포 가능성은 확정(yolo26m 17.1 fps). 단 교차 검증에서
"안전모 쓴 머리를 맨머리로 오탐"하는 결함이 드러나 2차 재학습이 필요하다.**

## 1. 설계 결정

### 통합 8클래스

```
0 person   1 head   2 helmet   3 safety_vest
4 foot     5 shoes  6 hands    7 gloves
```

**미착용을 별도 클래스로 두지 않는다.** `head`(맨머리)를 탐지하고 person 박스와의
포함관계로 코드에서 판정한다(`judge_ppe()`).

근거 — 미착용은 시각적 객체가 아니라 부정(negation)이라 클래스로 두면 각도·가림에 따라
`Hardhat` ↔ `NO-Hardhat` 을 오가며 깜빡인다. 현행 Hexmon 모델이 그 방식이다.
부수 효과로 CSS 데이터셋의 `NO-Hardhat` 라벨을 `head` 로 흡수해 데이터를 살린다.

### 데이터셋과 라이선스

| 데이터셋 | 규모 | 라이선스 | 상용 반입 |
|---|---|---|---|
| SH17 | 8,099장 / 75,994 인스턴스 | CC BY-NC-SA 4.0 | **불가** |
| Construction Site Safety (CSS) | 2,799장 | CC BY 4.0 | 가능 |
| Hard Hat Workers (HHW) | 7,035장 / helmet 19,744 | 공개 | 확인 필요 |

SH17 사용 시 산출 가중치에 **`-nc` 접미사가 자동으로 붙어** 상용 파이프라인 반입을 차단한다.
상용화 시에는 데이터만 교체해 재학습하도록 스크립트를 구성했다.

### 학습은 코랩, 엔진 변환은 젯슨

코랩은 x86 + 데이터센터 GPU라 여기서 만든 `.engine` 은 Jetson 에서 못 쓴다.
코랩 산출물은 `.pt` 까지이고, TensorRT 변환·INT8 캘리브레이션은 타깃 젯슨에서 한다.

## 2. 젯슨 배포 판정 — ✅ 확정

### 환경 정비 (2026-07-27, Tailscale 원격)

| 항목 | 정리 전 | 정리 후 |
|---|---|---|
| 여유 RAM | 1.4GB | **2.8GB** |
| 여유 디스크 | 9.0GB (95%) | **50GB (68%)** |

조치 = 헤드리스 전환(GUI 종료, 약 950MB 확보) + ollama 모델 40GB·apt 캐시 삭제.
Docker 이미지 30GB 는 사용자 선택으로 보존.

확정 사양 — **Orin Nano Super 4GB** · JetPack 6.2(L4T R36.4.3) · TensorRT 10.7.0 ·
torch 2.5.0a0+nv24.08(CUDA True) · **DLA 없음** · 전력 **MAXN_SUPER** ·
스왑 8GB 파일 + zram 1.8GB(이미 구성됨).

### 성능 실측 (TensorRT FP16 @960)

| 모델 | PyTorch | **TensorRT** | 개선 | 엔진 | 빌드 |
|---|---|---|---|---|---|
| yolo26s | 16.8 fps | **27.0 fps** (37ms) | 1.61× | 22MB | 561초 |
| **yolo26m** | 12.0 fps | **17.1 fps** (58ms) | 1.43× | 43MB | 706초 |

**yolo26m 이 목표선(≥10 fps)의 1.7배 → 원래 쓰려던 모델 그대로 배포 가능.**

### 남은 확인

위 수치는 **카메라 파이프라인이 꺼진 상태**다. m 추론 중 여유 메모리가 724MB 까지
떨어지고 스왑을 1.5GB 썼다. ROS2 Orbbec + 푸셔를 켠 상태에서 재측정해야 최종 판정이 선다.
빠듯하면 s(27fps·22MB)로 내리면 된다.

### 함정 — 엔진 빌드는 GUI 를 끄고 해야 한다

GUI 를 켠 채 빌드하자 GPU 가용이 107MB(필요 225MB)까지 떨어져 TensorRT 가
최적 커널을 931회 건너뛰었다. 그대로 두면 **성능이 저평가된 가짜 숫자**가 나온다.
`sudo systemctl isolate multi-user.target` 으로 내리고 빌드해야 한다.

## 3. 1차 학습 — yolo26s · 640 · 25 에포크

### 실행 조건

코랩 T4 Pro · `batch 16` · **12.345시간** · 학습 12,591장(SH17 9,933 + CSS 2,658) →
train 11,521 / val 970.

**960 → 640, batch -1(AutoBatch) → 16 으로 바꾼 것이 결정적이었다.**
960 + AutoBatch 는 에포크당 31분이라 60 에포크 완주가 불가능했다(77시간 추정).
GPU 메모리가 4.3/15GB 로 71% 놀고 있던 것이 원인.

### 결과

| 클래스 | val 인스턴스 | Recall | mAP50 | mAP50-95 |
|---|---|---|---|---|
| all | 5,733 | 0.651 | 0.676 | 0.447 |
| person | 1,662 | 0.867 | 0.901 | 0.712 |
| head | 1,282 | 0.874 | 0.903 | 0.680 |
| hands | 1,559 | 0.791 | 0.844 | 0.572 |
| shoes | 505 | 0.612 | 0.667 | 0.382 |
| helmet | **169** | 0.628 | 0.590 | 0.358 |
| safety_vest | **90** | 0.567 | 0.550 | 0.331 |
| gloves | 361 | 0.499 | 0.545 | 0.330 |
| foot | 105 | 0.371 | 0.407 | 0.213 |

### 안전화 — 이번 단계 목표 달성

`shoes` 0.612 / `foot` 0.371. 640 해상도 원거리에서도 신발이 61% 잡힌다.
**국내 재라벨링 투자 가치가 있다는 근거**가 확보됐다.

## 4. 교차 데이터셋 홀드아웃 — ★ 결론을 바꾼 검증

실 현장 영상을 확보하지 못해, **학습에 쓰지 않은 제3의 출처**로 일반화를 측정했다.
홀드아웃 = Hard Hat Workers (`joseph-nelson/hard-hat-workers`).

### 함정 두 개를 먼저 걷어냈다

**① v14 는 클래스가 병합돼 있다** — 내보내기 클래스가 `['head']` 하나뿐.
인스턴스 26,424 = 원본 helmet 19,747 + head 6,677 과 정확히 일치해 확인됐다.
안전모 쓴 머리도 `head` 로 라벨돼 있어 우리 모델이 `helmet` 으로 맞혀도 전부 오답 처리된다.
→ 이 버전으로 낸 "62.4% 하락"은 **허상**이었다.

**② v13 은 증강본이다** — 원본 7,035장 → 16,866장(2.4배). 회전·cutout·흑백이 걸려 있고
사무실 실내 장면까지 섞여 있다. Roboflow 는 `train` 만 증강하므로
**`valid`/`test` 원본(2,119장)만** 써야 공정하다.

증강 포함 → 제외로 바꾸자 head 83.7%→70.4%, helmet 35.7%→19.3% 로 개선됐다.

### 공정 조건 결과 (2,119장 · helmet 5,828 / head 2,065)

| class | R_인도메인 | R_교차 | 하락률 | P_교차 | mAP50_교차 |
|---|---|---|---|---|---|
| **helmet** | 0.633 | 0.511 | **19.3%** | 0.524 | 0.383 |
| **head** | 0.874 | 0.259 | **70.4%** | **0.181** | 0.130 |

판정 기준 — 10% 미만 양호 / 10~30% 보통 / 30% 초과 과적합.

### 진단 — 원인이 특정됨

핵심 지표는 recall 이 아니라 **head precision 0.181**(예측한 head 의 82%가 오답)이다.
홀드아웃은 helmet 이 74%인 데이터인데 여기서 head 오탐이 쏟아진다는 것은 하나를 뜻한다.

> **모델이 안전모 쓴 머리를 `head`(맨머리)로 예측하고 있다.**

helmet recall 이 0.511 이라 못 잡은 자리를 head 로 채운다.
학습 데이터가 `head 14,413 : helmet 4,478 = 3.2 : 1` 로 맨머리에 치우친 직접 결과다.

육안 확인에서도 크고 선명한 노란·빨간 안전모를 쓴 작업자를 `person` 으로만 잡고
헬멧을 놓치는 사례가 반복 관찰됐다.

### ★ 판단 정정

1차 결과 직후 "안전모는 구조적으로 안전 — 헬멧을 놓쳐도 맨머리가 안 잡히면
위반으로 안 센다"고 기록했으나 **틀렸다.** 모델이 헬멧 쓴 사람에게 적극적으로 `head` 를
예측하므로 `judge_ppe()` 의 `맨머리 AND 헬멧없음` 두 조건이 동시에 성립한다.

**실사용 시 안전모 착용 작업자가 미착용 위반으로 오탐된다.**
안전조끼 recall 0.567 과 합쳐 **현 상태로는 관제 투입 불가.**

### 이 검증의 가치

인도메인 val 만 봤다면 `head recall 0.874` 로 "충분하다"고 판단하고 배포했을 것이다.
현장 영상 부재를 메우려 넣은 교차 홀드아웃이 정확히 제 역할을 했다.

## 7. 교훈

- **공개 홀드아웃은 "버전별 클래스 구성"과 "증강 여부"를 먼저 확인해야 한다.**
  둘 다 확인 없이 쓰면 결론이 정반대로 나온다(62.4% 허상 → 70.4% → helmet 은 19.3%).
- **인도메인 val 성적은 낙관 편향이다.** 같은 분할에서 helmet 은 169개, vest 는 90개뿐이라
  신뢰구간이 넓었고, 교차 검증에서야 실체가 드러났다.
- **코랩 ETA 표시는 실제보다 빠르다.** 순간 속도라 정체를 반영하지 않는다.
  누적 경과 시간이나 완료된 에포크의 실제 소요로만 판단해야 한다.
- **AutoBatch(`batch=-1`)를 맹신하지 말 것.** GPU 를 71% 놀린 채 3배 느리게 돌았다.
- **엔진 빌드는 메모리를 추론보다 훨씬 많이 쓴다.** 4GB 젯슨에서는 GUI 를 내려야 한다.
- **`pip install -U ultralytics` 는 NVIDIA 빌드 torch 를 덮어써 CUDA 를 죽인다.**
  젯슨에서는 `--no-deps` 필수.
- **학습이 끝난 뒤에는 코랩 런타임이 90분 유휴로 회수된다.** 학습 중에는 실행 중이라
  안 죽지만, 끝난 뒤 자리를 비우면 `/content` 데이터가 사라진다.
