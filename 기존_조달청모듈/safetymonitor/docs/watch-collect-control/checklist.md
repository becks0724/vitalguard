# 수집 제어를 폰으로 옮긴다 — 계획·체크리스트

**사용자 결정(2026-08-22).** *"워치에서는 수집/중지 버튼을 만들지 않는다. 폰 앱에서 수집/중지 기능을 만든다."*

## 무엇을 왜

**왜 지금인가.** 08-20·08-21 두 번, 세션이 `session_end_by_user = 1` 로 끝났는데 **사용자는 누른
적이 없었다**. 두 번째는 수집이 **5시간 넘게** 죽어 있었다(18:21:21 → 다음 날 10:03).
원인은 아직 모른다. 후보가 둘인데 2회 관측으로 안 갈렸다.

```
ⓐ 오탭          확인 다이얼로그까지 두 번 눌렸다
ⓑ 플래그 오작동   stop() 이 안 불렸는데 stopRequestedByUser 가 섰다
```

**이 변경은 ⓐ 면 고치고, ⓑ 면 확정한다.** 워치에서 버튼을 없애면 ⓐ 가 물리적으로 불가능해지고,
그래도 `seBy=1` 이 뜨면 ⓑ 다. 2회 관측으로 못 한 판별을 구조가 대신한다.

**★ 그리고 이 결정이 자동 시작을 강제하는데, 그게 이 트랙의 원래 결함을 없앤다.**
워치에 시작 버튼이 없으면 재기동 시 켤 수단이 없다 ⟹ 기동하면 스스로 시작해야 한다.
`watch-counterpart-not-installed` 메모가 적어 둔 *"안 누르면 수집이 영구 정지한다"* 가 사라진다.

## 성공 기준 (약한 기준을 쓰지 않는다)

```
① 워치 화면에 버튼이 0개다 — confirmationDialog 도 사라진다
② 워치 앱을 강제종료했다 다시 열면 수집이 스스로 시작한다 (intent=run 일 때)
③ 폰에서 중지 → 워치가 실제로 멎고, 폰에 성공이 표시된다
④ 폰이 안 닿을 때 중지를 누르면 폰에 실패가 명시된다 (조용한 실패 0)
⑤ 워치 앱을 다시 열어도 ③ 뒤에는 자동 시작하지 않는다 (intent=stopped 존중)
⑥ DB 에 stopSource 가 실려 "폰 명령"과 "출처 불명"이 갈린다
```

## 설계 요지

### 상태는 세션이 아니라 **의도**다

워치 `UserDefaults` 에 하나.

```
collect.intent = "run" | "stopped"      초기값 "stopped" (갓 설치가 멋대로 수집하면 안 된다)

앱 기동         intent == "run"     → 자동 시작
                intent == "stopped" → 대기
폰 중지 명령 검증 통과 → "stopped"
폰 시작 명령 검증 통과 → "run"
그 밖의 모든 종료(크래시·젯샘·재설치·플래그 오작동) → intent 를 안 건드린다 = "run" 유지
```

**마지막 줄이 핵심이다.** 의도된 중지만 자동 시작을 막는다. 08-21 같은 일이 또 나도 워치 앱이
다시 뜨는 순간 수집이 살아난다.

### 상하행 비대칭

```
중지   sendMessage 한정 + replyHandler ack
       ⚠ transferUserInfo 금지 — 큐라서 늦게 도착한 중지가 **다음 세션을 끈다**.
         그건 지금 버그를 새 형태로 재현하는 것이다.
       ack 없으면 폰이 "워치에 못 닿았습니다 — 다시 시도" 를 띄운다.

시작   sendMessage → 실패 시 transferUserInfo 폴백
       늦게 켜지는 것은 무해하다. 워치 앱이 안 떠 있어도 다음 기동에 전달된다.
```

명령에 **대상 세션**을 실어 보내고, 워치는 지금 세션과 다르면 무시한다.

### 경로

```
lib/settings_screen.dart
  → MethodChannel "vitalguard/bridge"        (VitalBridge.swift:88)
  → WCSession.sendMessage(replyHandler:)      ← 폰에 송신 능력 신설 (지금은 수신 전용)
  → WatchStreamer.session(_:didReceiveMessage:replyHandler:)  ← 워치에 수신 경로 신설
                                                (지금 didReceive* 0건)
  → intent 영속 + start()/stop()
```

### 비상구는 만들지 않는다

폰이 죽으면 종료를 못 한다. 다만 **앱 강제종료가 수집을 멈춘다**(08-21 실측).
옆 버튼 길게 → Digital Crown 길게라 오탭이 날 구조가 아니다.
⚠ **별도 비상 버튼을 만들지 않는다** — 만드는 순간 오탭 표면이 되돌아온다.

## 체크리스트

### 0단계 — 착수 전 재측정 ([[L-107]])
- [ ] `seBy=1` 오탐이 그사이 또 났는지 DB 로 확인 (근거가 살아 있나)
- [ ] 워치 `didReceive*` 0건 · `onAppear` 자동시작 0건 재확인 (전제가 그대로인가)

### 1단계 — 워치 (수신·의도·자동 시작)
- [ ] `WatchStreamer` 에 `session(_:didReceiveMessage:replyHandler:)` 신설
- [ ] 명령 검증 — 타입·대상 세션 대조. 안 맞으면 무시하고 ack 에 사유를 담는다
- [ ] `CollectIntent` 영속(UserDefaults) — 폰 명령 경로에서만 쓴다
- [ ] 기동 시 자동 시작 — `intent == "run"` 일 때만
- [ ] 종료 지문에 `stopSource` 추가 (`"phone"` / 없음)
- [ ] 검증 = 강제종료 후 재기동에 자동 시작하는지 실기기 확인

### 2단계 — 워치 화면 (버튼 제거)
- [ ] `ContentView` 버튼·`confirmationDialog` 삭제, 상태 표시만 남긴다
- [ ] 대기일 때 "폰 앱에서 시작하십시오" 한 줄
- [ ] 검증 = 화면에 탭 가능한 요소가 0개

### 3단계 — 폰 (송신·UI)
- [ ] 폰에 WCSession 송신 추가 (지금은 수신 전용)
- [ ] MethodChannel 에 `startCollect` / `stopCollect` 노출
- [ ] `settings_screen.dart` 에 수집 시작/중지 + 현재 상태
- [ ] 실패 표시 — ack 없으면 명시. 조용한 실패 금지
- [ ] 검증 = 워치 앱을 끈 상태에서 중지를 눌러 실패가 뜨는지

### 4단계 — 가드 (신규 1건)
- [ ] 메시지 키 계약 양끝 집합 대조 (A·B 가드와 같은 방식)
- [ ] **중지 경로에 `transferUserInfo` 가 없다** — 큐 금지를 코드로 못 박는다
- [ ] 대상 세션 대조가 있다
- [ ] `intent` 4중주 — 영속 · 기동 시 읽음 · 자동 시작 분기 · 폰 명령이 씀
- [ ] `stopSource` 4중주 — 워치 기록 · 봉투 · 컬럼 · **읽는 경로** ([[L-101]])
- [ ] 워치 `ContentView` 에 `Button` 이 0개다
- [ ] 변이 시험 — 각 단언마다 실제로 빨개지는지 + 음성 대조 + 기준선 PASS ([[L-103]])

### 5단계 — 설치 (08-26 재서명 창)
- [ ] ⚠ 워치 소스 변경이라 이 창에 묶는다 ([[L-100]]) — 따로 내면 리셋이 두 번 난다
- [ ] 설치 후 실기기 검증 = 성공 기준 ①~⑥ 전부
- [ ] 설치 시각을 기록 — 세션 경계 판정에 쓴다

## 열린 위험

- ⚠ **ⓑ 라면 이 변경으로 안 고쳐진다.** 버튼이 없어도 플래그가 서면 수집은 멎는다.
  ⟹ **`seBy=1` 이 자동 재개를 영구 봉인하는 것**(`WatchStreamer.swift:856`)을 함께 완화할지가
  별도 결정이다. 안 하면 ⓑ 일 때 아무것도 안 고쳐진다. **미결 — 사용자 결정 대기.**
- ⚠ 퇴근 시 폰이 방전이면 밤새 수집이 돈다. 비상구 = 앱 강제종료.
- ⚠ 워치가 안 닿으면 중지가 안 간다. 폰이 도달 복구 시 재시도해야 한다.
- ⚠ 수신 경로 신설은 **수집을 끌 수 있는 새 표면**이다. 큐 금지·세션 대조가 그 방어선이고,
  둘 다 가드로 못 박는다.
