# 수집 제어 이관 — 결정과 근거

작업 중 내린 결정을 근거와 함께 쌓는다. 나중에 "왜 이렇게 했나" 를 다시 묻지 않기 위해서다.

## R-01 · 왜 워치 버튼을 없애는가 — 판별 불가에서 나왔다

두 번 관측했는데 원인이 안 좁혀졌다.

```
08-20 14:36:09   seBy=1   사용자는 누른 적 없음
08-21 18:21:14   seBy=1   사용자는 누른 적 없음 · 수집 5시간 정지
```

`stop()` 의 호출부는 확인 다이얼로그를 거치는 **두 번 탭** 하나뿐이다. 그런데도 섰다.
후보 ⓐ 오탭 / ⓑ 플래그 오작동 — **관측으로는 못 가른다.** 지문이 같기 때문이다.

⟹ **구조를 바꿔서 가른다.** 버튼이 없으면 ⓐ 는 물리적으로 불가능하다.

## R-02 · 30초 유예는 무동작이다 (코드 판정 · 08-22)

`406bcaf` 가 오탐을 막으려 붙인 유예가 왜 08-21 을 못 걸렀나.

```swift
func stop() {
    stopRequestedByUser = true
    stopRequestedAt = Date()     // ← 같은 호출에서 함께 선다
}
private var endedByUser: Bool {
    guard stopRequestedByUser, let at = stopRequestedAt else { return false }
    return Date().timeIntervalSince(at) <= userStopGraceSec   // 30초
}
```

유예는 **낡은 플래그**만 거른다. 그런데 `beginWorkout` 이 매 세션 시작에 둘 다 리셋하므로
(`WatchStreamer.swift:326-327`) **낡은 플래그가 생길 수 없다.** 플래그가 엉뚱하게 서면 시각도
함께 엉뚱하게 서서 그대로 통과한다.

⟹ `seBy = 0` 은 이 구조에서 나올 수 없다. C-1 이 기다리던 표본은 **부재**였다.
   (`docs/gps-phone-collection/checklist.md` 정정 완료)

## R-03 · 시작도 폰으로 옮긴다 — 그래서 자동 시작이 필수가 된다

처음 제안은 *"시작은 워치에 남긴다"* 였다. 근거 = 재기동 후 유일한 복구 수단이고,
기존 주석도 *"켜는 쪽은 오탭이어도 손해가 없다"* 고 적고 있다.

**사용자 결정은 둘 다 옮기는 것이다.** 그러면 재기동 시 켤 수단이 사라지므로
**워치가 기동 시 스스로 시작해야 한다** — 선택이 아니라 강제다.

★ 그런데 그것이 이 트랙의 **원래 결함**을 없앤다.

```
watch-counterpart-not-installed 메모
  "재개가 수동 — 시작 지점이 화면 버튼 하나뿐이고 .onAppear 자동 시작이 없다.
   사람이 워치에서 시작을 눌러야 하고, 안 누르면 수집이 영구 정지한다"
```

⟹ 결정이 부작용으로 숙제를 푼다. **제 앞선 권고보다 이쪽이 낫다.**

## R-04 · 상태를 세션이 아니라 "의도" 로 둔다

자동 시작을 그냥 켜면 **폰에서 끈 다음에도** 워치 앱을 열 때마다 다시 켜진다.
그래서 무엇을 기억할지가 설계의 전부다.

```
기억할 것 = "사람이 끄기를 원했는가"      (의도)
기억하지 말 것 = "세션이 어떻게 끝났는가"  (사건)
```

의도는 **폰 명령 경로에서만** 쓴다. 크래시·젯샘·재설치·플래그 오작동은 의도를 안 건드린다.
⟹ 08-21 같은 일이 또 나도 앱이 다시 뜨는 순간 살아난다.

⚠ 초기값은 `"stopped"` — 갓 설치한 앱이 사람 의사 없이 수집을 시작하면 안 된다.

## R-05 · 중지에 큐를 쓰지 않는다 — 지금 버그를 재현하기 때문이다

수신 경로를 새로 여는 것은 **수집을 끌 수 있는 새 표면**을 만드는 일이다.
`transferUserInfo` 는 큐라서 몇 분 뒤·다음 세션에 도착할 수 있다.
늦게 도착한 중지가 다음 세션을 끄면 그것은 **"의도하지 않은 수집 정지"** — 지금 고치려는 바로 그 증상이다.

```
중지  sendMessage 한정 + replyHandler ack   안 닿으면 그 자리에서 실패를 알린다
시작  sendMessage → 실패 시 큐 폴백          늦게 켜지는 것은 무해하다
```

비대칭이 옳다. **끄기는 즉시성과 확인이 필요하고, 켜기는 안 그렇다.**
대상 세션을 함께 실어 보내 지연 도착을 한 번 더 막는다.

## R-06 · 조용한 실패를 만들지 않는다

이 레포에서 반복된 사고 형태가 *"눌렀는데 아무 일도 안 일어나고 화면은 정상"* 이다.
`replyHandler` ack 를 받아야만 성공으로 표시한다. 못 받으면 명시한다.

## R-07 · 비상 버튼은 만들지 않는다

폰이 죽으면 못 끈다. 그러나 **앱 강제종료가 수집을 멈춘다**(08-21 프로세스 관측으로 확인).
옆 버튼 길게 → Digital Crown 길게라 오탭 구조가 아니다.
비상 버튼을 만드는 순간 **없애려던 오탭 표면이 되돌아온다.** 만들지 않는다.

## R-08 · 미결 — seBy=1 의 영구 봉인을 완화할 것인가

`WatchStreamer.swift:856` 의 `if !byUser` 가드 때문에 `seBy=1` 이면 자동 재개를 **통째로 건너뛴다**.
오탐 한 번이면 사람이 알아챌 때까지 멎는다. 08-21 이 그 5시간이었다.

⚠ **이 변경만으로는 ⓑ(플래그 오작동)가 안 고쳐진다.** 버튼이 없어도 플래그가 서면 멎는다.
⟹ 완화를 함께 넣을지가 별도 결정이다. **사용자 결정 대기.**

## R-09 · 판별을 살리려면 stopSource 가 필요하다

폰 명령도 결국 `stop()` 을 부르므로 정상 종료도 `seBy=1` 이 된다. 그대로 두면 판별이 다시 막힌다.

```
seBy=1 · source="phone"  → 정당한 종료
seBy=1 · source 없음     → ★ 워치에 버튼이 없는데 플래그가 섰다 = ⓑ 확정
```

⚠ 넣을 때 **읽는 경로를 먼저 지목한다** ([[L-101]]). 못 지목하면 또 쓰기 전용 컬럼이 된다 —
이 레포에 그 잔해가 이미 있다.
