> **본 프로토타입은 기술 검증 단계이며, 상용화 시점에 위 4종 컴플라이언스를 법률 자문 하에 구현한다.**

- 작업자 동의서·KOSHA 보고서·감사 로그 등의 *완전한 구현* 은 [발표 후 로드맵 M8](./checklist.md) 에서 진행
- 상세 법규 분석·자문 질문 리스트 15개·미해결 항목 24건은 본 문서 하단 본문 참조

### 위험 감지 5종 — 임계값 출처 면책

| 카테고리 | 임계값 | 출처 / 비고 |

## 1. 산업안전보건법 (KOSHA)

### 핵심 의무 [확인 필요]
- **위험성 평가** — 사업주는 작업장의 위험요인을 평가·관리할 의무
- **실시간 위험 모니터링** — 고위험 작업장은 실시간 감지·대응 체계 권고
- **사고 발생 시 보고** — 중대재해 발생 시 고용노동부 보고 의무 (중대재해처벌법 연계)
- **기록 보존** — 사고·작업환경측정 기록 보존 의무 ([확인 필요] 보존 기간 정확히)

### 본 시스템 영향
- 서비스 *목적 자체*. 본 시스템이 KOSHA 의무 이행을 디지털로 보조한다는 포지셔닝.
- 사고 발생 시 본 시스템의 시계열 데이터·HazardEvent 로그가 *증빙 자료* 가 될 수 있음.

### 필요 조치
- `HazardEvent` 모든 이벤트 보존 기간 3년 이상 (사고 데이터)
- `AuditLog` — 관제자 액션 (조회·해결·삭제) 전체 로깅
- KOSHA 사고 보고서 양식에 맞춘 PDF 출력 기능 (M8)
- 본 시스템 도입이 *위험성 평가 의무를 대체하지 않음* 을 계약서·UI 에 명시

### 미해결 [법률 자문]
- [ ] KOSHA 가 "실시간 위험 모니터링" 을 *권고* 인지 *의무* 인지 — 업종별·규모별 차이
- [ ] 사고 데이터 보존 기간 정확한 연수 (3년 / 5년 / 영구)
- [ ] 본 시스템 데이터가 산업재해 보상 청구 시 증거로 채택될 요건
- [ ] 중대재해처벌법상 *경영책임자* 의무와 본 시스템의 관계

## 2. 개인정보보호법

### 핵심 의무 [확인 필요]
- **민감정보 별도 동의** — 건강·생체정보는 일반 개인정보와 별도 명시적 동의 필요
- **수집 최소화 원칙** — 목적 달성에 필요한 최소한만 수집
- **보존 기간 명시·파기** — 목적 달성 후 즉시 파기 (예외 시 근거 명시)
- **안전성 확보 조치** — 암호화·접근 통제·접속 기록
- **정보 주체 권리** — 열람·정정·삭제·동의 철회권

### 본 시스템 영향 (가장 영향 큼)
- 심박·SpO₂·체온·위치·가속도 = **민감정보 (건강·생체정보)**
- 작업자 = 정보 주체. 사업주 = 개인정보 처리자 (위탁자). 본 서비스 = 수탁자.
- 위·수탁 계약 필수.

### 필요 조치
- **수집 동의**. 작업자 onboarding 시 명시적 동의 (디지털 서명) — `Worker.consentAt` 필드
- **암호화**. 전송 (TLS 1.3) + 저장 (AWS KMS)
- **접근 통제**. Cognito 역할 분리 (admin/operator/readonly) + AuditLog
- **보존 기간**. 일반 vital 1년 / 사고 데이터 3년 (KOSHA) / 익명화 후 통계 영구
- **동의 철회**. 작업자 요청 시 익명화 cron 자동 실행. 단 사고 데이터는 KOSHA 보존 의무로 익명화 불가 — 동의서에 사전 고지.
- **파기**. 보존 기간 경과 시 자동 파기 (DDB TTL + S3 lifecycle)
- **개인정보 처리방침** 공개 (웹사이트)

### 미해결 [법률 자문]
- [ ] 위치 정보가 *민감정보* 인지 *일반 개인정보* 인지 (위치정보법 별도 적용 여부)
- [ ] 위·수탁 계약 표준 양식 — 사업주·본 서비스 간
- [ ] 익명화 후에도 *재식별 가능성* 이 있을 때 어디까지 안전한지
- [ ] 작업자 동의가 *사업주 강요성* 이라 무효 주장 가능한 경우 대응
- [ ] 해외 협력사·해외 출장 시 *국외 이전* 동의 필요 여부

## 3. 근로기준법

### 핵심 의무 [확인 필요]
- **사생활 보호** — 업무 외 시간·장소에서의 모니터링 제한
- **근로감시 사전 협의** — 사업장에 모니터링 시스템 도입 시 노사 협의 의무 ([확인 필요] 정확한 조항)
- **취업규칙 변경** — 근로조건 변경에 해당하면 근로자 과반수 동의 필요

### 본 시스템 영향
- 작업자 입장에서 *상시 모니터링* 은 사생활 침해 우려.
- 업무 외 시간 (출퇴근·휴식·점심) 데이터 수집 범위가 핵심 쟁점.

### 필요 조치
- **수집 시간대 제한**. 근무 시간만 수집 — 작업자 단말에서 출퇴근 기록 연계해 publish on/off
- **위치 정확도**. 작업장 단위로만 (정확한 좌표 X — 작업장 polygon 안/밖만)
- **개별 화면 표시 금지**. 관제자 화면에 *상세 행동 패턴 분석* 표시 안 함
- **작업자 본인 데이터 열람권** — 본인 watch 화면에서 자기 데이터 확인 가능
- **취업규칙 변경 동의** — 사업주 → 작업자 절차. 본 서비스 가이드 제공
- **노사 협의록** — 사업주 측 의무. 본 서비스는 양식 제공.

### 미해결 [법률 자문·노무사]
- [ ] *근로감시* 의 법적 정의 — 본 시스템이 해당하는지
- [ ] 야간·휴일 근무 시 모니터링 범위
- [ ] 작업자가 단말 착용 거부 시 사용자 (사업주) 의 징계권
- [ ] 노조 있는 사업장 vs 없는 사업장 — 동의 절차 차이
- [ ] *행위 분석* (예. 음주·졸음 감지) 향후 추가 시 추가 동의 필요 여부

## 4. 의료기기법

### 핵심 의무 [확인 필요]

- **인증·신고** — 의료기기는 식약처 (MFDS) 등급별 인증·신고 필수
- **표시·광고 제한** — 미인증 제품의 의료적 효과 표시·광고 금지

### 본 시스템 영향
- 본 서비스를 *의료기기로 인증받지 않음* (1차 비범위). 따라서 의료적 주장 일체 금지.
- 위험 — UI 문구·마케팅·고객 응대 어디서든 "진단" / "치료" / "예방" 단어 사용 시 위법 가능.

### 필요 조치
- **UI 문구 가이드라인** — *알림 · 경고 · 위험 신호 · 안전 보조 정보* 만 허용. *진단 · 치료 · 처치 · 의료 정보* 금지.
- **마케팅 검토 체크리스트** — 모든 외부 노출 문구는 법무 검토
- **고객 응대 매뉴얼** — 의료 효과 문의에 *우리는 의료기기 아님* 응답 강제
- **응급 상황 면책 명시** — *본 시스템은 119 호출을 대체하지 않습니다* 동의서·UI 명시
- **알고리즘 설명 시** — *통계적 패턴 감지* 표현. *진단* 표현 금지.

### 미해결 [법률 자문 / MFDS 사전 상담]
- [ ] 낙상 감지·심박 이상 알림이 *의료기기 소프트웨어 (SaMD)* 에 해당하는지
- [ ] *위험 신호 감지* vs *진단* 의 법적 경계선
- [ ] 향후 2차에서 ML 도입 시 인증 의무 발생 시점
- [ ] Apple Watch · Galaxy Watch 의 *의료기기 인증 기능* (예. ECG) 을 본 시스템이 사용하면 책임 소재

## 5. 정보통신망법 · 클라우드 컴퓨팅법

### 핵심 의무
- **안전성 확보 조치** — 암호화·접근 통제·접속 기록·취약점 점검 [확인 필요]
- **침해 사고 신고** — 개인정보 유출 시 24시간 내 KISA·정보 주체 통지 [확인 필요]
- **클라우드 보안 인증 (CSAP)** — 공공 부문 납품 시 필요 (1차 비범위)

### 필요 조치
- **TLS 1.3** — 디바이스 ↔ AWS IoT Core
- **AWS KMS** — 저장 데이터 암호화
- **CloudTrail · CloudWatch** — 접속 기록·감사 로그
- **취약점 점검** — 정기 (분기 1회 권장)
- **침해 사고 대응 절차** — 사전 문서화 (M8)

### 미해결
- [ ] 본 서비스가 *정보통신서비스 제공자* 에 해당하는지 (사용자 ≠ 일반 대중)
- [ ] AWS Region 한국 (ap-northeast-2) 사용 시 데이터 주권 100% 충족인지
