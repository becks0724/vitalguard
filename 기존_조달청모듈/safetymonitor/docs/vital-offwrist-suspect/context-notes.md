# 벗음 의심 라벨 — 컨텍스트 노트

2026-08-28 밤 · 사용자 결정 "D 진행". 근거 실측·전수검사는 [vital-still-label/context-notes.md](../vital-still-label/context-notes.md) 08-28 밤 절.

## 무엇을 왜
- 벗은 애플워치의 심박은 **평평하다**(5분 창 SD ≤ 2.9 · 연속 표본 차이 평균 ≤ 1.03 · 벗음 7창 전수). 착용 p50 은 SD 3.04 · 1.25.
- 그러나 착용-정지 창의 29% 가 한 창 기준으로 벗음처럼 보인다 → **경보로는 못 쓴다.** 표시로만 쓴다(같은 규율의 선례 = `수신 중`·`심박끊김/연결끊김`·`무동작`).
- 사용자 현장 논리 — 일하는 사람의 심박이 15분 평평한 것은 그 자체로 확인 대상. 착용 1019창은 전부 책상 근무자 데이터라 현장 오탐은 이보다 낮을 가능성이 크지만 **아직 안 쟀다**.

## 규칙 (표시 전용)
```
flat(창)   = 5분 창 심박 표본 n ≥ 30 ∧ SD ≤ 2.5 ∧ 연속차 평균 ≤ 1.0      (n < 30 이면 판정 불가 → 중단)
벗음 의심  = 지금부터 거꾸로 flat 창 3개 연속(15분)                        ← 서버가 계산
화면       = `무동작 N분` 이 떠 있을 때만 그 아래 `벗음 의심` 한 줄         ← 평평 ∧ 정지 (활동 중 평평 = 착용 작업, 제외)
```
- 문턱 근거 = 전수검사 표(SD≤2.5 ∧ 연속차≤1.0 → 벗음 6/7 · 착용 오탐 11.7% · 15분 연속이면 12일에 착용 run 5건, 그중 2건은 벗음 의심).
  ⚠ 미탐 축은 분모 7 이라 문턱은 **방향값**이다. 현장 데이터가 생기면 다시 잰다.
- `n ≥ 30` 이 갤럭시(120초 주기 · 창당 ≤ 3표본)를 자연히 제외한다 — 갤럭시는 하드웨어 off-body 로 벗음이 `대기` 로 이미 잡힌다(지시 ③ 양쪽 적용 = 규칙은 출처 중립, 갤럭시는 판정 불가로 떨어짐).
- 재착용 복귀 하한 ~1분(센서 재획득 50초 · n=1)보다 훨씬 긴 15분이라 정상 재착용이 이 라벨을 거쳐 가지 않는다.

## 계산 위치 — 서버(`store.ts` · `heatStages` 골격 그대로)
- 화면은 최신 표본 하나만 받고, 인메모리 ring(500표본)은 애플워치가 늘면 15분을 못 덮는다 → **DB `recentHeartRates(15)` + 60초 캐시**로 워커별 맵을 만들어 GET 에 `offWrist` 로 싣는다. 온열 단계(`heatStage`)와 같은 골격(무상태 재계산·캐시·실패 시 표시 생략).
- DB 부하 = 1분에 1회 15분 창 조회(온열 단계의 180분 창보다 작다).

## 판정 불변
- 톤·게이트·집계·경보·`signalLevel` 은 이 값을 모른다. `recordAlert`·텔레그램·env_alert_state 어디에도 안 닿는다.
- 라벨 글자는 `OFFWRIST_LABEL` 한 곳. 가드 + 변이 시험(L-113).

## 하지 않는 것
