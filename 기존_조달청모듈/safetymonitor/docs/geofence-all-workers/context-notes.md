# 구획 이탈 알림 — 전 작업자 적용 (2026-08-27)

## 발단
사용자 제보 — 텔레그램에 `📍 현장 구획 이탈`이 장우진(EMP-6861)에게만 왔고 김태곤(EMP-admin3470)에게는 안 왔다.
요구사항 = **특정 작업자가 아니라 전체 작업자의 GPS 기준으로 동일하게 가동**되어야 한다.

## 확정된 사실 (코드·DB·재현 3겹)

### 1. 두 사람 다 실제로 이탈했다
현장 중심 = **등록 주소 지오코딩** `광주광역시 동구 중앙로 196` → `35.150500, 126.916166`. 반경 100m.

| | GPS 표본 | 이탈(>110m) | 최대 거리 | 3연속 이상 구간 | 실제 알림 |
|---|---|---|---|---|---|
| 장우진 (watchOS) | 4,538 | 707 (15.6%) | 386m | 1 | **1건** |
| 김태곤 (WearOS) | 97 | 23 (23.7%) | 482m | 2 | **0건** |

⚠ **처음 조사에서 중심을 틀리게 잡았다.** `site_coord_daily`(35.156, 126.925)를 중심으로 써서
"둘 다 100% 이탈 · 1km" 라는 값이 나왔다. 그것은 **주소가 없을 때의 폴백**이고 실제 중심에서
**1,009m** 떨어져 있다. 중심은 `siteAnchor(주소 지오코딩) ?? cachedCoord ?? effLat/effLon` 순서다.
**폴백을 정본으로 착각하면 이탈률이 15.6% → 100% 로 부풀려진다.**

### 2. 원인 — 전송 주기가 판정 게이트보다 느리면 상태가 매번 지워진다
| | 전송 간격 중앙값 | 60초 이상 간격 |
|---|---|---|
| 장우진 (watchOS) | 5.0초 | 0.1% |
| 김태곤 (WearOS) | 120.6초 (평균 208초) | **100.0%** |

`DemoDashboard.tsx` 지오펜스 effect —
```js
if (pt.ageSec === null || pt.ageSec >= 60) continue;   // ← fresh.add 앞
fresh.add(pt.workerId);
...
for (const id of states.keys()) if (!fresh.has(id)) states.delete(id);
```
이탈 확정은 **연속 3회**(`GEOFENCE_EXIT_STREAK`)인데, 샘플이 120초마다 오므로 60초가 지나면
상태가 지워지고 streak 이 1로 되돌아간다. **실제 타임스탬프 재현 = 상태삭제 96회 / 샘플 97개.**
streak 이 3에 도달할 방법이 구조적으로 없다.

⚠ 이 `60` 은 애플 기준이다. 같은 파일이 지도 표시에는 출처별 임계(`staleThresholdMs` —
애플 60초·**갤럭시 150초**)를 쓰는데 지오펜스만 고정 60초다.

### 3. 처방 선택 (실데이터 시뮬레이션)
| | 김태곤 | 장우진 |
|---|---|---|
| 현재 (게이트 60·보존 60) | 0회 ❌ | 1회 |
| ⓐ 출처별 임계(갤럭시 150) | 3회 | 1회 |
| **ⓑ 게이트 60 유지 · 보존만 10분** | **3회 ✅** | **1회(무변화)** |

**ⓑ 채택.** 핵심은 *"지금 샘플이 낡았다"* 와 *"GPS 가 끊겼다"* 를 분리하는 것 —
낡은 좌표로 **판정**하지 않는다는 원래 의도는 지키고, **상태까지 지우지는 않는다**.
ⓐ 는 임계만 늘려 근본(보존 = 판정 게이트에 묶임)을 안 건드린다.

### 4. 더 큰 문제 — 판정이 브라우저에서만 돈다
`app/lib/geofence.ts` 를 쓰는 곳은 `DemoDashboard.tsx` **하나뿐**이다.
**관제웹을 아무도 안 열어 두면 이탈 알림은 누구에게도 안 간다.** 서버·크론 경로가 없다.
`cron/absence-check` 가 같은 이유로 이미 서버로 옮겨진 전례다("부재는 수신이 없어서 발생하므로
수신 경로에서는 영원히 발화하지 않는다").

## 결정
사용자 지시 = **ⓑ 먼저, 그다음 ①(서버 판정)**.

## 서버 판정(①) 설계 메모
- 중심 = 주소 지오코딩. **서버도 같은 값을 써야 한다** — 클라이언트만 주소를 쓰고 서버가
  `site_coord_daily` 를 쓰면 두 판정이 1km 어긋난다(위 ⚠ 가 바로 그 함정).
- 발화 = `recordAlert({type:"geofence"})` — DB dedup(`worker_id,type,ts`)과 텔레그램 통지가
  그 안에 함께 있다. 별도 통지 경로를 만들지 않는다.
- 상태는 크론이 무상태로 돌아야 하므로 **streak 을 최근 N개 표본으로 재구성**한다
  (클라이언트처럼 메모리 상태를 못 든다).
