# 워치 QR 로그인 UI — 결정과 근거 ([WATCH.DESIGN])

- **컴포저블은 순수(state in → callback out)** — 폴링·타이머는 MainActivity([WATCH.APP]). 두 세션이 MainActivity 를
  동시에 만지지 않기 위해서다. 새 콜백은 기본값 `{}` 로 두어 배선 전에도 컴파일된다.
- **QR 은 흰 카드 위 검은 칸** — OLED 검정 배경에 흰 모듈(반전 QR)은 폰 카메라 앱이 못 읽는 경우가 있다.
  quiet zone 은 카드 안쪽 4모듈(ISO 권장값).
- **행렬은 서버 `qrMatrix.rows`(문자열 '1'/'0') 그대로 든다** — 워치에 QR 라이브러리 0. 변환 계층도 0.
- **기본 모드 = QR** — 사용자 지시 "로그인 방법으로 변경". 직접 입력은 [직접 입력] 링크로 남긴다(관리자 폰 없음·카메라 고장 대비).
- **카운트다운은 상태값(`secondsLeft`)** — 컴포저블이 시계를 읽으면 스크린샷 검증이 비결정이 된다(TimeText 전례).
- **카드 140dp 가 한 화면 배치의 상한** — [WATCH.APP] 은 180dp(모듈 ≈9px)를 권했지만, 226dp 원에서 180dp 정사각형은 모서리가
  잘리고(반경 127 > 113) 코드 글자·버튼 자리가 없다. 140dp 는 모서리 반경 112.4 로 들어오고 버튼 줄 바닥 현 폭 88dp 에
  [직접 입력]+[취소] 가 딱 맞는다. 칸 ≈6.1px · QR 본체 ≈19mm(0.47mm/모듈). 실기 판독이 불안하면 여백 2모듈(+8%)·ECC L(+9%) 순.
- **긴 문구는 카드 자리에** — 상단 안내줄은 원의 현이라 폭 ~119dp 뿐이라 "서버에 연결하지 못했습니다." 가 잘렸다(프리뷰 실측).
  LOADING·ERROR 는 카드가 비어 있으니 그 140dp 안에 줄바꿈으로 넣고, 안내줄엔 "잠시만요"/"오류" 만 둔다.
- **OpenCV 판독은 원본 크기에서만 통과** — 0.5배 축소+블러는 실패했지만 cv2 QRCodeDetector 는 폰 스캐너(ZXing/MLKit)보다
  훨씬 약해 대리 지표가 못 된다. 최종 판정은 실기+폰 카메라.
- **직접 입력 화면엔 QR 로 돌아가는 링크를 안 뒀다** — 다섯 항목이 이미 226dp 를 꽉 채운다. 취소 → 로그인 재진입이 QR 이다.

## 08-31 · 갤럭시워치8 40mm 적용
- **실측** — SM-L325N(LTE 확정) · `wm size` 438×438 · `wm density` 340 = 논리 206dp(워치9와 같은 밀도 · 지름만 20dp 작음) · Android 16 · API 36.
- **신규 설치 첫 실행 즉사(잠복 버그)** — 런타임 권한 0개 상태에서 CollectorService 의 FGS(health) 승격이 SecurityException(anyOf=[ACTIVITY_RECOGNITION·HIGH_SAMPLING_RATE_SENSORS·health.READ_*] 미충족). 워치9는 PoC 때 부여한 권한이 남아 못 봤다. → onCreate 에 `canStartHealthFgs()` 가드 + 허용 콜백이 시작을 이어받음(FreshInstallGuardTest 2건).
- **QR 화면 기하 붕괴** — 226dp 기준 고정 카드 140dp 가 206dp 에서 넘쳐 안내줄이 원 상단 현 밖(밝은 픽셀 526개 실측), 카드 대각 quiet 4→1.7모듈. → 카드 = `min(140, 지름−78)` 유도식(206→128dp). 수정 후 실측: 원 밖 0픽셀 · 카드 272px=128dp · 모듈 ≈5.5px(스캔 여유 유지). 226dp 이상은 종전 140 그대로(스크린샷 골든 불변).
- **프리뷰 레일** — `WearWatch8Shots.kt`(spec 438px·340dpi) 8장. 이후 40mm 기하 회귀는 실기 없이 이 레일로.
- **실기 함정 3종** — ① 이 네트워크는 NAT64: 192.0.0.x 는 기기별 CLAT 가상 주소라 IPv4 도달 불가, `adb pair/connect` 는 **IPv6 링크로컬 `[fe80::…%en0]`** 로만 된다(mdns `adb-tls-pairing` 으로 포트 확인). ② 충전기 분리 시 `svc power stayon true` 무효 → 워치가 앰비언트 도즈로 빠져 `input` 스와이프를 삼킨다 — `settings put system screen_off_timeout 600000` 임시 설정(끝나면 60000 원복). ③ 무선 디버깅 접속 포트는 끊길 때마다 갈아치워질 수 있다 — 재접속 전 `adb mdns services`.

## 08-31 · 자동 로그아웃(미착용 90분) 신설
- 규칙(사용자): QR 방식 유지 + 로그인 후 미착용 1시간 30분 지속 시 자동 로그아웃.
- 설계 = **알람 신설 없이 기존 tick(120초 정확 알람)에 만료 검사를 얹는다** — suspend 관통이 이미 실측된 경로(R-32)라 오차 ≤ 2분. 미착용 앵커 `offBodySince` 는 prefs 영속이라 재부팅·프로세스 사망을 건너뛰어도 정산된다(onStartCommand 시작 정산). `OffBodySource.observed` 로 "재시작 직후 기본값 worn=true" 를 착용 증거로 오독하지 않는다.
- 정책 확정: **충전 중 = 미착용**(규칙 문언 그대로) — 야간 충전 90분이면 아침 QR 재로그인.
- 유의(구현 안 함·기존 동작): 로그아웃은 자격만 지운다 — 미전송 큐는 보존되고, 다른 작업자가 이어서 로그인하면 잔여 큐가 새 자격으로 올라간다. 수동 로그아웃도 종전부터 같다. 교대 운용에서 문제되면 별도 결정 필요.

## 09-01 · 로그아웃을 화면이 말하게 (사용자 지시)
- 문제(사용자 지적) — 자동 로그아웃이 동작해도 **워치 메인에서 알 방법이 없다.** 로그인 중엔 상태 줄에 이름이 뜨는데, 로그아웃되면 `state.workerName ?: "심박수"` 가 **"심박수" 로 되돌아가** 평소 화면과 완전히 같아진다. 작업자는 보호받는 줄 알고, 관제는 조용해진 이유를 모른다.
- **★ 진짜 원인은 라벨이 아니라 반영 경로였다.** ae33048 에서 `onResume` 에 로그아웃 반영을 넣었는데 **이 앱에서는 안 걸린다** — 시계 화면으로 안 돌아가려고 앰비언트로 머무는 구조(`ambientObserver`)라 액티비티가 계속 RESUMED 고 `onResume` 이 다시 오지 않는다. 그래서 **3초 폴링 루프에서 매 틱 prefs 를 다시 읽도록** 바꿨다(`cfg.token != null` → workerId·workerName 동기화). 라벨만 고쳤으면 증상이 그대로 남았다.
- 표기(사용자안 그대로) — 이름 자리에 **"로그아웃"**, 색은 severity 가 아니라 `VgColors.Caution`. **같은 자리에 같은 색으로 글자만 바꾸면 못 알아본다.**
- 푸터는 로그아웃을 **착용보다 먼저** 본다 — 그 상태의 "착용하면 시작됩니다" 는 거짓이다(차도 자격이 없어 전송 안 됨). → "로그인이 필요합니다".
- **폭 예산으로 전송 자리를 비웠다** — 상태 줄 가용 ≈148dp 인데 `로그아웃(40) + 5 + 막대15 + 6 + 배터리30 + 5 + "전송 1h"(50) = 151dp` 로 넘친다. 게다가 자격이 없어 못 보내는 중에 전송 이력을 띄우면 보내는 것처럼 읽힌다. → `uploadStatus` 최우선 분기로 빈 문자열.
- 테스트 6건(`LoggedOutLabelTest`) · :wear 281 → **287 통과**.
- 미수정(기존 동작·범위 밖) — `shortAge` 가 `1h`·`3m` 처럼 영문 단위를 화면에 내보낸다. "한국어 단독" 관례와 어긋나지만 이번 변경이 만든 것이 아니라 손대지 않았다.
