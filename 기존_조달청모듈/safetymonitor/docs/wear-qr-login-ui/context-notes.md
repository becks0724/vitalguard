# 워치 QR 로그인 UI — 결정과 근거 ([WATCH.DESIGN])

- **컴포저블은 순수(state in → callback out)** — 폴링·타이머는 MainActivity([WATCH.APP]). 두 세션이 MainActivity 를
  동시에 만지지 않기 위해서다. 새 콜백은 기본값 `{}` 로 두어 배선 전에도 컴파일된다.
- **QR 은 흰 카드 위 검은 칸** — OLED 검정 배경에 흰 모듈(반전 QR)은 폰 카메라 앱이 못 읽는 경우가 있다.
  quiet zone 은 카드 안쪽 4모듈(ISO 권장값).
- **행렬은 서버 `qrMatrix.rows`(문자열 '1'/'0') 그대로 든다** — 워치에 QR 라이브러리 0. 변환 계층도 0.
- **기본 모드 = QR** — 사용자 지시 "로그인 방법으로 변경". 직접 입력은 [직접 입력] 링크로 남긴다(관리자 폰 없음·카메라 고장 대비).
- **카운트다운은 상태값(`secondsLeft`)** — 컴포저블이 시계를 읽으면 스크린샷 검증이 비결정이 된다(TimeText 전례).
- **카드 140dp 가 한 화면 배치의 상한** — [WATCH.APP] 은 180dp(모듈 ≈9px)를 권했지만, 226dp 원에서 180dp 정사각형은 모서리가
  잘리고(반경 127 > 113) 코드 글자·버튼 자리가 없다. 140dp 는 모서리 반경 112.4 로 들어오고 버튼 줄 바닥 현 폭 88dp 에
  [직접 입력]+[취소] 가 딱 맞는다. 칸 ≈6.1px · QR 본체 ≈19mm(0.47mm/모듈). 실기 판독이 불안하면 여백 2모듈(+8%)·ECC L(+9%) 순.
- **긴 문구는 카드 자리에** — 상단 안내줄은 원의 현이라 폭 ~119dp 뿐이라 "서버에 연결하지 못했습니다." 가 잘렸다(프리뷰 실측).
  LOADING·ERROR 는 카드가 비어 있으니 그 140dp 안에 줄바꿈으로 넣고, 안내줄엔 "잠시만요"/"오류" 만 둔다.
- **OpenCV 판독은 원본 크기에서만 통과** — 0.5배 축소+블러는 실패했지만 cv2 QRCodeDetector 는 폰 스캐너(ZXing/MLKit)보다
  훨씬 약해 대리 지표가 못 된다. 최종 판정은 실기+폰 카메라.
- **직접 입력 화면엔 QR 로 돌아가는 링크를 안 뒀다** — 다섯 항목이 이미 226dp 를 꽉 채운다. 취소 → 로그인 재진입이 QR 이다.
