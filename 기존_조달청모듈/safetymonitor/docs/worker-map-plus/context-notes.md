# 작업자 지도 확장(worker-map-plus) 컨텍스트 노트

2026-07-22. 사용자 승인 범위 = 추천 1·2순위(①고스트 마커 ②알림→지도 ③트레일 ④위험구역 ⑤필지 폴리곤).

## 결정과 근거

1. **① 은 개선이 아니라 지도 false-OK 수정** — 표에는 STALE_MS(60초) "연결끊김" 강등이 있으나
   `workerStatus()`(지도 마커 톤)는 stale 미처리 → 연결 끊긴 작업자가 지도에서 마지막 상태색(초록 등)으로
   계속 표시되던 상태. 마커를 지우는 대신 **고스트(회색·점선·경과 병기)로 유지** — 사고·수색 시
   "마지막 확인 위치"가 핵심 정보라 제거하면 안 됨.
2. **② focus 는 12초 자동 해제** — 펄스 링이 영구 잔존하면 다음 관제에 혼란. 모달 "관제 지도에서 보기"
   클릭 시 dismiss(닫기)만 호출하고 ack 는 건드리지 않음(확인은 관리자의 명시 행위 유지).
3. **③ 트랙 조회는 서버 다운샘플이 아니라 [윈도 LIMIT 조회 + 클라 균등 다운샘플]** — ts 컬럼이 TEXT ISO 라
   SQL 시간버킷이 번거롭고, 30분×2초 케이던스 ≈ 900행이라 전송량이 작음. LIMIT 2000 상한 + 순수 유틸
   `downsampleTrack`(240점, 마지막 점 보존)으로 충분. 별칭(worker_alias) 폴딩 반영 — 같은 사람이 폰/워치
   2개 ID 로 보낸 트랙을 합쳐 시간순 정렬.
4. **③ 트레일 기간은 30분 고정** — 기간 선택 UI 는 요청 없는 설정성(Karpathy §2)이라 배제. 상수
   `TRACK_WINDOW_MIN` 하나로 조정 여지만 남김.
5. **④ 진입 판정은 `stepGeofence` 미러 신규 함수** — 거리 부호 뒤집기 재사용은 마진 방향이 꼬여
   가독성이 나쁨. 동일 상수(±10m·연속 3회)를 공유하는 `stepZoneEntry` 를 별도로 두고 단위테스트 미러.
6. **④ 존 편집은 권한있음(hasAdminMenuAccess) 서버 강제** — 작업자 등록/AED 편집과 동일 게이트.
   UI 는 canManage 로 숨김+서버 403 이중.
7. **④ 알림 우선순위 = SOS > 낙상 > 생체 > 위험구역 진입 > 구획 이탈** — 진입(크레인 반경·굴착부)이
   현장 밖 이탈보다 즉시 위험이 큼. 팝업 톤도 이탈(앰버)과 구분되는 오렌지.
8. **④ 캘린더 위험작업 연동(오늘 크레인 작업 → 존 자동 활성화)은 이번 범위 제외** — 후속 트랙.
9. **⑤ 판정은 원 유지, 폴리곤은 시각 레드라인만** — 검증 배포된 geofence(이탈 알림) 의미를 바꾸지 않는
   외과적 선택. 폴리곤 판정(point-in-polygon) 전환은 다필지·관리자 편집까지 묶어 후속.
10. **⑤ VWorld 데이터 API 는 서버에서 Referer 동봉** — 연속지적도 WMS 가 등록 도메인 Referer 를
    요구했던 실측(worker-gps-map)과 동일 가능성. 서버 fetch 라 헤더 자유. 실패 시 graceful(found:false).
11. **알림 이력 클라 기록 게이트 확장** — `/api/alerts` POST 허용 type 을 geofence → geofence·danger_zone
    2종으로. SOS/낙상/생체는 여전히 서버(addSample)만 기록(위조 삽입 차단 유지).
