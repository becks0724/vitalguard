# 수집 커버리지 히트맵 — 체크리스트

**목표.** 관제웹에서 작업자를 클릭하면 뜨는 추세 패널에 **1년치 수집 커버리지 히트맵** 탭을 더한다. 칸 하나 = 하루, 색 = **그날 몇 분 수집됐는가**.

**답하는 질문.** *"이 작업자가 언제 실제로 감시됐는가."* 지금 관측률이 워커마다 19~92% 로 들쭉날쭉한데(2026-08-17 실측) 그걸 한 화면에서 볼 방법이 없다.

**사용자 결정 2건.**
- 칸 값 = **수집 커버리지**(걸음·평균 심박·활동에너지 아님)
- 범위 = **1년**. ⚠ 현재 데이터로는 365칸 중 **39칸(11%)만** 채워진다고 보고했고, 그대로 진행하기로 결정됐다. 그래서 **빈칸이 거짓말하지 않게 만드는 것**이 이 트랙의 절반이다.

**범위 밖.** 다른 탭 변경 · 모바일 레이아웃 신설 · 칸 값 토글(걸음·경보는 나중) · 히트맵에서 상세로 드릴다운.

## 실연결 확인 (2026-08-17 · 추정 아님 · 각 구간 실제 호출 · 읽기 전용)

`EMP-6861` 로 SQL→real.ts→HTTP 핸들러(인증 포함)→화면 순수 로직까지 **22/22 통과**.

```
① 별칭 확장            EMP-6861 → EMP-6861, admin6861, EMP-admin6861
① dailyCoverageMinutes 39일 · 값 0~1440 위반 0
① firstDataDay         2026-06-26
② buildRealHistory     39점 · value>0 전건(0 을 채우지 않음) · date YYYY-MM-DD
③ 무인증 401 · 인증 200 · metric 반향 · range=365 · source=measured · days=99 거부 400
③ firstDataDate 동봉   2026-06-26
④ 칸 365 · 수집 39칸 = 서버 점 수 · 격자 유실 0(53주)
④ ★ 빈칸이 갈린다      미수신 14 · 운영 이전 312
```

**실측 요약** — 수집 39일 · 미수신 14일 · 운영 이전 312일 · 누적 265시간 · **운영 기간 수집률 74%**.

★ 세 상태 구분이 실데이터에서 실제로 발동했다. 합쳤다면 **326칸이 전부 "미수신"** 으로 읽혀 없는 사고를 312건 그렸을 것이다.

⚠ **React 렌더만 미확인**이다 — 이 레포에 렌더 테스트 인프라가 없다. 배치·상태·색 단계는 순수 함수로 분리해 단위 테스트했고(9건), 배선은 소스 불변식 가드(8건)로 고정했다. 남은 것은 사용자 육안이다.
