# 관제웹 안정화 — 문제 리스트 (2026-08-21 실측)

방법 = 정적 전수조사(타이머 30개·13파일) + 로컬 시뮬레이션 3종
(정상 175초 · 탭 숨김 위장 98초 · 죽은 DB 63초 — 헤드리스 브라우저에 fetch/console 계측기 주입).
프로덕션은 읽기 전용으로만 대조(로그·무인증 curl). **이 문서는 분석까지다 — 수리는 별도 결정.**

심각도 = P0 지금 피해 발생 중 · P1 조건 만족 시 실피해/비용 · P2 구조적 부채 · P3 정리.
"깨지면 보이는 모습" 이 없는 항목은 적지 않았다.

---

## P1-1 · 관제웹이 꺼 둔 cctv-ai 를 스스로 24/7 깨워 두고 있다 — 비용 + 무의미 트래픽

```
서버   lib/cctv-fall-poller.ts — 인스턴스마다 1.5초 폴 (instrumentation.ts 가 부팅마다 기동)
브라우저 /ai-cctv/cctv/connection·2·3 — 열린 탭마다 매분 3건 (전부 503 · 콘솔 무음)
실측   cctv-ai 요청 로그 = 1.5초 간격 200 연속 (08-21 · 폴러 케이던스 그대로)
       stats2 실물 = HTTP 200 + {"ok":false,"error":"ai backend unreachable"}
```

- **`!res.ok` 게이트가 뚫려 있다** — cctv-ai 컨테이너(프록시)는 살아서 HTTP 200 을 내고
  몸통의 `ok:false` 는 아무도 안 본다. 매 1.5초 JSON 파싱→이벤트 판정까지 돈다.
- **min-instances 0 이 무력화된다** — 우리 폴이 끊기지 않으니 cctv-ai 인스턴스가 영원히
  내려가지 않는다. 인스턴스 2개면 0.75초당 1회. **"CAM-03 OFF·과금 0"(07-20 실측) 이후
  이 구조가 과금을 되살렸는지 청구서 확인 필요.**
- 깨지면 보이는 모습 = 아무것도 안 깨진다. 그래서 한 달 넘게 아무도 몰랐다.
- 처방 후보 = 몸통 `ok:false` N연속 시 백오프(1.5s→60s) 또는 기동 env 게이트. 폴러 코드 한 곳.

## P1-2 · fall-poller 가 카메라 0 대인데 DB 까지 간 기록이 있다 — 경보 신뢰성

```
08-20 19:40:02  [cctv-fall-poller] 폴 실패 1회 연속 … Connection terminated (pg 오류)
```
tick 안에서 pg 에 닿는 경로는 `ingestCctvEvent`(event 가 참일 때)뿐이다. 카메라가 없는데
event 가 만들어졌다는 뜻이고, `cctvStatsToEvent` 가 `{ok:false}` 형태를 어떻게 다루는지
확인이 필요하다. **⚠ 이 항목은 미해명이다 — 오탐 경보(낙상 fusion)로 이어질 수 있는 경로라
P1 에 둔다.** 판정 전에 원인 단정 금지(L-85).

## P1-3 · gaspod 텔레메트리 GET 이 무인증 공개 — 프로덕션 실측 확정

```
GET /api/gaspod/telemetry?n=1  →  200 (무인증)
   latest = device_id·o2·temp·humidity·mq7_raw·mq136_raw·vbat·state·ts … · count 32,228
   n 최대 720행/회
[통제군] GET /api/aed/devices 무인증 → 401  (게이트 부재가 라우트 성질임을 확정)
```
생체가 아니라 P0 는 아니지만, **현장 가스 농도·기기 상태가 URL 만 알면 조회된다.**
`GASPOD_REQUIRE_TOKEN` 은 POST(수집) 전용이고 GET 은 인증 코드 자체가 없다.
08-13 `mock/history` 봉인(사번→생체 노출)과 같은 계열 — 그때 GET 전수 점검이 이 라우트를
안 덮었다. 처방 = `verifyBasicAuth` 게이트(그때와 동일 처방) + **다른 GET 전수 재점검**.

## P2-1 · 매분 같은 초 버스트 — 모든 60초 폴이 마운트 시각에 정렬된다

```
로컬 실측  t+37s = 9건 · t+97s = 14건 · t+157s = 9건  (정확히 60초 간격 · 같은 초)
프로덕션   D-3 실측과 동일 지문 (00304 = 매분 1건 실패 · 실패 초 동시 8건)
```
- 원인 = 폴 13곳이 전부 `useEffect(mount) → setInterval(60s)` 라 페이지 로드 초에 정렬.
- idleTimeout 90s(`61112df`)가 **콜드 커넥트 비용은 제거**했지만 동시성 스파이크 자체는 남는다.
- 처방 후보 = 마운트 시 랜덤 지연(0~59s) 한 겹. ⚠ **ⓐ 효과를 먼저 관찰하고 결정** —
  둘을 같이 넣으면 어느 쪽이 고쳤는지 못 가른다(L-94 계열).

## P2-2 · 탭 숨김 게이트가 13파일 중 3파일뿐 — 숨김 중에도 분당 ~50건

```
숨김 위장 98초 실측 (document.hidden=true 강제)
  계속   monitor/vital 2초(49건) · gaspod 8초(12건) · aed 3종·gaspod/config·
         connection 3종 60초(각 2건)
  멈춤   calendar 계열 (DemoDashboard 게이트 3곳 — ac14830 이 고친 것들만)
```
- 관제 대시보드는 24/7 열어 두는 화면이라 **숨김 = 드문 상태가 아니라 기본 상태**일 수 있다
  (다른 창 뒤에 두는 운용). 이 트래픽이 P2-1 버스트·DB 상시 부하의 배경이다.
- ⚠ 한계 = 위장 시험은 **앱 자체 게이트만** 검증한다. 실브라우저는 백그라운드 탭 타이머를
  스로틀하므로(크롬 5분 후 1/분) 실효 부하는 이보다 낮을 수 있다 — 다만 그건 브라우저의
  선의이지 우리 설계가 아니다.
- 처방 후보 = 숨김 시 정지가 과하면(복귀 시 공백) **주기 완화**(2s→10s 등). 사용자 결정 필요.

## P2-3 · `persisted:false` 를 아무도 안 읽는다 — DB 장애가 가스 카드에서 무음

```
죽은 DB 실측  GET gaspod/telemetry → 200 {ok:true, persisted:false, rows:메모리}
화면          grep persisted in components = 0건  ·  [통제군] 같은 응답의 count 는 읽힘
```
서버는 열화를 정직하게 표시하는데 화면이 그 필드를 안 읽는다 — **L-91/L-101 과 같은 형태**
(만들어 둔 신호의 읽는 경로 부재). vital 쪽은 08-15 열화 배너가 있는데 가스 쪽만 없다.

## P2-4 · calendar/media — 요청당 DB 왕복 13회짜리 라우트가 60초 상시 폴

폴 대상 API 중 압도적 1위(다음이 aed/devices 4회). 캘린더 탭이 닫혀 있어도
오늘-위험작업 칩 폴(`runTodayHazardPoll`)이 매분 부른다(실측: 관제 탭에서 60초당 1건).
D-3 실패 라우트 분포에서도 calendar/media 가 1위(8/37)였다 — 무거워서 줄 끝에 자주 선다.

## P3-1 · /ai-cctv/connection* 503 이 콘솔에도 안 남는다

실측 175초 = 503 ×9 · 콘솔 0건. CCTV 타일 UI 에 연결 상태 표시가 있는지는 미확인 —
표시가 있으면 문제 아님(그 확인까지가 이 항목의 처방).

## P3-2 · 로컬 .env.local 관리자 자격 ≠ 프로덕션

오늘 라이브 검증에서 확인(로그인 API 401). 08-15 APP_JWT_SECRET 불일치와 같은 형태.
비상시 로컬에서 프로덕션 관제에 못 들어간다 — 의도한 분리인지 사용자 확인 필요.
