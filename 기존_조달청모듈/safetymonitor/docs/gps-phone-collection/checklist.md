# 폰 GPS 수집 트랙 — 체크리스트

**목표.** 신규 앱(`vitalguard_app`)의 **iOS 폰**이 위치를 수집해 관제로 올린다. 방식은 **region monitoring(경계 감시) + 근무 중 coarse 추적**. 관제구역 반경은 **최소 50m · 최대 100m**.

**배경.** 08-01 이후 GPS 수신 0건이다. 신규 앱에 위치 코드가 한 줄도 없고 권한 문구·백그라운드 모드도 없다. 서버 스키마·DB 컬럼·지오펜스·동선·CSV 내보내기는 전부 살아 있으므로 **생산자만 복구**하면 된다. 근거는 `context-notes.md` G-01~G-09.

**범위 밖.** 워치 GPS(배터리 대가가 크고 watchOS 는 region monitoring 이 없다) · 폰·워치 좌표 융합(공통모드 오차라 평균해도 안 준다) · 근무 시간대(time-of-day) 개념 신설 · 관제 화면 신규 UI.

08-19 결론은 **"결함이 아니라 설계가 의도대로 동작한 것"** 이었다. 그 판정 자체는 지금도 맞다.


### B-2 지하 실측 완료 (08-20 18:33 · 08-21 진단) — ★ 결함 확인

사용자가 지하 2층에서 촬영했고 각인 주소가 실제와 크게 어긋났다. 폴백 경로는 **동작했다** —
좌표가 비지 않았다(08-20 에 고친 그 결함은 재발 안 함). 문제는 **어느 좌표를 골랐는가**다.

```
실제 촬영지 필문대로 70        35.160701, 126.925092   (VWorld 지오코딩)
각인된 좌표                    35.158428, 126.927534   실제에서 336m
그 시각 추적 좌표              35.161337, 126.926531   실제에서 149m · 정확도 10m
                               18:32:19~18:36:29 51행 고정 = 촬영(18:33:35)을 감싼다
```

**★ 폰은 149m 짜리를 들고 있었는데 각인은 336m 짜리를 썼다.**

각인 좌표는 **그날 추적 경로에 0건** 등장한다(통제군 = 추적 좌표 51행). 즉 `oneShot` 이 낸
값인데 `latestFix` 에 못 들어갔다 — **정확도 게이트 `<= siteRadiusMaxM`(100m)를 통과 못 했다**는
뜻이다. 그런데 각인은 그것을 받았다.

**원인 = `requestFreshFix` 에 정확도 게이트가 없다.** 세 경로 전부.
```swift
if let cached = self.cachedFix(within: freshEnoughSec) { completion(...); return }  // 나이만 본다
if loc.horizontalAccuracy <= Self.siteRadiusMaxM { self.latestFix = loc }           // 캐시 여부만 가른다
completion(self.payload(from: loc))                                                 // 정확도와 무관하게 준다
```
업로드 경로(`currentFix`·`refreshFixWhileStationary`)는 거르는데 **각인 경로만 안 거른다.**

부수 원인 둘.
```
① cachedFix 가 "더 정확한" 이 아니라 "더 최근" 을 고른다 —
   게이트 통과분(latestFix)이 신선해도 게이트 미통과 oneShot.lastKnown 이 더 최근이면 진다
② 각인이 정확도를 안 적는다 — 소수 6자리(≈0.1m)로 찍으면서 실제 불확실성을 안 밝힌다.
   나이는 60초 넘으면 `(N분 전 좌표)` 를 붙이는데 정확도는 아예 자리가 없다
```

⚠ 주소 변환은 정상이다 — `광주광역시 산수동 554-38` 은 그 (틀린) 좌표의 올바른 역지오코딩이다.
고칠 곳은 좌표 선택이지 주소가 아니다.
