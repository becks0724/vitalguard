# 워치 배터리 소모 실측 — 컨텍스트 노트

## 08-31 · 트랙 개시
- 요청. ① 앱 실행 시 배터리 소모량 ② 파트별 분해 ③ 디스플레이 미사용 시 예상 사용량 예측(추후 웨어러블 개발용).
- 대상 기기 = **갤럭시워치9 44mm(SM-L355N · 445mAh · 226dp · API 37)**. 사용자가 핫스팟에 연결한 기기가 워치9였고, 이쪽만 로그인·수집 중이라 "앱 실행 중" 측정이 가능하다. 워치8 40mm(325mAh)은 로그아웃 상태(QR 라이브 대기)라 환산으로만 다룬다.
- 방법 = 2축.
  - **차분(순간전류)** — `/sys/class/power_supply/battery/current_now` 를 상태별로 샘플링해 평균. 상태 3종 = ⓐ 화면ON+앱TOP ⓑ 화면OFF+수집 지속 ⓒ 앱 강제중지+화면OFF. ⓐ−ⓑ=디스플레이, ⓑ−ⓒ=앱(센서+CPU+전송), ⓒ=시스템 베이스.
  - **적분(장구간)** — `batterystats --reset` 후 ≥30분 창. `charge_counter` 차이=실 mAh, `Estimated power use`=모델 기반 파트 귀속. 두 축이 교차 검증한다.
- 알려진 오염원. 무선 adb 디버깅(WiFi 상시)이 전 상태에 공통 포함 — **차분에서는 상쇄**되고 절대값은 +α 과대(보고서에 명기). LTE 등록 상태·AOD 여부를 측정 전 스냅샷으로 고정.

## 08-31 · 1차 실측 결과(부분 유효)
- **유효 데이터.** B(도즈+수집) n=60 평균 **−70mA**(적분 대조 77.1mAh/h — 단위=mA 확정) · A(화면ON+앱TOP) n=42 평균 **−62.6mA** · C 초반 30초(충전 개입 전) **≈−8mA**(−13/−8/−7/−9).
- **1차 분해.** 앱 수집 비용 ≈ B−C ≈ **60mA**(센서 연속 + 잦은 vital POST 로 WiFi 활성 유지가 지배 추정) · 화면ON−도즈AOD 차이 ≈ ±8mA(노이즈에 묻힘 — AOD 도 픽셀을 켜므로 물리적으로 타당) · adb 5초 샘플링 자체는 저렴(C 가 −8mA 로 증명).
- **사고.** C 시작 ~2.3분 뒤 워치가 충전기에 올라감(+600mA 유입·45→52%) → C 후반·45분 창 무효. adb 도 끊겨(NA 24건) 앱 재기동 실패 — **11:42 이후 수집 공백**. 이후 워치가 망에서 이탈(mdns 0·ping 무응답).
- **재측정 설계(교훈 반영).** 창 측정은 **adb 무접속**으로 — 경계에서만 접속해 스냅샷/리셋/덤프. W1=수집+도즈 30분 · W2=앱중지 30분 · W3=AOD off+수집 30분(항목③ 직측). 충전기 금지.

## 08-31 · 2차 실측(무접속 창) — 확정 수치
대상 = 워치9 44mm(445mAh) · 착용·방전 중 · adb 는 창 경계에서만 접속(1차 오염 제거).

| 구간 | 조건 | 소모 |
|---|---|---|
| W1 14:51~15:21 | 앱 수집 + AOD | **64.85 mAh/h** (92→85%) |
| 앱 사망 15:22~15:29 | 앱 없음 + 시계 AOD | **46.3 mAh/h** |
| W3 15:53~16:22 | 앱 수집 + **AOD off** | **60.2 mAh/h** (79→72%) |

**파트 분해.** 시스템 바닥(OS+무선+시계면) **46.3** · 앱(센서+ML+업로드) **≈18.5** · AOD **≈4.6**.
→ 앱은 전체의 **28%**, 디스플레이(AOD)는 **7%** 뿐이다. **지배 요인은 시스템 바닥(71%)** 이다.

**수명 환산.** 워치9 445mAh — 앱+AOD **6.9h** · AOD 끄면 **7.4h** · 앱 없음 9.6h.
워치8 325mAh 환산 — 앱+AOD **약 5.0h**(정격비 0.73배).

**항목③ 답(디스플레이 미사용 예측).** AOD 를 꺼도 **7% 절감(6.9→7.4h)** 에 그친다. 화면 없는 웨어러블을 만들어도
같은 수집 주기·무선 설정이면 **7.5h 부근이 상한**이다. 실효 개선은 화면이 아니라 **시스템 바닥(무선·LTE 상주)**
에서 나온다 — 절감하려면 전송 주기·라디오 정책을 건드려야 한다(주기 변경은 R-32 결론과 충돌하므로 별도 판단).

**⚠ 방법론 교훈 2건.**
① `am force-stop` 은 지속되지 않는다 — W2(앱중지 30분) 중 약 7.6분 만에 앱이 되살아나(15:29) 창이 오염됐다.
   구제 = **DB `battery_charge_uah`(표본마다 실림)로 사후 재구성**. 창 경계 스냅샷보다 해상도가 높다(2분 간격).
   ★ 다음부터는 창 설계 없이 **DB 전하 곡선 + 상태 라벨**만으로 파트 분해가 가능하다.
② 순간 전류(`current now`)는 스팟값이라 평균과 크게 다르다(앱 사망 구간 스팟 −8mA vs 실제 평균 46mAh/h).
   **판정은 전하 적분(`charge counter`)으로만 한다.**

## 08-31 저녁 · 워치8 실측과 **워치9 수치 정정**

### 워치8 40mm (EMP-admin3470 · 무접속 창)
| 항목 | 값 |
|---|---|
| 창 | 16:43:12 → 17:17:24 (34.2분 · 표본 18) |
| 배터리 | 66% → 57% (9%p) |
| 전하 | 188,860 → 164,152 µAh (24.7 mAh) |
| **소모율** | **43.4 mAh/h** |
| 만충 실측 | ≈286 mAh (설계 325 mAh) |
| **수명** | **≈6.3시간** (%기준 = 용량 무관, 가장 견고) |

### ★ 워치9 정정 — 64.9 mAh/h · 6.9시간은 **과대평가였다**
짧은 창이라 adb 접속·화면 조작이 섞였다. 하루치 곡선에서 **충전 구간을 뺀 단조 구간 셋**이 일관된다.

| 구간 | 소모율 |
|---|---|
| 09:02–10:15 | 57.4 mAh/h |
| 10:23–11:39 | 58.2 mAh/h |
| 14:34–16:41 | 59.0 mAh/h |

→ **워치9 = 약 58 mAh/h · 만충 실측 466 mAh · 수명 ≈8.0시간.**

### ★ 새 교훈 — adb 를 붙인 채 재면 안 된다
같은 워치8, 같은 앱, 인접한 두 창.
```
16:01–16:41  adb 접속 중   65.0 mAh/h
16:43–17:17  무접속        43.4 mAh/h     → 접속 프리미엄 ≈ +20 mAh/h (50%)
```
무선 디버깅 접속 자체가 소모의 3분의 1을 만든다. **배터리 판정은 무접속 창에서만.** DB 전하 곡선으로 재구성하므로 adb 는 애초에 필요 없다.

### 두 기기 비교 · 현장 함의
| | 워치9 44mm | 워치8 40mm |
|---|---|---|
| 만충 실측 | 466 mAh | 286 mAh |
| 소모율 | 58 mAh/h | 43.4 mAh/h |
| 수명 | ≈8.0시간 | ≈6.3시간 |

워치8이 **25% 덜 먹는데 수명은 21% 짧다** — 화면이 작아 아낀 만큼을 39% 작은 배터리가 상쇄하지 못한다.
**8시간 교대 기준 워치9은 아슬아슬, 워치8은 중간 충전이 전제되어야 한다.**

## 09-09 · 하루치 연속 실측으로 두 수명 재확인 — **워치8은 문서가 24% 짧게 잡고 있었다**

09-08 하루가 DB 에 통째로 남아 재계산했다. **위 표를 지우지 않는다** — 두 값은 조건이 다르고, 충돌이 아니다.

| | 워치9 44mm | 워치8 40mm |
|---|---|---|
| 종전(위 표) | 8.0시간 `58 mAh/h · 466 mAh` | **6.3시간** `34.2분 창 · 66→57% 외삽` |
| **연속 실측** | **8.1시간** `09-09 06:53 100% → 10:17 58% · 3.41h · 12.32 %p/h` | **7.8시간** `09-08 11:16 95% → 18:25 3% · **7시간09분 · 211표본** · 12.86 %p/h` |

- **워치9은 문서가 옳았다**(8.0 vs 8.1 · 8일 간격 독립 재현). **워치8만 짧게 잡혀 있었다.**
- 워치8의 7시간 09분은 **외삽이 아니라 그날 실제로 돈 시간**이다. 34분 창을 100%p 로 늘린 6.3시간이 24% 짧다.
- ⚠ **운용 결론은 안 바뀐다** — 7.8시간도 8시간 교대를 못 채운다. *"워치8은 중간 충전 전제"* 는 그대로 유효하다.
  다만 **"6.3시간이라 두 번" 과 "7.8시간이라 한 번" 은 현장 지시가 다르므로** 인용할 때 조건을 함께 적는다.

### ★ 소모율을 조건 없이 인용하지 않는다 — 한 기기 안의 산포가 3.3배다
45분 이상 단조 방전 구간 전수(기기 라벨은 계정이 아니라 **배터리 지문**으로 붙였다 — `watch_device_model` 이 전 행 NULL 이라).

| | 구간 | 총 시간 | 범위 | 중앙 |
|---|---|---|---|---|
| 워치9 44mm | 11개 | 71.9h | 14.4 ~ 78.7 mAh/h | 55.6 |
| 워치8 40mm | 11개 | 23.1h | 15.8 ~ 52.7 mAh/h | 30.5 |

- ⟹ 두 측정값이 갈릴 때 *"어느 값이 맞나"* 는 잘못된 질문이다. **"어떤 상태의 값인가"** 가 맞는 질문이다.
- ⚠ **SOC 대역이 값을 체계적으로 밀어 올린다.** 워치8 `31→15%` 52.7 vs `99→59%` 30.5 ·
  워치9 `36→18%` 78.7 vs `100→54%` 55.6. **대역을 안 맞추면 기기 비교 자체가 무의미하다.**
- ⟹ 인용 형식 = `43.4 mAh/h (34분 창 · adb 해제 직후 · 66→57%)` / `33.4 mAh/h (6.8시간 · 무접속 · 95→15%)`.
- ⚠ 위 표의 43.4 는 **adb 를 끊은 지 2분 뒤** 창이다. 같은 문서가 *"접속 프리미엄"* 을 적고 있으니
  **잔여 라디오 비용 가설이 데이터와 어긋나지 않는다**(단정은 아니다 — 2시간 이상 무접속 구간의 최대가 33.4 다).

### 기기별 비교는 계정이 아니라 **배터리 지문**으로 라벨을 붙인다
`chargeUah / batteryPct * 100` = 만충환산 µAh. 09-09 에 이것으로 **08-29~08-31 사이 기기 교체**를 찾아냈다 —
`admin3470` 의 지문이 466,836 → 288,583 으로 바뀐다(워치9 → 워치8). 계정으로 라벨을 붙이면 **같은 계정의 다른 기기**가 섞인다.
