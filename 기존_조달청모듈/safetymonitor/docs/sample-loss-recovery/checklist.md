
(`worker_id` + `heart_rate_measured_at` 대조).

## ★★ 오늘의 사고 — 공유 워킹트리에서 stash 금지

배포 직전 테스트 1건이 깨져 원인을 찾다가 **`git stash` 를 돌렸고, 그것이 다른 세션의
미커밋 작업(수상안전 D-35)을 통째로 치웠다.** `apply` 로 복원했고 stash 는 당사자 확인 전까지
보존 중이다(`pop` 이었으면 되돌릴 수 없었다).

**공유 워킹트리에서 `stash`·`HEAD` 는 나 혼자 쓰는 물건이 아니다.** 진단이 필요하면 워킹트리를
비우지 말고 **별도 워크트리**(`git worktree add --detach`)를 쓴다. 실제로 그렇게 해서
"실패 1건이 남의 미커밋 탓"임을 증명했다(깨끗한 HEAD 에서 89/89 통과).

그 뒤 `ALLOW_DIRTY=1` 로 배포했다 — 이 옵션은 **워킹트리 대신 아카이브에서 검증**하므로
"검증한 것 ≠ 배포한 것"이 되지 않는다(810 pass / 0 fail).

**관련 교훈 — 공유 HEAD 에서 보류는 보류가 아니다.** 커밋해 두고 push 만 참으면 안전할 것
같지만, `git archive HEAD` 라 **다음에 누가 무엇을 배포하든 함께 실린다.** 오늘 08-17 로
보류했던 `9464777` 이 정확히 그렇게 나갔다. 보류하려면 브랜치로 빼거나 커밋하지 않는다.
