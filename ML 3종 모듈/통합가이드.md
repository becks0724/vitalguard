## 2. 배선 — 코드 4조각

**① 캡처 로거** (충격 전2s+후10s = 12초 윈도, 게이트 1.5G):
```swift
let logger = IMUWindowLogger(preSec: 2.0, postSec: 10.0, logThresholdG: 1.5, refractorySec: 2.0)
let ml = FallMLModule()          // nil이면 모델 미탑재 — ML 기능 비활성 처리
let guard_ = CountdownGuard()    // 기본 30초·지속움직임 5초 자동취소
```

**② deviceMotion 콜백에 2줄** (기존 모션 스트림 안):
```swift
logger.ingest(ax: ax, ay: ay, az: az, gx: r.x, gy: r.y, gz: r.z, totalG: totalG, at: now)
guard_.feed(totalG: totalG, now: now)
```

**③ 윈도 판정** (충격 +10초에 자동 호출됨):
```swift
logger.onWindow = { window in
    guard let ml else { return }
    let v = ml.assess(window)                 // 판정 + 추적정보
    // v6.2.0 경보 게이트 — danger 라도 피크가 2.8G(FallMLModule.alertGateG) 미만이면
    // 카운트다운을 열지 않는다. 판정·trace 기록은 그대로(게이트가 놓친 낙상의 사후 실측용).
    if v.decision == .danger && v.alertGatePassed {
        guard_.start()                        // 카운트다운 개시 (UI: 진동+버튼 표시)
    }
    log(v.trace)                              // ★ 추적성 — 반드시 로그/서버에 남길 것
}
```

**④ 카운트다운 결말 3종**:
```swift
guard_.onAutoCancel   = { /* 지속 움직임 → 조용히 취소 (회복) */ }
guard_.onManualCancel = { /* "낙상 아님" 버튼 → 취소 */ }
guard_.onConfirm      = { /* 무반응 → 낙상 확정: 서버 신고 + trace 동봉 */ }
// UI의 "낙상 아님" 버튼 → guard_.cancelByUser()
```

**⑤ 섀도 보고 (v6.1.1 — 판정을 서버에 남긴다, 경보 없음)**:
`FallShadowReporter`(모듈 소속)가 후보(candidate)·결말(prompt_result) 항목을 릴레이 축약 키로 만든다.
기존 WatchStreamer 의 인라인 섀도 로직(후보 생성·reportFallOutcome)을 이 클래스로 교체할 것:
```swift
let shadow = FallShadowReporter(emit: { self.pendingFallItems.append($0) })
shadow.onDanger  = { /* 오버레이 표시 — 진동 정책·테스트 모드는 지금처럼 앱에서 */ }
shadow.onResolve = { outcome in /* 오버레이 닫기 */ }
// 판정 시: shadow.onVerdict(v) · 모션 콜백: shadow.feed(totalG:) · 버튼: shadow.cancelByUser()
```
⚠ fallDetected·fallDecision 은 리포터가 절대 만들지 않는다(섀도 계약) — 3단계(실경보)에서
그 두 키를 실을 때도 리포터 밖(앱)이 아니라 **ML 담당에게 요청해 모듈에서** 연다.

**⑥ 추적정보(trace) 계약 (v6.2.0 고정 — 결정 4)**:
`Verdict.trace` 의 키는 **additive-only** 다 — 기존 키의 이름·타입·의미는 바꾸지 않고 추가만
한다. 모양 판별자는 `module_version`. 서버는 이 계약을 근거로 전용 컬럼·도착 가드를 만들 수 있다.

| 키 | 타입 | 의미 |
|---|---|---|
| `module_version` | string | 모듈 버전(모양 판별자) |
| `decision` | string | `veto_work` \| `danger` \| `no_danger` |
| `p_work` / `p_nonrecovery` / `p_impact` | number | 3모델 확률 |
| `samples` | int | 윈도 샘플 수 |
| `effective_hz` | number | 실효 표본율(샘플수÷스팬) |
| `peak_g` | number | 윈도 피크 \|accel\| (G) |
| `alert_gate_g` | number | 경보 게이트 상수 (v6.2.0+, 현재 2.8) |
| `alert_gate_passed` | bool | 피크가 게이트 이상인가 (v6.2.0+) |
| `judged_at` | string | 판정 시각 (ISO-8601 UTC) |

저장 실태: 서버 전용 컬럼 없음 — `vital_samples.raw_json` 안에 남는다(2026-08-28 확인).

## 3. 확인 (필수)
- 디버그 화면에 `MLSelfCheck.run()` 결과 표시 → **6줄 전부 ✅** = 탑재 성공

## 4. 모듈 업데이트 받는 법
새 버전 태그를 pull → 폴더 교체 → 자가검증 ✅ → 배포. 통합 코드 변경 없음.
`FallMLModule.version`이 로그에 찍히므로 어떤 빌드가 어떤 모듈인지 항상 추적된다.
