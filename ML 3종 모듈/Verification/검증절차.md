# 모델·임계 교체 검증 게이트 (절대 규칙)

> 배경: 2026-07-29 "v5" 교체 사고 — 검증 없는 impact 모델 교체 + 억제 로직 추가로
> 배포 워치의 낙상 알림이 사실상 침묵(규칙 포착 낙상의 93% 억제)했던 실제 회귀.
> 이 게이트는 그 재발 방지 장치다. **어떤 예외도 없다.**

## 교체 커밋에 반드시 동봉할 것 3가지

1. **라벨 데이터 채점 리포트** — 새 모델을 `imu_collect.imu_window` 라벨 윈도 전량에 채점:
   - impact: 낙상/작업/일상 중앙값 + 운영임계 통과율 (낙상↑ · 작업/일상↓ 방향 확인)
   - work_veto: 낙상 오기각률(0이어야 정상) + 작업 기각률
   - recovery: 회복/비회복 분리 확인
   - 판정 기준: **구버전보다 못하면 교체 금지** (게이트 원칙 — 이긴 것만 승격)
2. **메타데이터 갱신 확인** — mlmodel 안의 학습수치(n, OOF, 임계)가 새 학습과 일치할 것
   (v5는 메타데이터가 구버전 그대로였다 — 재현 절차가 깨졌다는 신호)
3. **온디바이스 자가검증 ✅** — 새 모델 기준 정답지(ml_selfcheck.json) 재생성 후 6/6 통과 스크린샷

## 버전·추적 규칙

- `FallMLModule.version` 올리기 (모델만 바뀌어도) + git 태그 `vX.Y.Z`
- `CHANGELOG.md`에 학습 데이터 범위(기간·인원·윈도수) 명시
- `작업기록.md`에 작업 로그
- 임계값은 재산출 절차(LOSO OOF) 없이 손대지 않는다 — 산출 근거는 Models/thresholds.json

## 설계 불변식 (코드 리뷰 체크리스트)

- [ ] impact 확률이 알림을 **억제**하는 경로가 없다 (증거 전용 · fail-open)
- [ ] 기각권은 work_veto(precision≥0.95 운영점)와 recovery뿐이다
- [ ] ML 미가용 시 안전측 동작이 정의돼 있다 (모델 없음→기능 비활성, recovery 없음→위험 간주)
- [ ] Verdict.trace가 로그·신고에 실린다
